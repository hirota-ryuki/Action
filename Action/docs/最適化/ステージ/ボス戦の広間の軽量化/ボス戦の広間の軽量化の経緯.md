## 2026-11-15 部品の三角形を減らし、BossHall の頂点を 99万から 57万にした

### 1. 現状の問題

Debug ビルドの起動を測ると、ボス戦の広間のモデル `BossHall.tkm` の読み込みにいちばん時間がかかっていた（[起動時のモデルロード高速化の経緯](../../起動/起動時のモデルロード高速化/起動時のモデルロード高速化の経緯.md)）。頂点は **997,185個** で、プレイヤー（28,493個）の35倍ある。tkm のファイルは 63MB だった。

**用語:**

| 用語 | 何のことか |
|---|---|
| tkm | k2Engine のモデルのファイル（`.tkm`）。頂点・面・マテリアルが入っている |

部品ごとの三角形の数（Blender で数えた）は次のとおり。部品の数（柱は10本など）を全部足した数。

| 部品 | 三角形 | 置いている数 |
|---|---|---|
| 窓 | 104,852 | 11 |
| 柱 | 101,190 | 10 |
| 燭台 | 100,008 | 12 |
| アーチ | 80,248 | 8 |
| 垂れ幕 | 58,620 | 12 |
| 壁の灯り | 47,760 | 6 |
| 像 | 43,438 | 2 |
| がれき | 33,978 | 6 |
| 玉座 | 28,924 | 1 |
| 扉 | 17,264 | 1 |
| 床・壁・絨毯など | 166 | |

窓・柱・燭台・アーチの4つで、全体の約6割になる。どれもカメラから遠く、細かいでこぼこは画面ではほとんど見えない。

### 2. ソースコードの問題箇所

部品の三角形を減らす割合は、[make_boss_stage.py](../../../../tools/BossStage/make_boss_stage.py) の `PARTS` の4つ目の数で決めている（1.0 なら減らさない）。Blender の Decimate モディファイアで減らす。

**用語:**

| 用語 | 何のことか |
|---|---|
| Blender | 3Dモデルを作るソフト。このプロジェクトでは、ウィンドウを出さずに Python のスクリプトで動かして、広間を作る |
| モディファイア・Decimate | モディファイアは、モデルを壊さずに形を変える Blender の機能。Decimate は、形をなるべく保ったまま、三角形を `ratio`（割合）まで減らす |

```python
PARTS = {
    "Throne":      (5.0, "height", 1024, 1.0),
    "Door":        (8.0, "height", 1024, 0.6),
    "Pillar":      (13.0, "height", 1024, 0.35),
    "Window":      (11.0, "height", 1024, 0.35),
    "Arch":        (10.0, "width",  1024, 1.0),
    "Candelabrum": (3.0, "height",  512, 0.27),
    "Statue":      (3.8, "height", 1024, 0.7),
    "Banner":      (6.5, "height", 1024, 1.0),
    "Rubble":      (2.5, "width",   512, 1.0),
    "Sconce":      (1.8, "height",  512, 1.0),
}
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `5.0`（`PARTS` の組の1つ目） | 部品の大きさをそろえるため | 部品を、この長さ（メートル）にそろえて置く。`"Throne": (5.0, ...)` なら、玉座は 5m | このプロジェクトの Blender のスクリプト [make_boss_stage.py](../../../../tools/BossStage/make_boss_stage.py) |
| 値 | `"height"`（`PARTS` の組の2つ目） | 大きさを、高さと幅のどちらに合わせるか決めるため | `"height"` なら高さを、`"width"` なら幅を、1つ目の数にそろえる | このプロジェクトの Blender のスクリプト [make_boss_stage.py](../../../../tools/BossStage/make_boss_stage.py) |
| 値 | `1024`（`PARTS` の組の3つ目） | 部品のテクスチャの大きさを決めるため | テクスチャの1辺（ピクセル）。`512` なら小物用の小さい画像になる | このプロジェクトの Blender のスクリプト [make_boss_stage.py](../../../../tools/BossStage/make_boss_stage.py) |

### 3. 直し方

広間全体で、三角形をおよそ半分にする。遠くからしか見ない柱・窓・燭台は大きく減らし、玉座・アーチ・像のように形を見せたいものは半分くらいにする。

はじめは、がれきも 0.4 に減らした。しかし、拡大して比べると、石のでこぼこがはっきり減っていた（下の「試したこと」）。がれきは全体の5%ほどしかなく、減らしても速さはほとんど変わらないので、減らさない（1.0 のまま）ことにした。

### 5. どう確かめたか

- 割合を変えて `make_boss_stage.py` を Blender で動かし、広間を作り直した。部品のテクスチャ（PNG）は前と全く同じものが出たので、変わったのは FBX と tkm だけ。
- 起動すると、FBX の方が新しいので tkm が作り直される。その tkm をコミットした。
- 画面は、ゲームを最小化・非アクティブで起動し、窓を透明（不透明度 1/255）・クリックを素通り・いちばん奥にしてから、アクティブにしないで元の大きさに戻し、`PrintWindow` で窓だけを撮った。撮ったらすぐに終了させた。
- カメラから遠い玉座・像・壁の灯りは、`make_boss_stage.py` が書き出す確かめ用の画像（`tools/BossStage/preview/`）でも見て、形が崩れていないことを確かめた。

**用語:**

| 用語 | 何のことか |
|---|---|
| FBX | 3Dモデルを交換するためのファイル形式（`.fbx`）。広間は Blender から FBX で書き出し、エンジンが tkm に変換して読む |
| `PrintWindow` | Windows の API（`<windows.h>`）。ほかの窓の上に重ならなくても、その窓の中身だけを画像として取り出す |

### 試したこと: がれきも減らしたとき

がれきを 0.4 にしたときの拡大（左が減らす前、右が 0.4）。石の細かいでこぼこがなくなり、のっぺりした。これを見て、がれきは減らさないことにした。

## 2026-11-15 減らしたあと、FPS も約 164 から約 238 に上がった

広間はゲームの中でも重く、約 168 FPS しか出ていなかった。測ると、重いのは光や影ではなく広間のモデル `BossHall` の三角形の多さだった（[最適化の方法の経緯](../../最適化の方法/最適化の方法の経緯.md)）。上の「部品の三角形を減らした」は起動を速くするためにしたものだが、この重さも減らしている。

同じ exe で、減らす前と後のモデルを入れ替えて交互に3回ずつ測ると、**約 164 → 約 238 FPS**（1フレーム 6.10 → 4.21ms）になった。測り方は [最適化の方法の経緯](../../最適化の方法/最適化の方法の経緯.md) の「5. どう確かめたか」。
