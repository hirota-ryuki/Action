# フレームレートの手順

設計: [フレームレートの設計](フレームレートの設計.md)
経緯: [フレームレートの経緯](フレームレートの経緯.md)

FPS の上限（60）と VSync の待ちを外し、FPS が上がってもゲームの動きが速くならないようにするまでの手順です。上から順にやると、[フレームレートの設計](フレームレートの設計.md) の形になります。

**出来上がるもの:** ゲームが GPU・CPU の出せるだけの FPS で動きます。エフェクト・物理・カメラの右スティックは、FPS が変わっても同じ速さで動きます。

**前提:**

- Visual Studio で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 始める前は、エンジンにもとからある形（FPS の上限 60、VSync を待つ）になっている。
- [README の「ゲームを作る順番」](../../../README.md#ゲームを作る順番) のゲームの手順書で `GameCamera` を作った場合は、手順4の形（経過時間で数える）がもう入っているので、手順4は飛ばす。
- 内蔵の GPU で描いていると、上限を外しても 30fps 前後しか出ないことがある。そのときは [GPUの選び方の手順](../GPUの選び方/GPUの選び方の手順.md) もやる。

| 手順 | 足すもの | 確かめ方 |
|---|---|---|
| 1 | FPS の上限と VSync の待ちを外す | FPS が 60 より上に出る |
| 2 | エフェクトを経過時間で進める | エフェクトの速さが FPS で変わらない |
| 3 | 物理を経過時間で進める | 物理で動く物の速さが FPS で変わらない |
| 4 | カメラの右スティックを経過時間で回す | 右スティックで回る速さが FPS で変わらない |

**読み方:**

- 足す場所は「〇行目 `その行に書いてあること` の下」で示します。行番号は、それより前の小手順を済ませたときの番号です。
- 枠の左の数字は、足したあとの行番号です。右の枠のコードを、そのまま書きます。
- 消すところは、消す行を枠で示します（番号は消す前の番号）。書き換えるところは、「前」と「後」の枠を並べています。
- 小手順の見出しは、足すコードのコメントか関数の名前です。何のためのコードかは、コードのコメントに書いてあります。
- コードの下に、3つを置きます。
  - 「行・何をしているか」の表: 1行ずつの動き。
  - 「なぜ」「効果」: その小手順でそう書く理由と、書くと何ができるようになるか。
  - 「初めて出てくる名前」の表: このページで初めて出てくる変数・引数・関数・型・マクロ・C++ の書き方を、コードに出てくる順に並べます。2回目からは載せないので、わからない名前はページ内検索（`Ctrl+F`）で最初に出てきた所を探してください。「どこから来たもの」で、このゲームで作ったもの・エンジン（k2Engine）の機能・C++ の標準ライブラリ・C++ の書き方のどれかがわかります。
- [前提知識](../../../前提知識.md) で「よく知っている」にあるもの（`constexpr`・`static`・マクロ・`const`・Effekseer など）は、表に載せません。
- VSCode で `Ctrl+Shift+V` を押してプレビューで読みます。

## 手順4: カメラの右スティックを経過時間で回す

右スティックでのカメラの回転は「1フレームに 2度」だったので、FPS が上がると速く回ります。「1秒に 120度」にして、経過時間を掛けます（60FPS のときの 2度 × 60 = 120度）。マウスは動いた量で回すので、変えません。

- **効果:** FPS が変わっても、右スティックでカメラが回る速さは同じになる。

- ソリューションのビルドが通る。

## 上限を戻すとき

手順1の `//#define USE_FPS_LIMITTER` のコメントを外すだけで、60FPS の上限と VSync の待ちが戻ります。手順2〜5は経過時間で動くので、戻したあとも同じ速さのまま使えます。
