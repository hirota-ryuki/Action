# フレームレートの設計

作成日: 2026-11-06
対象: `k2EngineLow` のフレームレート制御（FPS の上限、VSync、1フレームの経過時間）
経緯: [フレームレートの経緯](フレームレートの経緯.md)
手順: [フレームレートの手順](フレームレートの手順.md)（どのファイルに何を足し、何をコメントアウトしたか）

このドキュメントでは、1フレームの長さがどう決まり、ゲームの処理にどう渡されるかを説明します。
FPS の上限を変えたいとき、動きの速さが FPS で変わってしまうときに読んでください。

- 今は **FPS の上限なし**（`USE_FPS_LIMITTER` を無効）で動かしている。VSync も待たない。
- ゲームの処理は `g_gameTime->GetFrameDeltaTime()` を掛けて動かすので、FPS が変わっても動く速さは変わらない。
- 上限は `k2EngineLowPreCompile.h` の1行で戻せる。

**用語:**

| 用語 | 何のことか |
|---|---|
| VSync | 垂直同期。モニターが画面を書き換えるタイミングまで、`Present()` で待つこと。待つと、FPS はモニターのリフレッシュレート（1秒に画面を書き換える回数）より上がらない |

---

## 1. 全体像

1フレームは `K2EngineLow` の `BeginFrame()` から `EndFrame()` までです。

```
K2EngineLow::BeginFrame()
 ├─ FPSLimitter::BeginFrame()      … 上限用のストップウォッチを開始
 ├─ GameTime::BeginMeasurement()   … 経過時間の計測を開始
 └─ GraphicsEngine::BeginRender()

  （ゲームの更新・描画）

K2EngineLow::EndFrame()
 ├─ GraphicsEngine::EndRender()
 │    └─ FrameBuffer::Present(syncInterval)   … USE_FPS_LIMITTER が有効なら 1（VSync 待ち）、無効なら 0
 ├─ FPSLimitter::Wait()            … USE_FPS_LIMITTER が有効なときだけ。最大FPSを超えないよう待つ
 └─ GameTime::EndMeasurement()     … 経過時間を記録 → 次のフレームの GetFrameDeltaTime() になる
```

**用語:**

| 用語 | 何のことか |
|---|---|
| ストップウォッチ | 経過時間を計る部品（`Stopwatch` クラス）。`Start()` で計り始め、`Stop()` で止めて、経過時間を取り出せる |
| `Present()` | 描き終えた画面をモニターに出す関数。引数が 1 ならモニターの更新を待ち、0 なら待たない |

| 部品 | ファイル | 役割 |
|---|---|---|
| `USE_FPS_LIMITTER` / `MAX_FPS` | [k2EngineLowPreCompile.h](../../../../k2EngineLow/k2EngineLowPreCompile.h) | 上限を付けるかどうか、最大FPS（60） |
| `FPSLimitter` | [FPSLimitter.h](../../../../k2EngineLow/time/FPSLimitter.h) | 最大FPSに届くまでスピンして待つ |
| `GameTime` | [GameTime.h](../../../../k2EngineLow/time/GameTime.h) | 1フレームの経過時間を計り、ゲームに渡す |
| `K2EngineLow::SetFrameRateMode()` | [k2EngineLow.h](../../../../k2EngineLow/k2EngineLow.h) | 固定 / 可変フレームレートの切り替え |
| `GraphicsEngine::EndRender()` | [GraphicsEngine.cpp](../../../../k2EngineLow/graphics/GraphicsEngine.cpp) | `Present()` の待ち方（VSync）を決める |
| FPS の表示 | [DebugHud.cpp](../../../../Game/Source/UI/Hud/DebugHud.cpp) | ゲームの UI で、右上に 0.5秒ごとの平均を出す（[FPSの表示の設計](../../../ゲーム/UI/FPSの表示/FPSの表示の設計.md)）。`K2EngineLow::EndFrame()` で描いていた処理はコメントアウトして止めている |

---

## 2. 詳細

### 2.1 FPS の上限（USE_FPS_LIMITTER）

`USE_FPS_LIMITTER` は、次の2つをまとめて切り替えます。

| | 有効 | 無効（今） |
|---|---|---|
| `Present()` の待ち | `Present(1)`: モニターの更新（VSync）を待つ | `Present(0)`: 待たない |
| `FPSLimitter::Wait()` | `MAX_FPS`（60）を超えないよう待つ | 呼ばない |
| 結果の FPS | モニターのリフレッシュレートか 60 の低い方 | GPU・CPU が出せるだけ |

スワップチェーンは `DXGI_SWAP_EFFECT_FLIP_DISCARD` なので、`Present(0)` ではモニターより速く描いた分の古いフレームは捨てられ、画面には新しいフレームが出ます。
`DXGI_PRESENT_ALLOW_TEARING` は使っていないため、フルスクリーンでもティアリングを許すモードにはなりません。

**用語:**

| 用語 | 何のことか |
|---|---|
| スワップチェーン | 画面に出す絵を入れておく、複数枚のバッファの組。1枚を画面に出している間に、別の1枚へ次の絵を描く |
| `DXGI_SWAP_EFFECT_FLIP_DISCARD` | スワップチェーンの切り替え方の指定。画面に出し終えた古いバッファの中身は捨てる |
| ティアリング | モニターの更新の途中で絵が切り替わり、画面の上下で絵がずれて見えること |
| `DXGI_PRESENT_ALLOW_TEARING` | `Present()` に渡せる指定。VSync を待たないとき、ティアリングを許して遅れを減らす |

### 2.2 1フレームの経過時間（GameTime）

`GameTime` には2つのモードがあります。`SetFrameRateMode()` で切り替えます。

| モード | `GetFrameDeltaTime()` が返す値 | 使う場面 |
|---|---|---|
| 可変（`enFrameRateMode_Variable`、既定） | 計った経過時間の平均（直近30フレーム）。ただし **1/30 秒より大きくはならない** | 普段のゲーム |
| 固定（`enFrameRateMode_Fix`） | `1 / maxFPS` の固定値 | 今は使っていない |

可変モードでは FPS が上がるほど返る値が小さくなり、動きの速さは変わりません。

## 3. 実装方法

### 3.1 上限の切り替えはマクロ1つ

上限は実行時のフラグではなく、プリプロセッサのマクロで切り替えています。

```cpp
// k2EngineLowPreCompile.h
//#define USE_FPS_LIMITTER		// 有効でFPSに上限を設ける。（無効にしてFPS無制限）
static const int MAX_FPS = 60;	// 最大FPS。USE_FPS_LIMITTERが有効なときに使用される。
```

```cpp
// GraphicsEngine::EndRender()
#ifdef USE_FPS_LIMITTER
			m_frameBuffer.Present(1);
#else
			m_frameBuffer.Present(0);
#endif
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| メンバー変数 | `m_frameBuffer` | 描いた絵を画面に出す部品を持つため | スワップチェーンを持つ `FrameBuffer`。`Present()` はこの部品の関数 | k2EngineLow（エンジン）の [GraphicsEngine.h](../../../../k2EngineLow/graphics/GraphicsEngine.h) の `GraphicsEngine` クラス |

```cpp
// K2EngineLow::EndFrame()
		m_graphicsEngine->EndRender();
#ifdef USE_FPS_LIMITTER
		m_fpsLimitter.Wait();
#endif
		m_gameTime.EndMeasurement();
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| メンバー変数 | `m_graphicsEngine` | 描画の終わりの処理を呼ぶため | `GraphicsEngine` へのポインター。`EndRender()` で `Present()` まで進める | k2EngineLow（エンジン）の [k2EngineLow.h](../../../../k2EngineLow/k2EngineLow.h) の `K2EngineLow` クラス |
| メンバー変数 | `m_fpsLimitter` | FPS の上限を守るための待ちをするため | `FPSLimitter`。`Wait()` が最大FPSに届くまで待つ | k2EngineLow（エンジン）の [k2EngineLow.h](../../../../k2EngineLow/k2EngineLow.h) の `K2EngineLow` クラス |
| メンバー変数 | `m_gameTime` | 1フレームの経過時間を計って覚えるため | `GameTime`。`EndMeasurement()` で経過時間を記録する | k2EngineLow（エンジン）の [k2EngineLow.h](../../../../k2EngineLow/k2EngineLow.h) の `K2EngineLow` クラス |

VSync と FPSLimitter を同じマクロで止めているのは、片方だけ止めても FPS が上がらないためです（VSync を止めても FPSLimitter が 60 で待つ、FPSLimitter を止めても VSync がリフレッシュレートで待つ）。

### 3.2 FPSLimitter はスピンで待つ

`Sleep()` は精度が粗い（1〜15ms）ので、ストップウォッチを回し続けて残り時間が 1ms 以下になるまでループします。待っている間も CPU のコアを1つ使います。

```cpp
float frameDeltaTimeMin = 1000.0f / m_maxFPS;
do {
	m_sw.Stop();
	restTime = frameDeltaTimeMin - (int)m_sw.GetElapsedMillisecond();
} while (restTime > 1.0f);
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 変数 | `frameDeltaTimeMin` | 1フレームの最短の長さを持つため | `1000 / 最大FPS`（ミリ秒）。60 なら約 16.7ms | k2EngineLow（エンジン）の [FPSLimitter.h](../../../../k2EngineLow/time/FPSLimitter.h) の `Wait()` |
| メンバー変数 | `m_maxFPS` | 上限のFPSを持つため | 最大FPS。初期値は `MAX_FPS`（60） | k2EngineLow（エンジン）の [FPSLimitter.h](../../../../k2EngineLow/time/FPSLimitter.h) の `FPSLimitter` クラス |
| メンバー変数 | `m_sw` | `BeginFrame()` から今までの時間を計るため | `Stopwatch`。`BeginFrame()` で `Start()` している | k2EngineLow（エンジン）の [FPSLimitter.h](../../../../k2EngineLow/time/FPSLimitter.h) の `FPSLimitter` クラス |
| 関数 | `Stop()` | 今までの経過時間を確定するため | 計測を止めて経過時間を取り出せるようにする（呼ぶたびに計り直し） | k2EngineLow（エンジン）の [Stopwatch.h](../../../../k2EngineLow/time/Stopwatch.h) |
| 変数 | `restTime` | あと何ミリ秒待てばよいかを持つため | 1フレームの最短の長さから経過時間を引いた残り。1 以下になったらループを抜ける | k2EngineLow（エンジン）の [FPSLimitter.h](../../../../k2EngineLow/time/FPSLimitter.h) の `Wait()` |
| 関数 | `GetElapsedMillisecond()` | 経過時間をミリ秒で読むため | `Stop()` したときの経過時間（ミリ秒、`double`）を返す | k2EngineLow（エンジン）の [Stopwatch.h](../../../../k2EngineLow/time/Stopwatch.h) |

### 3.3 経過時間は平均して上限を付ける

1フレームごとの値はぶれるので、直近30フレームの平均を使います。さらに、ロード直後などで1フレームが長くなったときに物が大きく飛ばないよう、1/30 秒で頭打ちにしています。

```cpp
m_frameDeltaTime = min(1.0f / 30.0f, totalTime / m_frameDeltaTimeQue.size());
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| メンバー変数 | `m_frameDeltaTime` | 1フレームの経過時間を持つため | 可変モードのとき `GetFrameDeltaTime()` が返す値（秒） | k2EngineLow（エンジン）の [GameTime.h](../../../../k2EngineLow/time/GameTime.h) |
| 関数 | `min()` | 経過時間に上限を付けるため | 2つのうち小さい方を返す。`std::` が付かないので、`std::min` ではなく Windows のマクロ | Windows の API（<windows.h>。[k2EngineLowPreCompile.h](../../../../k2EngineLow/k2EngineLowPreCompile.h) で読み込み済み） |
| 変数 | `totalTime` | 直近の経過時間の合計を持つため | `m_frameDeltaTimeQue` の全部を足したもの。これを個数で割って平均にする | k2EngineLow（エンジン）の [GameTime.h](../../../../k2EngineLow/time/GameTime.h) の `PushFrameDeltaTime()` |
| メンバー変数 | `m_frameDeltaTimeQue` | 直近の経過時間を並べて覚えるため | 経過時間（`float`）の `std::list`。30個を超えたら古いものから捨てる | k2EngineLow（エンジン）の [GameTime.h](../../../../k2EngineLow/time/GameTime.h) の `GameTime` クラス |
| 関数 | `size()` | 平均に使う個数を得るため | `std::list` に入っている要素の数を返す | C++ の標準ライブラリ（`std::list` のメンバー。`<list>` は [k2EngineLowPreCompile.h](../../../../k2EngineLow/k2EngineLowPreCompile.h) で読み込み済み） |

## 4. 使い方

### 4.1 FPS の上限を戻す

[k2EngineLowPreCompile.h](../../../../k2EngineLow/k2EngineLowPreCompile.h) の `//#define USE_FPS_LIMITTER` のコメントを外します。最大FPSを変えたいときは `MAX_FPS` を変えます。

### 4.2 今の FPS を見る

どのビルドでも、ゲームの画面の右上に `FPS xx.x` が出ます。ゲームの UI の [DebugHud.cpp](../../../../Game/Source/UI/Hud/DebugHud.cpp) が、実際の時間で測った 0.5秒ごとの平均を出しています（[FPSの表示の設計](../../../ゲーム/UI/FPSの表示/FPSの表示の設計.md)）。

`K2EngineLow::EndFrame()` で `FPS = xx.xx` を描く処理は、コメントアウトして止めています。こちらは `1 / GetFrameDeltaTime()` なので、30 FPS より下が出せません。

### 4.3 ゲームの処理を書くとき

動く量・タイマーには必ず `g_gameTime->GetFrameDeltaTime()` を掛けます。1フレームあたりの固定値で動かすと、FPS 無制限では FPS に比例して速くなります。

エンジンの中で経過時間を使っているもの:

| もの | 場所 | 進め方 |
|---|---|---|
| エフェクト（Effekseer） | `EffectEngine::Update()` | 経過時間 × `EffectEngine::FRAMES_PER_SECOND`（60）フレームだけ進める。エフェクトの時間をフレームで数えるときは、同じ数え方にする |
| 物理（Bullet） | `GameObjectManager::ExecuteUpdate()` → `PhysicsWorld::Update()` | 実際の経過時間を渡す。Bullet の中で 1/60秒ずつに分けて進める |
| 明るさに目が慣れる速さ | `CalcSceneLuminance` | 毎フレーム経過時間を定数バッファに入れる |
| カメラの右スティックの回転 | `GameCamera::GetCameraRotationInput()` | 120°/秒 × 経過時間。マウスは動いた量なのでそのまま |

3D サウンドのドップラー効果（`SoundEngine::Update()` の聞く側の速さ）は、まだ 60 で割る決め打ちのまま。ゲームで音を使い始めるときに、単位（cm と音速）をそろえて直す。

## 5. 調整用の数値

| 名前 | 場所 | 値 | 意味 |
|---|---|---|---|
| `USE_FPS_LIMITTER` | `k2EngineLowPreCompile.h` | 無効 | 上限と VSync を使うか |
| `MAX_FPS` | `k2EngineLowPreCompile.h` | 60 | 上限を使うときの最大FPS |
| 平均するフレーム数 | `GameTime::PushFrameDeltaTime()` | 30 | 経過時間の平均を取る数 |
| 経過時間の上限 | 同上 | 1/30 秒 | 1フレームの経過時間の最大値 |

---

## 6. 決めたこと

- **FPS の上限をなくしている。** どこまで FPS が出るかを試すため。上限は1行で戻せる（[経緯](フレームレートの経緯.md)）。

---

## 7. 既知の課題

- **ティアリングが出ることがある**。VSync を待たないので、ウィンドウの状態によっては画面の上下でずれが見えることがあります。
- **FPS が高いと GPU・CPU を使い切る**。ノートPCでは発熱や電池の減りが大きくなります。
- **1/30 秒より長いフレームでは遅く見える**。経過時間に上限があるため、FPS が 30 を下回るとゲームの進みがゆっくりになります（上限なしとは関係ない）。
