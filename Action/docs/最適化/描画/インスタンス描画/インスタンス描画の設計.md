# インスタンス描画の設計

作成日: 2026-11-08
対象: [ModelRender.h](../../../../k2Engine/graphics/ModelRender.h)、[ModelRender.cpp](../../../../k2Engine/graphics/ModelRender.cpp) のインスタンス描画、[ModelVSCommon.h](../../../../Game/Assets/shader/ModelVSCommon.h) の `VSMainInstancing`
経緯: [ステージの経緯](../../../ゲーム/ステージ/ステージの経緯.md)（2026-11-08 の「つまずいたこと」の 3）、[ステージの軽量化の経緯](../../ステージ/ステージの軽量化/ステージの軽量化の経緯.md)（行列で渡す・幾何学データの更新を減らす）

同じモデルをたくさん置くときに、まとめて描くための仕組みのページです。今はゲームのどこからも使っていません（使っていた草原のステージは 2026-11-15 に消しました）。それでも仕組みを残しているのは、同じ物を大量に置く場面（草・石など）をまた作るときに、そのまま使えるようにするためです。

- **アニメーションのないモデルは GPU インスタンシングで描く。** 頂点はモデルのまま、頂点シェーダーでインスタンスごとのワールド行列を掛ける。
- **描くのは、そのフレームに `UpdateInstancingData()` で渡した数だけ。** 渡さなかった物は描かれない。
- **画面の外の物を飛ばす処理（カリング）はしない。** 呼ぶ側で、描く物だけを渡す。

**用語:**

| 用語 | 何のことか |
|---|---|
| カリング | 画面に入らない物を、描かないことにする処理 |
| 計算シェーダー | 描くためではなく、GPU に計算だけをさせるシェーダー。ここでは頂点の事前計算に使う |
| スキン | 骨（ボーン）の動きに合わせて、モデルの頂点を動かすこと |
| 頂点バッファ | 頂点のデータを入れておく GPU のメモリ |
| G バッファ | 色・法線などを、画面と同じ大きさの画像として別々に描き出しておく場所。光の計算は、あとでこれを読んで行う（[用語集](../../../用語集.md#描画)） |
| ZPrepass | 色を塗る前に、奥行きだけを先に描いておく描画。あとで隠れる物の色の計算を省く |
| SRV | Shader Resource View。シェーダーが読む資源（テクスチャや配列）を、GPU に見せるための窓口 |
| 拡張 SRV | モデルを作るときに、使う側が足せる SRV（`ModelInitData::m_expandShaderResoruceView`）。0 番から並ぶ |
| `t10` | シェーダーの中で、読み取り用の資源を受け取る場所の番号（`register(t10)`）。拡張 SRV の 0 番がここに入る |

GPU インスタンシングは[用語集](../../../用語集.md#描画)を見てください。

---

## 1. 全体像

| 種類 | 頂点の作り方 | 1回の描画で描く数 |
|---|---|---|
| 普通のモデル（`maxInstance` が 1） | 計算シェーダーで頂点を事前計算する（スキンもここで計算） | 1 |
| アニメーションありのインスタンス描画 | 全インスタンス分の頂点を事前計算し、大きな頂点バッファにまとめる | 1（まとめたものを1回） |
| **アニメーションなしのインスタンス描画** | **事前計算しない。モデルの頂点のまま** | **渡した数** |

`ModelRender::Init()` に `maxInstance` を 2 以上、アニメーションクリップを `nullptr` で渡すと、3つ目になる（`m_isGpuInstancing`）。

## 2. 実装方法

### 初期化

`InitComputeAnimatoinVertexBuffer()` の頭で決める。`InitAnimation()` のあとに呼ばれるので、ここでアニメーションの有無がわかっている。

```cpp
m_isGpuInstancing = m_isEnableInstancingDraw && m_animationClips == nullptr;
if (m_isGpuInstancing) {
    return;  // 頂点の事前計算は作らない
}
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| メンバー変数 | `m_isEnableInstancingDraw` | インスタンス描画が使えるかを覚えるため | `Init()` に `maxInstance` を 2 以上で渡されたら true | k2Engine（エンジン）の [ModelRender.h](../../../../k2Engine/graphics/ModelRender.h) の `ModelRender` クラス |
| メンバー変数 | `m_animationClips` | アニメーションがあるかを見分けるため | `Init()` で渡されたアニメーションクリップ。`nullptr` ならアニメーションなし | k2Engine（エンジン）の [ModelRender.h](../../../../k2Engine/graphics/ModelRender.h) の `ModelRender` クラス |

G バッファ・ZPrepass・シャドウマップ・半透明の各モデルを作るところで、`SetupGpuInstancing()` が設定を書き換える。次の2行が、その書き換えの中身。

```cpp
modelInitData.m_computedAnimationVertexBuffer = nullptr;   // モデルの頂点バッファで描く
modelInitData.m_vsEntryPointFunc = "VSMainInstancing";     // g_worldMatrixArray[SV_InstanceID] を掛ける
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 関数 | `SetupGpuInstancing()` | 4種類のモデルの作り方で、同じ書き換えを使い回すため | `m_isGpuInstancing` のときだけ、渡された `ModelInitData` を、モデルの頂点バッファと `VSMainInstancing` で描く設定に書き換える | k2Engine（エンジン）の [ModelRender.cpp](../../../../k2Engine/graphics/ModelRender.cpp) の `ModelRender` クラス |
| 引数 | `modelInitData` | 作るモデルの設定を受け取って書き換えるため | モデルを作るときの設定（`ModelInitData`）の参照。`SetupGpuInstancing()` の引数 | k2EngineLow（エンジン）の [Model.h](../../../../k2EngineLow/graphics/Model.h) |
| メンバー変数 | `m_computedAnimationVertexBuffer` | 事前計算した頂点を使うかを決めるため | 事前計算した頂点を持つ `ComputeAnimationVertexBuffer` へのポインター。`nullptr` にすると、モデルの頂点バッファで描く | k2EngineLow（エンジン）の [Model.h](../../../../k2EngineLow/graphics/Model.h) の `ModelInitData` |
| メンバー変数 | `m_vsEntryPointFunc` | 使う頂点シェーダーを決めるため | 頂点シェーダーの関数の名前（文字列）。初期値は `"VSMain"` | k2EngineLow（エンジン）の [Model.h](../../../../k2EngineLow/graphics/Model.h) の `ModelInitData` |
| 関数 | `VSMainInstancing()` | インスタンスごとのワールド行列を頂点に掛けるため | インスタンス番号に対応するワールド行列を `g_worldMatrixArray` から取り、頂点に掛ける（HLSL） | ゲームの [ModelVSCommon.h](../../../../Game/Assets/shader/ModelVSCommon.h) |
| 変数 | `g_worldMatrixArray` | 全インスタンスのワールド行列を読むため | ワールド行列の配列（`StructuredBuffer<float4x4>`）。`register(t10)` で受け取る | ゲームの [ModelVSCommon.h](../../../../Game/Assets/shader/ModelVSCommon.h) |
| 値 | `SV_InstanceID` | 何番目のインスタンスを描いているかを知るため | 頂点シェーダーに、インスタンスの番号（0 から）を渡す指定 | HLSL（シェーダーの言語）の組み込みの指定（セマンティクス） |

ワールド行列の配列（`m_worldMatrixArraySB`）は、エンジンのもとのコードが、すでに拡張 SRV の 0 番（`t10`）に渡していて、シェーダーの `g_worldMatrixArray` がそれを読む。

### 毎フレーム

1. 呼ぶ側が `UpdateInstancingData(番号, 位置, 回転, 拡大)` か `UpdateInstancingData(番号, 行列)` を、番号 0 から詰めて呼ぶ。1回ごとに `m_numInstance` が 1 増える。
   - 位置・回転・拡大で渡すと、中で `CalcWorldMatrix()` を呼んで行列にしてから、行列の方に渡す。
   - 動かない物は、`CalcWorldMatrix()` で行列を最初に作っておき、行列の方で渡すと、毎フレームの行列の計算がなくなる。
2. `Draw()` で行列の配列を GPU に送り、`m_numDrawInstance = m_numInstance` として覚えてから `m_numInstance` を 0 に戻す。2つの変数の値は、1フレームの中で次のように変わる（前のフレームに N 個、このフレームに n 個渡した場合）。

   | 時点 | `m_numInstance`（渡した数を数える） | `m_numDrawInstance`（描く数） |
   |---|---|---|
   | `UpdateInstancingData()` を呼ぶ前 | 0 | N（前のフレームの数） |
   | `UpdateInstancingData()` を n 回呼んだあと | n | N |
   | `Draw()` のあと | 0 | n |
3. 描画パスの `OnRenderToGBuffer()` などは `GetDrawInstanceCount()`（GPU インスタンシングなら `m_numDrawInstance`、それ以外は 1）を描く数として渡す。0 なら何も描かない。

### 幾何学データの更新

エンジンは番号ごとに「幾何学データ」（`GemometryData`。ワールド座標の箱で、影の範囲を決めるのに使う）を持つ。`ModelRender` が `m_geometryDatas` に番号の数だけ持ち、シーン全体の `SceneGeometryData` に登録する。`SceneGeometryData::Update` が、登録された全部の `GemometryData` を毎フレーム更新する。番号は最大数ぶんあるので、草のように数千置くと、描かない番号の更新で CPU が重くなる。そこで `GemometryData::Update()`（`Gemometry` はコードの綴りで、Geometry の誤り）の頭で `ModelRender::IsGeometryDataActive(番号)` を見て、要らない番号はすぐ戻る。

```cpp
bool IsGeometryDataActive(int instanceId) const
{
    if (!m_isGpuInstancing) return true;     // GPU インスタンシング以外は、いつも更新
    if (!m_isShadowCaster) return false;     // 影を落とさない物は、箱を使わない
    return instanceId < (std::max)(m_numInstance, m_numDrawInstance);  // このフレームに渡した番号だけ
}
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 引数 | `instanceId` | 何番目のインスタンスの箱かを受け取るため | 幾何学データの番号 | k2Engine（エンジン）の [ModelRender.h](../../../../k2Engine/graphics/ModelRender.h)（`IsGeometryDataActive()` の引数） |
| メンバー変数 | `m_isShadowCaster` | 影を落とす物かを覚えるため | 影を落とすなら true（初期値 true） | k2Engine（エンジン）の [ModelRender.h](../../../../k2Engine/graphics/ModelRender.h) の `ModelRender` クラス |
| C++ の書き方 | `(std::max)` | `max` を、マクロでなく関数として呼ぶため | `std::max` をかっこで囲む。囲まないと、Windows の `max` マクロ（このプロジェクトは `NOMINMAX` を定義していない）と取り違える | C++ の書き方 |

## 3. 使い方

```cpp
// 初期化：最大数を 2 以上にする（1 だとインスタンス描画にならない）
m_modelRender.Init("Assets/modelData/xxx.fbx", nullptr, 0, enModelUpAxisZ, true, maxInstance);

// 毎フレーム（Update）：描く物だけを 0 番から詰めて渡す
int n = 0;
for (auto& item : items) {
    if (見えない) continue;
    m_modelRender.UpdateInstancingData(n++, item.position, item.rotation, item.scale);
}

// 描画（Render）
if (n > 0) m_modelRender.Draw(rc);
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `enModelUpAxisZ` | モデルの上方向の軸を指定するため | モデルの上方向が Z 軸（`EnModelUpAxis` の値） | k2EngineLow（エンジン）の [GraphicsEngine.h](../../../../k2EngineLow/graphics/GraphicsEngine.h) |
| 変数 | `maxInstance` | 置ける最大数を決めるため | インスタンスの最大数（2 以上） | 使う側が決める |

- 動かない物を毎フレーム渡すときは、`CalcWorldMatrix()` で作った行列を覚えておき、`UpdateInstancingData(番号, 行列)` で渡す。
- `Update()` は呼ばなくてよい（インスタンス描画のときは何もしない）。
- 1つも渡さないフレームは `Draw()` を呼ばない。

## 4. 決めたこと

- もとの「全インスタンス分を事前計算する」作りは、アニメーションありのインスタンス描画のために残した（今は使っている所がない）。
- カリングはエンジンに入れず、呼ぶ側に任せた。物の並び方（区画など）は使う側の方がよく知っているため。

## 5. 既知の課題

- アニメーションありのインスタンス描画は、今も全インスタンスを毎フレーム事前計算し、描く数の指定もない。使うときに見直す。
- `RemoveInstance()` は行列を 0 にするだけなので、GPU インスタンシングでは「番号を詰めて渡す」使い方をする。
