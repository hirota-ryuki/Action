# ドキュメント一覧

このフォルダには、機能の設計や実装の経緯を説明するドキュメントを置いています。
新しい機能を作ったり、既存のコードを読み始めたりするときは、まずここから探してください。

---

## フォルダ構成

```
docs/
├── README.md                ← この一覧
├── 01_設計書/                ← 今のコードの構造・役割分担・実装方法
│   ├── ゲーム/               ← Game プロジェクト（キャラクター・魔法・カメラなど）
│   └── エンジン/             ← k2Engine / k2EngineLow（描画・モデル読み込みなど）
└── 02_実装レポート/          ← ある時点での実装の経緯・検証結果・判断待ちの事項
    ├── ゲーム/
    └── エンジン/
```

| フォルダ | 何が書いてあるか | 読むとき |
|---|---|---|
| `01_設計書` | 今のコードがどういう構造になっているか。コードを変えたら一緒に直す | コードを読む前、機能を追加する前 |
| `02_実装レポート` | ある時点で何をして、どう確かめたか。基本的に書いた時点のまま残す | なぜ今の形になっているかを知りたいとき |

その下は、対象のコードがどちらにあるかで分けています。

| フォルダ | 対象のコード |
|---|---|
| `ゲーム` | `Action/Game/`（ゲーム固有の処理） |
| `エンジン` | `Action/k2Engine/`、`Action/k2EngineLow/`（エンジンの処理） |

## ドキュメントを追加するとき

1. 種類（`01_設計書` か `02_実装レポート`）と分野（`ゲーム` か `エンジン`）でフォルダを選ぶ。
   - 該当するフォルダがなければ作ってよい（例: `01_設計書/エンジン/`）。
2. **設計書は項目ごとに1ページ**にする。別の項目を、すでにある設計書に書き足さない。
   - 例: 炎魔法を足したら、`魔法と弾の設計.md` に章を足すのではなく `炎魔法の設計.md` を作る。
   - 共通の仕組みのページからは、各項目のページへリンクを張る。
   - 章は「全体像 → 詳細 → 実装方法 → 調整用の数値 → 決めたこと → 既知の課題 → 関連するページ」の順にする。無い章は飛ばしてよい。ただし「実装方法」（その仕組みを使って何かを足す手順）は必ず書き、章の名前もこの名前にそろえる。
   - 冒頭の説明のすぐ下に、方針を2〜3行の箇条書きで書く。以前の形や理由は「決めたこと」に回す。
   - 経緯（何が遅かった・どう調べた）は設計書ではなく実装レポートに書く。
3. ファイル名は**日本語のタイトル**にする。
   - スペースは使わない。区切りは `_` か `・` にする。
   - 例: `プレイヤーのステートの設計.md`、`FBXランタイムインポート機能_実装・検証レポート.md`
4. 冒頭に、タイトル・作成日・対象（ブランチや機能）を書く。
5. ソースコードへのリンクは、そのドキュメントからの相対パスで書く（例: `01_設計書/ゲーム/` からなら `../../../Game/Source/...`）。
6. **この一覧の表に1行追加する**。目的から引けるように、必要なら「目的から探す」の表にも追加する。
7. 内容が古くなったときは、
   - 設計書は、コードに合わせて直す。
   - 実装レポートは消さずに、何が古いかをこの一覧の「注意事項」に書く。
