## 2026-11-19 アクティビティバーからアカウントを切り替える拡張機能を作る

- アクティビティバーにアカウントの一覧を出し、押したら切り替えたい、という頼みで作った。
- 切り替え方は2つを比べ、2にした。
  1. ログアウトしてログインし直す（`/logout` → `/login`）。毎回ブラウザでアカウントを選ぶことになり、一覧はどれでログインするかのメモにしかならない。
  2. ログイン情報を保存しておき、ファイルを入れ替える。ブラウザはアカウントごとに最初の1回だけ。Claude Code の公式な決まりではないので、更新で効かなくなるかもしれない。
- 入れ替えるファイルを決めるため、`~/.claude/.credentials.json` と `~/.claude.json` の**項目の名前だけ**を見た（中身の鍵は見ていない）。`.credentials.json` は `claudeAiOauth` の中にアクセストークン・リフレッシュトークン・期限など、`~/.claude.json` の `oauthAccount` には `accountUuid`・`emailAddress`・`organizationUuid` などが入っていた。鍵だけを替えると、表示されるアカウントと使う鍵が食い違うので、`oauthAccount` も一緒に替えることにした。
- 使っている間にリフレッシュトークンが取り替えられることがあるので、切り替える前に、使用中のアカウントを今の `.credentials.json` で保存し直すことにした。
- このPCには Node.js がないので、ビルドの要らない JavaScript 1ファイルで書き、VSCode にはジャンクションで読ませた（`.vsix` を作る道具 `vsce` は Node.js が要る）。
- Windows PowerShell 5.1 は、BOM のない `.ps1` の日本語を読み違えて文法の誤りになった。リポジトリのほかの `.ps1` と同じく、UTF-8（BOM 付き）で保存した。

### どう確かめたか

1. **VSCode が拡張機能として読むか。** `install-claude-accounts.ps1` でジャンクションを作り、`code --list-extensions --show-versions` に `local.claude-accounts@0.0.1` が出ることを見た。
2. **保存・切り替え・消すの動き。** 本物のログイン情報に触らないよう、使い捨てのフォルダを `USERPROFILE` にし、偽の `.credentials.json`・`.claude.json` を置いた。`vscode` の部分を差し替えた試験のスクリプトから `extension.js` を動かした（VSCode の `Code.exe` を `ELECTRON_RUN_AS_NODE=1` で動かすと Node.js として使える。窓は出さない）。結果は次のとおりで、どれも想定どおりだった。

| 試したこと | 結果 |
|---|---|
| A を保存 → B でログインしたことにして B を保存 | 一覧に A・B、B に「（使用中）」とチェック |
| B の鍵を B2 に変えて（使っている間の取り替え）から A に切り替え | `.credentials.json` が A の鍵に、`oauthAccount` が A に。`~/.claude.json` のほかの項目（`numStartups`）はそのまま |
| A に切り替えたあとの B の保存 | B2（取り替えたあとの鍵）になっていた |

| B のまま「+」で名前を「B仕事」にする | ファイルは増えず（`uA.json`・`uB.json` のまま）、名前だけ替わった |
| A を消す | 一覧から A が消えた |
| 保存していない C でログインしたことにして切り替え、確かめで「やめる」 | `.credentials.json` は C のまま |

3. **手順書。** 手順書の枠（`<!-- new: -->`・`<!-- add: -->`）を作業用の道具（スクラッチの JavaScript）で上から順に空のフォルダへ当て、手順ごとに `package.json` が JSON として読めること・`extension.js` が JavaScript の文法として通ることを見た。最後に、4つのファイル（`package.json`・`accounts.svg`・`install-claude-accounts.ps1`・`extension.js`）が今のファイルと一字一句同じになり、全文の枠とも同じだった（枠 41 個、食い違い 0）。
4. **画面での確かめ。** 動いている VSCode の再読み込みは、使っている会話を止めてしまうので、ユーザーに頼んだ。

## 2026-11-19 「保存した鍵が無効」が消えないのを直す

「保存した鍵が無効から更新できない」という知らせで直した。画像は付けていない。直す前と直した後の比較は、一覧に出る文で載せる。画面は VSCode のサイドバーで、撮るには動いている VSCode を前に出す必要があるため。

### 1. 現状の問題

- 一覧に「保存した鍵が無効（ログインし直して、保存し直す）」と一度出ると、そのまま変わらなかった。
- そのとき、保存してある鍵を1つずつ API に送ると、次のようになった。

| アカウント | API の返事 |
|---|---|
| 使用中（保存なし） | 200（取れた） |
| 保存した1つ目 | 200（取れた） |
| 「無効」と出ていた保存 | 429「Rate limited. Please try again later.」 |

- 429 は「混んでいるので後で」の返事で、鍵が無効かどうかは、この返事からはわからない（あとで同じ鍵を送ると 401 だったので、この保存は本当に無効だった）。
- 名前とアカウントの食い違いもあった。「claudehirota@gmail.com」という名前の保存の中身が、別のアカウント（claudehirota2）だった。使用中の claudehirota@gmail.com は保存されていなかった。ユーザーはその保存を消し、使用中のアカウントを保存し直した。

### 2. ソースコードの問題箇所

[extension.js](../../../../.claude/extensions/claude-accounts/extension.js) の `updateUsage` は、取れたときだけ値を新しくしていた。

```js
      const fetched = await fetchUsage(isCurrent ? readJson(CREDENTIALS_PATH) : p.credentials);
      if (fetched) usage[p.oauthAccount.accountUuid] = fetched;
```

- `fetchUsage` は、401 のときだけ `{ invalid: true }` を返し、429 や鍵の期限切れのときは `null` を返す。`null` のときは前の値をそのまま残す。
- 前の値が「無効」だと、そのあと取れない間はずっと「無効」と出る。鍵が使えるようになっていても、表示は変わらない。
- 保存のボタン（`onSave`）は、保存したあと読み直すだけで、前に取った値を消していなかった。新しい鍵で取り直すときに 429 が返ると、前の鍵の「無効」が残る。

### 3. 直し方

1. 401 ではない理由で取れなかったときは、前の値が「無効」なら「取れなかった」に替える。「無効」は、401 が返ったそのときだけの印にする。前の値が使用量なら、前と同じく残す（古い値だと書いた行が付く）。
2. 保存のボタンで保存したら、そのアカウントの前の使用量を消してから読み直す。切り替える前の保存し直し（`onSwitch`）では消さない。そのときの今のアカウントは、もともと `.credentials.json` の鍵で取っているので、「無効」が残ることはない。

### 4. ソースコードの直し

```diff
       const fetched = await fetchUsage(isCurrent ? readJson(CREDENTIALS_PATH) : p.credentials);
       if (fetched) usage[p.oauthAccount.accountUuid] = fetched;
+      // 401 のほかの理由（429 の混雑・鍵の期限切れなど）で取れなかったときは、前の「無効」の印を残さない
+      else if (usage[p.oauthAccount.accountUuid]?.invalid) usage[p.oauthAccount.accountUuid] = { failed: true, fetchedAt: Date.now() };
```

```diff
+// 保存し直したアカウントの、前に取った使用量を消す（新しい鍵で取り直すため）。
+async function forgetUsage(accountUuid) {
+  const usage = state.get('usage', {});
+  delete usage[accountUuid];
+  await state.update('usage', usage);
+}
```

```diff
   if (usage.invalid) return [new vscode.TreeItem('保存した鍵が無効（ログインし直して、保存し直す）')];
+  if (usage.failed) return [new vscode.TreeItem('使用量: 取れなかった（混んでいる・鍵の期限切れなど。5分ごとに取り直す）')];
```

```diff
   saveCurrent(name);
+  await forgetUsage(account.accountUuid);
   provider.refresh();
```

一覧に出る文の比較:

| 起きたこと | 直す前 | 直した後 |
|---|---|---|
| 401 のあと 429 | 保存した鍵が無効 | 使用量: 取れなかった（混んでいる・鍵の期限切れなど。5分ごとに取り直す） |
| そのあとまた 401 | 保存した鍵が無効 | 保存した鍵が無効 |
| 「無効」のアカウントにログインし直して保存したが、API は 429 | 保存した鍵が無効 | 使用量: まだ取れていない |
| そのあと取れた | 5時間・週の2行 | 5時間・週の2行 |

### 5. どう確かめたか

1. **直した動き。** 前の項と同じく、使い捨てのフォルダを `USERPROFILE` にし、`vscode` と `fetch` を差し替えて `extension.js` を動かした。返事の番号を 401 → 429 → 401 と変え、そのあと新しい鍵にして保存した。一覧に出る文は、上の比較の表の「直した後」のとおりになった。
2. **前の試験（並べ替え・使用量・5分の間隔・古い値）。** 前の項と同じ結果だった。
3. **手順書。** 手順8に 8-14・8-15 を足し、8-5・8-8 に直しの行を足した。前の項と同じ道具で枠を当て、4つのファイルが今のファイルと一字一句同じになった（枠 64 個、食い違い 0）。
4. **画面での確かめ。** 動いている VSCode の拡張機能ホストの起動し直しは会話を止めるので、ユーザーに頼んだ。

## 2026-11-19 Claude Code のようなバーの表示にし、会話のたびに使用量を聞き直す

「アクティビティバーの Claude Code みたいな表にしてほしい」「5時間の残りと週の残りが逆になっていると思う。データが合っているか確かめて」「逐一残りの％を更新して」という頼みで作り直した。

### データが合っているかの確かめ

5時間と週は逆になっていなかった。使用中のアカウント（claudehirota）の鍵で API を1回呼び、返事の中身をそのまま見た（16:22）。

| 返事の項目 | 値 | 前の一覧の表示 |
|---|---|---|
| `five_hour.utilization`・`resets_at` | 11.0・08:10（UTC。日本の 17:10） | 5時間: 残り 89%・17:10 に復活 |
| `seven_day.utilization`・`resets_at` | 93.0・22:00（UTC。日本の翌日 07:00） | 週: 残り 7%・11/20(金) 07:00 に復活 |
| `limits`（同じ返事の別の項目） | `session` 11%・`weekly_all` 93%（`severity: critical`） | — |

- `five_hour` を5時間、`seven_day` を週として出していて、取り違えはなかった。同じ返事の `limits` も、`session` が 11%、`weekly_all` が 93% で同じだった。週の枠を 93% 使っているので、週の残りが 7% と少なく出ていた。
- 前の表示は「残り」だけを出していた。Claude Code の `/usage` は「〇% used（使った割合）」を出すので、並べて見ると逆に見える。今回、バーと「〇% 使用」は使った割合（`/usage` と同じ向き）、右の大きな数字は「残り 〇%」にして、両方を出すようにした。
- 作り直した拡張機能を本物のアカウントで、ファイルを書き換えずに動かした。claudehirota は「5時間の枠 残り 83%（17% 使用・17:10 に復活）」「週の枠 残り 7%（93% 使用・11/20(金) 07:00 に復活）」、hirotaryuki126 は「残り 77%（23% 使用）」「残り 51%（49% 使用・11/23(月) 20:01 に復活）」と出た。claudehirota の 5時間の枠が 11% → 17% に増えたのは、この作業の間に使ったため。

### 何を変えたか

- **一覧を Webview にした。** VSCode の決まった形の一覧（`TreeView`）では、バー・色付きの数字・ボタンの並びを描けないため。アカウントごとに枠を描き、5時間の枠と週の枠をバーで出す。描くのは `media/view.js`、見た目は `media/view.css`。`extension.js` はファイル・API・切り替えを受け持ち、中身を `postMessage` で送る。
- **ボタンを枠の中に移した。** 切り替えは枠の「このアカウントに切り替える」、↑↓✕ は枠の右上。行の右クリックのメニュー用のコマンド（上へ・下へ・消す・切り替え）は、要らなくなったので `package.json` から外した。見出しの「+」と回る矢印は残した（回る矢印は「使用量を聞き直す」）。
- **保存していないアカウントで使っているときは、欄の一番上に保存のボタンを出す。** 前の項で、使用中のアカウントが保存されていないのに気づけなかったため。
- **会話のたびに聞き直す。** `~/.claude/projects` の下（Claude Code が会話を書く所）を `fs.watch` で見張り、5秒静かになったら使用中のアカウントを聞く。ただし前に聞いてから30秒は空ける。1分ごとにも聞く（ほかのアカウントは5分ごと）。欄が見えていないときは聞かない。
- **429 のときは2分待つ。** 前の項で 429 を見たので、聞く回数を増やすにあたり、断られたらそのアカウントは2分聞かない。
- **取れなかった理由を、毎回入れ替える形にした。** 前の項の直し（「無効」のあと取れなければ「取れなかった」に替える）を、理由（`status`）を毎回入れ替える形にまとめた。
- **手順書を作り直した。** 手順3〜8 を、Webview で作る形に書き直した。あとの手順で行を足すだけで済むように、`viewData` は `profiles` に読んでから `sortByOrder(profiles)` を1行で足す形、`view.js` の枠は `append` で足していく形にした。`package.json` のコマンドは、聞き直し（手順8）を保存（手順4）の前に置き、`navigation@1`・`@2` で見出しのボタンの順を決めた（あとから足す行のあとに `,` のない行が来るようにして、途中でも JSON として正しくするため）。

### どう確かめたか

1. **画面を作る側と描く側。** 使い捨てのフォルダを `USERPROFILE` にし、`vscode`（Webview を含む）・`fetch`・ページの要素（DOM）を差し替えた試験のスクリプトから、`extension.js` と `view.js` を一緒に動かした。

| 3つ保存（使用中のA・鍵が期限内のB・期限切れのC）して欄を開く | A・B だけ API を呼んだ。A は「残り 89%」（11% 使用、バーは色なし）、B は「残り 25%」（黄）、週は「残り 7%」（赤）。C は「鍵の期限切れで聞けない」 |

| B だけ 429 を返す | B の枠に前の値と「混んでいて取れなかった」。続けて聞き直しのボタンを押しても B は呼ばない |
| B に切り替え | `~/.claude.json` の `oauthAccount` が B になり、ほかの設定は残った |
