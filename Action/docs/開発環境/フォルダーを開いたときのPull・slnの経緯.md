## 2026-11-09 フォルダーを開いたら、Pull と sln を開くところまで自動でする

### したこと

ユーザーから「このフォルダを VSCode で開いたら、sln を開いて最新版の Pull まで全部やってほしい」と頼まれた。それまでは、開くたびに Claude に「全てPullして」と頼み、Game.sln は手で開いていた。

- `.claude/scripts/pull-and-open-sln.ps1` を足し、`.vscode/tasks.json` に `runOn: folderOpen` のタスク「Pull して sln を開く」を足した。
- 「全て Pull」は、そのとき Claude が手でしたことと同じにした: `git fetch --all --prune`、遅れているブランチを早送り、リモートにしかないブランチをローカルにも作る。

### 決めたこと

- **Pull してから sln を開く。** 古いファイルを Visual Studio が読んだあとで書き換わらないようにするため。
- **ブランチは切り替えない・早送りだけ。** 同じフォルダーをほかの Claude が使っているかもしれないため（CLAUDE.md の #94 の決まり）。分かれているブランチを勝手にマージすると、衝突したときにフォルダーが途中の状態で残る。
- **作業ブランチに main を取り込むことはしない。** 取り込むかどうかは作業ごとに決めることなので、自動ではしない。
- **ターミナルは前に出さず、閉じずに残す。** 開くたびにパネルが出ると邪魔なので出さない。分かれているブランチなどを後から見られるように残す。

### どう確かめたか

- このリポジトリで `-NoOpen` を付けて動かし、「どのブランチも最新でした。」と出て、何も変わらないことを見た。
- 作業用フォルダーに小さなリポジトリ（bare のリモート・ローカル・worktree）を作り、リモートを1コミット進めてから動かした。
  - 開いているブランチ（変更中のファイルあり・ぶつからない）、ほかの worktree のブランチ、どこでも開いていないブランチが、どれも追いついた
  - ローカルにもコミットがあるブランチは `[ahead 1, behind 1]` と出て、そのままだった
  - リモートにしかないブランチ2本が、ローカルにも作られた
- Visual Studio を開く部分は、ユーザーの画面に窓を出すことになるので、Claude は動かしていない。次にフォルダーを開いたときに、ユーザーに見てもらう。
