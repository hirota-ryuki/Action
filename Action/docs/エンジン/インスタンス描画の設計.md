# インスタンス描画の設計

作成日: 2026-11-08
対象: [ModelRender.h](../../k2Engine/graphics/ModelRender.h)、[ModelRender.cpp](../../k2Engine/graphics/ModelRender.cpp) のインスタンス描画、[ModelVSCommon.h](../../Game/Assets/shader/ModelVSCommon.h) の `VSMainInstancing`
経緯: [ステージの経緯](../ゲーム/ステージ/ステージの経緯.md)（2026-11-08 の「つまずいたこと」の 3）、[ステージの軽量化の経緯](../ゲーム/ステージ/ステージの軽量化の経緯.md)（行列で渡す・幾何学データの更新を減らす）

同じモデルをたくさん置くときに、まとめて描くための仕組みのページです。ステージの草・岩・木（[ステージの設計](../ゲーム/ステージ/ステージの設計.md)）で使っています。

- **アニメーションのないモデルは GPU インスタンシングで描く。** 頂点はモデルのまま、頂点シェーダーでインスタンスごとのワールド行列を掛ける。
- **描くのは、そのフレームに `UpdateInstancingData()` で渡した数だけ。** 渡さなかった物は描かれない。
- **画面の外の物を飛ばす処理（カリング）はしない。** 呼ぶ側で、描く物だけを渡す。

---

## 1. 全体像

| 種類 | 頂点の作り方 | 1回の描画で描く数 |
|---|---|---|
| 普通のモデル（`maxInstance` が 1） | 計算シェーダーで頂点を事前計算する（スキンもここで計算） | 1 |
| アニメーションありのインスタンス描画 | 全インスタンス分の頂点を事前計算し、大きな頂点バッファにまとめる | 1（まとめたものを1回） |
| **アニメーションなしのインスタンス描画** | **事前計算しない。モデルの頂点のまま** | **渡した数** |

`ModelRender::Init()` に `maxInstance` を 2 以上、アニメーションクリップを `nullptr` で渡すと、3つ目になる（`m_isGpuInstancing`）。

## 2. 実装方法

### 初期化

`InitComputeAnimatoinVertexBuffer()` の頭で決める。`InitAnimation()` のあとに呼ばれるので、ここでアニメーションの有無がわかっている。

```cpp
m_isGpuInstancing = m_isEnableInstancingDraw && m_animationClips == nullptr;
if (m_isGpuInstancing) {
    return;  // 頂点の事前計算は作らない
}
```

G バッファ・ZPrepass・シャドウマップ・半透明の各モデルを作るところで、`SetupGpuInstancing()` が設定を書き換える。

```cpp
modelInitData.m_computedAnimationVertexBuffer = nullptr;   // モデルの頂点バッファで描く
modelInitData.m_vsEntryPointFunc = "VSMainInstancing";     // g_worldMatrixArray[SV_InstanceID] を掛ける
```

ワールド行列の配列（`m_worldMatrixArraySB`）は、もとから拡張 SRV の 0 番（`t10`）に渡していて、シェーダーの `g_worldMatrixArray` がそれを読む。

### 毎フレーム

1. 呼ぶ側が `UpdateInstancingData(番号, 位置, 回転, 拡大)` か `UpdateInstancingData(番号, 行列)` を、番号 0 から詰めて呼ぶ。1回ごとに `m_numInstance` が 1 増える。
   - 位置・回転・拡大で渡すと、中で `CalcWorldMatrix()` を呼んで行列にしてから、行列の方に渡す。
   - 動かない物は、`CalcWorldMatrix()` で行列を最初に作っておき、行列の方で渡すと、毎フレームの行列の計算がなくなる。
2. `Draw()` で行列の配列を GPU に送り、`m_numDrawInstance = m_numInstance` として覚えてから `m_numInstance` を 0 に戻す。
3. 描画パスの `OnRenderToGBuffer()` などは `GetDrawInstanceCount()`（GPU インスタンシングなら `m_numDrawInstance`、それ以外は 1）を描く数として渡す。0 なら何も描かない。

### 幾何学データの更新

エンジンは番号ごとに「幾何学データ」（ワールド座標の箱。影の範囲を決めるのに使う）を持ち、`SceneGeometryData::Update` で毎フレーム更新する。番号は最大数ぶんあるので、草のように数千置くと、描かない番号の更新で CPU が重くなる。そこで `GemometryData::Update()` の頭で `ModelRender::IsGeometryDataActive(番号)` を見て、要らない番号はすぐ戻る。

```cpp
bool IsGeometryDataActive(int instanceId) const
{
    if (!m_isGpuInstancing) return true;     // GPU インスタンシング以外は、いつも更新
    if (!m_isShadowCaster) return false;     // 影を落とさない物は、箱を使わない
    return instanceId < (std::max)(m_numInstance, m_numDrawInstance);  // このフレームに渡した番号だけ
}
```

## 3. 使い方

```cpp
// 初期化：最大数を 2 以上にする（1 だとインスタンス描画にならない）
m_modelRender.Init("Assets/modelData/xxx.fbx", nullptr, 0, enModelUpAxisZ, true, maxInstance);

// 毎フレーム（Update）：描く物だけを 0 番から詰めて渡す
int n = 0;
for (auto& item : items) {
    if (見えない) continue;
    m_modelRender.UpdateInstancingData(n++, item.position, item.rotation, item.scale);
}

// 描画（Render）
if (n > 0) m_modelRender.Draw(rc);
```

- 動かない物を毎フレーム渡すときは、`CalcWorldMatrix()` で作った行列を覚えておき、`UpdateInstancingData(番号, 行列)` で渡す（例: [ステージの部品の描き方の設計](../ゲーム/ステージ/ステージの部品の描き方の設計.md)）。
- `Update()` は呼ばなくてよい（インスタンス描画のときは何もしない）。
- 1つも渡さないフレームは `Draw()` を呼ばない。

## 4. 決めたこと

- もとの「全インスタンス分を事前計算する」作りは、アニメーションありのインスタンス描画のために残した（今は使っている所がない）。
- カリングはエンジンに入れず、呼ぶ側に任せた。物の並び方（区画など）は使う側の方がよく知っているため。

## 5. 既知の課題

- アニメーションありのインスタンス描画は、今も全インスタンスを毎フレーム事前計算し、描く数の指定もない。使うときに見直す。
- `RemoveInstance()` は行列を 0 にするだけなので、GPU インスタンシングでは「番号を詰めて渡す」使い方をする。
