# フレームレートの手順

作成日: 2026-11-08
設計: [フレームレートの設計](フレームレートの設計.md)
経緯: [フレームレートの経緯](フレームレートの経緯.md)

FPS の上限（60）と VSync の待ちを外し、FPS が上がってもゲームの動きが速くならないようにするまでの手順です。上から順にやると、[フレームレートの設計](フレームレートの設計.md) の形になります。

**出来上がるもの:** ゲームが GPU・CPU の出せるだけの FPS で動きます。エフェクト・物理・カメラの右スティックは、FPS が変わっても同じ速さで動きます。

**前提:**

- Visual Studio 2022 で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 始める前は、エンジンにもとからある形（FPS の上限 60、VSync を待つ）になっている。
- 手順3は、炎のエフェクト（`FireEffect`）があるときだけ行う。[炎魔法の手順](../ゲーム/魔法/炎魔法の手順.md) を先に済ませておく。
- [README の「ゲームを作る順番」](../README.md#ゲームを作る順番) のゲームの手順書で `FireEffect`・`GameCamera` を作った場合は、手順3・5の形（経過時間で数える）がもう入っているので、手順3・5は飛ばす。
- 内蔵の GPU で描いていると、上限を外しても 30fps 前後しか出ないことがある。そのときは [GPUの選び方の手順](GPUの選び方の手順.md) もやる。
- 作業を始める前に、main からブランチを切る。

| 手順 | 足すもの | 確かめ方 |
|---|---|---|
| 1 | FPS の上限と VSync の待ちを外す | FPS が 60 より上に出る |
| 2 | エフェクトを経過時間で進める | エフェクトの速さが FPS で変わらない |
| 3 | 炎のエフェクトを重ねる間隔を、同じ数え方にする | 炎が途切れずに出続ける |
| 4 | 物理を経過時間で進める | 物理で動く物の速さが FPS で変わらない |
| 5 | カメラの右スティックを経過時間で回す | 右スティックで回る速さが FPS で変わらない |

## 手順1: FPS の上限と VSync の待ちを外す

FPS を出せるだけ出すために、60FPS に抑える待ちと、モニターの更新を待つ VSync の2つを外します。どちらもマクロ `USE_FPS_LIMITTER` 1つで切り替わるようになっているので、マクロを外すだけで済みます。

**この手順で触るファイル:**

| ファイル | 何をするか |
|---|---|
| [k2EngineLowPreCompile.h](../../k2EngineLow/k2EngineLowPreCompile.h) | コメントアウト（`#define USE_FPS_LIMITTER` の1行） |

### 1-1. マクロをコメントアウトする

[k2EngineLowPreCompile.h](../../k2EngineLow/k2EngineLowPreCompile.h) の `using namespace Microsoft::WRL;` の下にある `#define USE_FPS_LIMITTER` を**コメントアウト**し、行の終わりのコメントに「（無効にしてFPS無制限）」と足します。`MAX_FPS` の行は残します（上限を戻すときに使うため）。

```diff
 using namespace Microsoft::WRL;
 
-#define USE_FPS_LIMITTER		// 有効でFPSに上限を設ける。
+//#define USE_FPS_LIMITTER		// 有効でFPSに上限を設ける。（無効にしてFPS無制限）
 static const int MAX_FPS = 60;	// 最大FPS。USE_FPS_LIMITTERが有効なときに使用される。
 #define ENABLE_DXR_ON_RTX_ONLY	// 有効でDXRはRTXシリーズのみ有効。
```

### 1-2. マクロで切り替わる所（もとからある・変えない）

マクロを外すと、次の2か所が変わります。どちらもエンジンにもとからある分岐なので、**ファイルは変えません。**

[GraphicsEngine.cpp](../../k2EngineLow/graphics/GraphicsEngine.cpp) の `GraphicsEngine::EndRender()`。`Present()` に渡す数が `1`（VSync を待つ）から `0`（待たない）になります。

```cpp
#ifdef USE_FPS_LIMITTER
			m_frameBuffer.Present(1);
#else
			m_frameBuffer.Present(0);   // ← マクロを外すと、こちらが使われる
#endif
```

[k2EngineLow.cpp](../../k2EngineLow/k2EngineLow.cpp) の `K2EngineLow::EndFrame()`。60FPS になるまで待つ `m_fpsLimitter.Wait()` が呼ばれなくなります。

```cpp
		m_graphicsEngine->EndRender();
#ifdef USE_FPS_LIMITTER
		m_fpsLimitter.Wait();       // ← マクロを外すと、ここは呼ばれない
#endif
		m_gameTime.EndMeasurement();
```

片方だけ外しても FPS は上がりません（VSync を外しても 60 で待ち、待ちを外しても VSync で待つ）。マクロ1つで両方が外れるようになっています。

**確かめ方:**

- `k2EngineLowPreCompile.h` はプリコンパイル済みヘッダーなので、k2EngineLow 全体がビルドし直される。ソリューションのビルドが通る。
- ゲームを起動すると、右上の FPS（[FPSの表示の手順](../ゲーム/UI/FPSの表示の手順.md) で出すもの）が 60 より上になる。
- この時点では、エフェクト・物理・カメラの右スティックが FPS に合わせて速くなる。次の手順から直す。

## 手順2: エフェクトを経過時間で進める

エフェクト（Effekseer）は、`Update()` を1回呼ぶと1フレーム（1/60秒）進むので、FPS が上がると速く再生されます。経過時間をエフェクトのフレーム数に直して渡します。

**この手順で触るファイル:**

| ファイル | 何をするか |
|---|---|
| [EffectEngine.h](../../k2EngineLow/graphics/effect/EffectEngine.h) | 追加（定数 `FRAMES_PER_SECOND`） |
| [EffectEngine.cpp](../../k2EngineLow/graphics/effect/EffectEngine.cpp) | 書き換え（`EffectEngine::Update()` の `m_manager->Update();` の1行） |

### 2-1. 1秒あたりのフレーム数を決める

[EffectEngine.h](../../k2EngineLow/graphics/effect/EffectEngine.h) の `public:` のすぐ下（`CreateInstance()` の上）に**追加**します。エフェクトの時間はこの数で数えるので、ゲームからも使えるように `public` に置きます。

```diff
 	public:
+		/// <summary>
+		/// エフェクト（Effekseer）の1秒あたりのフレーム数。エフェクトの時間は、このフレームで数える。
+		/// </summary>
+		static constexpr float FRAMES_PER_SECOND = 60.0f;
 		/// <summary>
 		/// インスタンスの作成。
 		/// </summary>
```

### 2-2. 経過時間を渡す

[EffectEngine.cpp](../../k2EngineLow/graphics/effect/EffectEngine.cpp) の `EffectEngine::Update(float deltaTime)` で、`m_manager->Update();` を**書き換え**ます。引数を渡さないと1フレームずつ進むので、経過時間（秒）× 60 を渡します。

```diff
 		m_renderer[backBufferNo]->SetCommandList(m_commandList[backBufferNo]);
 
-		m_manager->Update();
+		// 経過時間をエフェクトのフレームに直して進める（FPS が変わっても、エフェクトの速さは変わらない）。
+		m_manager->Update(deltaTime * FRAMES_PER_SECOND);
 
 		//レンダラーにカメラ行列を設定。
```

`deltaTime` は、[k2EngineLow.cpp](../../k2EngineLow/k2EngineLow.cpp) の `K2EngineLow::ExecuteUpdate()` から `EffectEngine::GetInstance()->Update(g_gameTime->GetFrameDeltaTime());` で渡されています（もとからある・変えない）。

**確かめ方:** ソリューションのビルドが通る。エフェクトを出すと、上限を外す前と同じ速さで再生される。

## 手順3: 炎のエフェクトを重ねる間隔を、同じ数え方にする

`FireEffect` は、エフェクトが終わる前に次を重ねて再生し、炎が途切れないようにしています。その間隔を「ゲームのフレームの回数」で数えていたので、手順2のあとは FPS が上がると間隔が短くなりすぎます。手順2と同じ「経過時間 × 60」で数えます。

**この手順で触るファイル:**

| ファイル | 何をするか |
|---|---|
| [FireEffect.h](../../Game/Source/Objects/FireEffect.h) | 書き換え（`m_framesSinceLastPlay` の型を `int` から `float` に） |
| [FireEffect.cpp](../../Game/Source/Objects/FireEffect.cpp) | 書き換え（`FireEffect::Update()` の `m_framesSinceLastPlay++;` の1行） |

### 3-1. 数える変数を小数にする

経過時間 × 60 は小数になるので、[FireEffect.h](../../Game/Source/Objects/FireEffect.h) のメンバー変数を**書き換え**ます。

```diff
 	int m_replayIntervalFrames = 0;   // 次の再生を重ねるまでのフレーム数。0以下なら重ねない（元エフェクトが無限ループ）。
-	int m_framesSinceLastPlay = 0;
+	float m_framesSinceLastPlay = 0.0f;  // 前の再生からの経過時間（エフェクトのフレーム数）。
 	bool m_isValid = false;           // エフェクトを読み込めたか。
```

### 3-2. 経過時間で数える

[FireEffect.cpp](../../Game/Source/Objects/FireEffect.cpp) の `FireEffect::Update()` で、`m_framesSinceLastPlay++;` とその上のコメントを**書き換え**ます。

```diff
-	// EffectEngine は1ゲームフレームにつき1フレーム進めるので、こちらもフレームで数える。
-	m_framesSinceLastPlay++;
+	// エフェクトは経過時間をエフェクトのフレーム（1秒に EffectEngine::FRAMES_PER_SECOND）に直して進むので、こちらも同じ数え方にする。
+	m_framesSinceLastPlay += g_gameTime->GetFrameDeltaTime() * EffectEngine::FRAMES_PER_SECOND;
 	const bool isIntervalElapsed = m_replayIntervalFrames > 0 && m_framesSinceLastPlay >= m_replayIntervalFrames;
```

`m_framesSinceLastPlay = 0` に戻している `PlayNext()` はそのまま使えます（`float` に `0` を入れても同じ）。

**確かめ方:** ソリューションのビルドが通る。炎魔法を撃って床が燃えるとき、炎が途切れずに出続ける。

## 手順4: 物理を経過時間で進める

物理エンジン（Bullet）には、毎フレーム 1/60秒と決め打ちで渡していたので、FPS が上がると物理で動く物が速くなります。実際の経過時間を渡します。Bullet の中で 1/60秒ずつに分けて進めるので、細かく割る処理は要りません。

**この手順で触るファイル:**

| ファイル | 何をするか |
|---|---|
| [Gameobjectmanager.cpp](../../k2EngineLow/gameObject/Gameobjectmanager.cpp) | 書き換え（`GameObjectManager::ExecuteUpdate()` の最後の1行） |

[Gameobjectmanager.cpp](../../k2EngineLow/gameObject/Gameobjectmanager.cpp) の `GameObjectManager::ExecuteUpdate()` の最後（全部のゲームオブジェクトの `UpdateWrapper()` のあと）を**書き換え**ます。

```diff
 		//物理エンジンのアップデートを呼び出す。
-		PhysicsWorld::GetInstance()->Update(1.0f / 60.0f);
+		// 実際の経過時間を渡す（物理エンジンの中で 1/60秒ずつに分けて進める）。
+		PhysicsWorld::GetInstance()->Update(g_gameTime->GetFrameDeltaTime());
 	}
```

**確かめ方:** ソリューションのビルドが通る。物理で動く物（落ちる・転がる物）が、上限を外す前と同じ速さで動く。

## 手順5: カメラの右スティックを経過時間で回す

右スティックでのカメラの回転は「1フレームに 2度」だったので、FPS が上がると速く回ります。「1秒に 120度」にして、経過時間を掛けます（60FPS のときの 2度 × 60 = 120度）。マウスは動いた量で回すので、変えません。

**この手順で触るファイル:**

| ファイル | 何をするか |
|---|---|
| [GameCamera.cpp](../../Game/Source/Objects/GameCamera.cpp) | 書き換え（定数 `CAMERA_ROTATE_SPEED` を `CAMERA_ROTATE_SPEED_DEG_PER_SEC` に、`GetCameraRotationInput()` の2行） |

### 5-1. 回る速さを「1秒あたり」にする

[GameCamera.cpp](../../Game/Source/Objects/GameCamera.cpp) の先頭の無名の `namespace` にある定数を**書き換え**ます。名前も、単位がわかるように変えます。

```diff
 namespace
 {
-	constexpr float CAMERA_ROTATE_SPEED = 2.0f;
+	// 右スティックを倒し切ったときの回転の速さ（度/秒）。経過時間を掛けて、FPS によらず同じ速さにする。
+	constexpr float CAMERA_ROTATE_SPEED_DEG_PER_SEC = 120.0f;
 	// マウスの感度。大きいほど少ない移動量で大きく回転する。
```

### 5-2. 経過時間を掛ける

同じファイルの `GameCamera::GetCameraRotationInput()` の先頭2行を**書き換え**ます。定数の名前を変えたので、ここを直さないとビルドが通りません。

```diff
 void GameCamera::GetCameraRotationInput(float& yawDeg, float& pitchDeg)
 {
-	yawDeg = CAMERA_ROTATE_SPEED * g_pad[0]->GetRStickXF();
-	pitchDeg = CAMERA_ROTATE_SPEED * g_pad[0]->GetRStickYF();
+	const float rotateDeg = CAMERA_ROTATE_SPEED_DEG_PER_SEC * g_gameTime->GetFrameDeltaTime();
+	yawDeg = rotateDeg * g_pad[0]->GetRStickXF();
+	pitchDeg = rotateDeg * g_pad[0]->GetRStickYF();
 
 	float mouseYawDeg = 0.0f;
```

その下のマウスの処理（`TryGetMouseRotationInput()`）は、もとからある（変えない）。

**確かめ方（これで出来上がり）:**

- ソリューションのビルドが通る。
- 右スティックを倒し切ると、カメラが1秒に約 120度回る。FPS が変わっても回る速さは変わらない。

## 上限を戻すとき

手順1の `//#define USE_FPS_LIMITTER` のコメントを外すだけで、60FPS の上限と VSync の待ちが戻ります。手順2〜5は経過時間で動くので、戻したあとも同じ速さのまま使えます。
