# アニメーションの上半身の層の設計

経緯: [アニメーションの上半身の層の経緯](アニメーションの上半身の層の経緯.md)
手順: [アニメーションの上半身の層の手順](アニメーションの上半身の層の手順.md)

作成日: 2026-11-19
対象: `k2EngineLow` の `Animation`・`k2Engine` の `ModelRender`（#193 で足したもの）

下のアニメーション（歩きなど）を流したまま、上半身だけ別のアニメーションを重ねる仕組みです。三人称の溜め撃ちで、脚は歩きのまま、上半身だけ Attack1 で構えるのに使っています（[三人称の溜め撃ちの設計](../../ゲーム/プレイヤー/三人称の溜め撃ち/三人称の溜め撃ちの設計.md)）。一人称の腕では、左腕・右腕に1枚ずつ使い、氷を撃つ腕だけを構えの上に重ねています（[一人称の腕の設計](../../ゲーム/プレイヤー/一人称の腕/一人称の腕の設計.md)）。

- 層は、もう1つの `Animation`。骨ごとの重み（0〜1）を持たせると層になり、スケルトンに書き込まずに、下の姿勢の上に重ねる。
- 重ねるときは、骨ごとに「親から見た形」にして混ぜ、親から順に組み直す。下で腰が動けば、重ねた胸・腕も腰に付いていく。
- 使う側は `ModelRender` に骨の名前と重みを渡すだけ。重ねる強さと再生の速さは、下のアニメーションとは別に変えられる。
- 層は2枚（`MAX_ANIMATION_LAYER`）まで作れ、番号の小さい順に重ねる。

**用語:**

| 用語 | 何のことか |
|---|---|
| 層 | 下のアニメーションの姿勢の上に、骨ごとの重みで重ねるアニメーション |
| 根元から見た行列 | モデルの根元の骨（ルート）から見た、骨の位置・向き・大きさ。アニメーションを流すと、エンジンは骨の行列をこの形で持つ |
| 親から見た行列 | 親の骨から見た、骨の位置・向き・大きさ |

---

## 1. 全体像

| クラス | 役割 |
|---|---|
| `ModelRender`（[ModelRender.h](../../../k2Engine/graphics/ModelRender.h)） | 下のアニメーション `m_animation` と、層 `m_layerAnimation[MAX_ANIMATION_LAYER]` を持つ。骨の名前から骨ごとの重みを作って層に渡し、毎フレーム下 → 層0 → 層1 の順に進める |
| `Animation`（[Animation.h](../../../k2EngineLow/graphics/Animation.h)） | 骨ごとの重みがあれば層として動く。姿勢を作るところ（クリップ同士の補間）は、層でないときと同じ |

1フレームの流れ（`ModelRender::Update()`）:

1. `m_animation.Progress()`: 下のアニメーションが、全部の骨の姿勢をスケルトンに書く（もとからある）。
2. 層ごとに（番号の小さい順に）、作ってあり、全体の重みが 0 より大きければ、`m_layerAnimation[layerNo].Progress()`。前の層が重ねたあとの姿勢の上に重なる。
   1. 層のクリップから、骨ごとの拡大・回転・平行移動を作る（`UpdateGlobalPose()` の前半。もとからある）。
   2. 層なので、スケルトンへそのまま書かず、`ApplyAsLayer()` で下の姿勢に重ねる。

---

## 2. 重ね方

`ApplyAsLayer()` は、骨を親から順に（`m_layerBoneOrder`）たどり、骨ごとに次をします。

1. 下の姿勢（スケルトンに書いてある、根元から見た行列）を、親から見た形にする。
2. 重み = 骨ごとの重み × 全体の重み が 0 より大きければ、層の姿勢も親から見た形にして、拡大・回転・平行移動に分けて混ぜる（拡大と平行移動は `Lerp`、回転は `Slerp`）。
3. 混ぜた「親から見た形」に、混ぜ終わった親（根元から見た形）を掛けて、根元から見た形に戻し、スケルトンに書く。

重みが 0 の骨（脚など）も 1〜3 を通ります。混ぜないので下の姿勢のままですが、3 で親を組み直した結果の上に乗るので、親（背骨など）が層で動けば一緒に動きます。

---

## 3. 実装方法

### Animation: 重みがあれば層

```cpp
std::vector<float> m_layerBoneWeights;  // 層のときの、骨ごとの重み。空なら層ではない。
std::vector<int> m_layerBoneOrder;      // 層を重ねるときに骨を計算する順（親が先）。
float m_layerWeight = 0.0f;             // 層の全体の重み。
```

「層か」を別の `bool` で持たず、`IsLayer()` は `!m_layerBoneWeights.empty()` にしました。重みと食い違うことがないためです。骨の順は、重みを渡したとき（`SetLayerBoneWeights()`）に1回だけ作ります。骨ごとに根元までたどり、根元に近い方から並べるので、骨の番号の順が親から順になっていなくても、親が先になります。

`UpdateGlobalPose()` は、書き込む直前に分かれ道を足しただけです。もとからある `for`（全部の骨にそのまま書き込む）は変えていないので、層でない `Animation` の動きは変わりません。

```cpp
if (IsLayer()) {
    ApplyAsLayer(vGlobalScale, qGlobalPose, vGlobalPose);
}
else
//グローバルポーズをスケルトンに反映させていく。
for (int boneNo = 0; boneNo < numBone; boneNo++) {   // もとからある
```

### 親から見た形にしてから混ぜる

```cpp
Matrix mixedLocal = ToParentSpace(baseRoot, boneNo, parentNo);   // 下の姿勢（親から見た形）
if (weight > 0.0f) {
    // 下と層を、それぞれ拡大・回転・平行移動に分けて混ぜる
    ...
}
mixedRoot[boneNo] = parentNo < 0 ? mixedLocal : mixedLocal * mixedRoot[parentNo];
m_skeleton->SetBoneLocalMatrix(boneNo, mixedRoot[boneNo]);
```

根元から見た行列のまま混ぜると、層の胸は「層のクリップで胸があった場所」に残り、下の歩きで腰が上下しても付いてきません。親から見た形（`ToParentSpace()`: 自分 × 親の逆行列）なら「腰に対して胸がどう付いているか」だけを混ぜるので、腰に付いていきます。行列の分け方・組み方（`DecomposeBoneMatrix()`・`ComposeBoneMatrix()`）は、`UpdateGlobalPose()` のクリップ同士の補間と同じ順（拡大 → 回転 → 平行移動）にそろえました。

`Matrix`（k2EngineLow の [Matrix.h](../../../k2EngineLow/math/Matrix.h)）は 4 行 × 4 列の行列で、`Inverse()` は逆行列（変換を打ち消す行列）を作ります。3つの行列の配列は、そのフレームの中だけで使うので、`UpdateGlobalPose()` と同じく `alloca`（C++ の標準ライブラリ。関数を抜けると消えるメモリーを取る）で取ります。

### ModelRender: 骨の名前で重みを決める

`InitAnimationLayer()` は、骨ごとに自分 → 親 → …と根元へたどり、最初に名前が見つかった組の重みを使います（`std::find_if` と `wcscmp`）。子孫に別の組があればそちらが勝つので、「背骨は 0.5、胸から先は 1」のように根元の骨を数個書くだけで、全部の骨の重みが決まります。層の `Animation` は、下と同じスケルトン・同じクリップで `Init` します。

層の再生の速さ `m_layerAnimationSpeed[layerNo]` は、層ごとに、下の `m_animationSpeed` とは別に持ちます。歩きは歩く速さに合わせて再生の速さを変えるので、同じ値を使うと上半身の動きまで速くなったり遅くなったりします。全体の重みが 0 のときは、層を進めません（重ねても何も変わらないため）。

## 4. 使い方

```cpp
ModelRender& modelRender = m_model.GetModelRender();
// 背骨から先に 0.5、胸から先に 1。脚と腰は 0（下のまま）。
modelRender.InitAnimationLayer({ { L"J_Bip_C_Spine", 0.5f }, { L"J_Bip_C_Chest", 1.0f } });

modelRender.PlayLayerAnimationFromTime(clipNo, 0.0f, 0.0f);  // 層のクリップを 0秒から流す
modelRender.SetLayerWeight(weight);         // 0〜1。毎フレーム少しずつ変えて、入れたり抜いたりする
modelRender.SetLayerAnimationSpeed(0.0f);   // 0 でそのコマで止まる。1 で等速

// 2枚目の層を使うときは、どの関数も最後に層の番号を渡す（省くと 0）。
modelRender.InitAnimationLayer({ { L"J_Bip_R_UpperArm", 1.0f } }, 1);
modelRender.SetLayerWeight(weight, 1);
```

- `InitAnimationLayer()` は `InitAnimation()`（クリップを渡す）とスケルトンの読み込みのあとに呼ぶ。クリップの番号は `Init` に渡した並びの番号。
- 重みは 0 から始まるので、`SetLayerWeight()` を呼ぶまでは何も変わらない。

## 5. 決めたこと

| 決めたこと | 理由 |
|---|---|
| 層を別のクラスにせず、`Animation` に重みを持たせる | 姿勢を作る計算（クリップの再生・クリップ同士の補間）を、そのまま使い回せる |
| 混ぜるのは親から見た形 | 根元から見た形で混ぜると、下で腰が動いても上半身が付いてこない |
| 骨ごとの重みは、名前で根元の骨を数個渡す | 骨の番号はモデルごとに違う。全部の骨を書かなくてよい |
| 層の再生の速さを下と別にする | 歩く速さに合わせた再生の速さに、上半身がつられないように（#193 の途中で直した） |
| 層は配列にし、番号は省けるようにする | 一人称の腕で、左腕と右腕を別々に重ねるのに2枚要った。番号を省くと 0 なので、1枚だけ使う所は書き換えなくてよい |

---

## 6. 既知の課題

- 層は2枚まで。もっと要るときは `MAX_ANIMATION_LAYER` と `m_layerAnimationSpeed` の初めの値を増やす。
- [アニメーションの上半身の層の手順](アニメーションの上半身の層の手順.md) は、層が1枚のときのもの。2枚にする変更（変更前と変更後の比較）は、[経緯](アニメーションの上半身の層の経緯.md) の 2026-11-19「層を2枚まで作れるようにした」にある。手順書には、まだ入れていない。
- 層の姿勢は「下の姿勢に、その骨の親から見た形で混ぜる」だけで、足し算（下の動きに層の動きを足す）はできない。
