# アニメーションの再生の設計

経緯: [アニメーションの再生の経緯](アニメーションの再生の経緯.md)
手順: [アニメーションの再生の手順](アニメーションの再生の手順.md)（キーフレームの間を曲線で補間し、切り替えの曲線を足す）

アニメーションクリップ（`.tka`）のキーフレームから、毎フレームのボーンの姿勢を決める仕組みです。

---

## 1. 全体像

| クラス | 役割 |
|---|---|
| `Animation`（[Animation.h](../../k2EngineLow/graphics/Animation.h)） | クリップの切り替えと、クリップ同士の補間（`Play` の `interpolateTime`）。再生中のクリップごとに `AnimationPlayController` を持つ |
| `AnimationPlayController`（[AnimationPlayController.cpp](../../k2EngineLow/graphics/AnimationPlayController.cpp)） | 1つのクリップの再生。時間を進め、今のキーフレームからボーンのローカル行列を作る |

1フレームの流れ（`AnimationPlayController::Update`）:

1. `m_time` に経過時間を足す。
2. `ProgressKeyframeNo`: 今の時間より後で一番近いキーフレームの番号（`m_currentKeyFrameNo`）まで進める。最後まで行ったら、ループなら先頭へ戻り、そうでなければ最後で止まる。
3. `SamplingBoneMatrixFromAnimationClip`: 1つ前のキーフレームと今のキーフレームの間を、前後のキーフレームも通る曲線で補間して、ボーンの行列を作る。
4. 親から順にルートの空間の行列にする。

---

## 2. キーフレームの間の補間

1つ前のキーフレーム（k1）と今のキーフレーム（k2）の間を、さらに1つ前（k0）と1つ後（k3）も通る曲線（Catmull-Rom）で補間します。直線で補間すると、手足がキーフレームを結んだ折れ線の上を動き、キーフレームのところで動きの向きと速さが急に変わります。240fps などで描くと、それが1秒に約30回見えてカクカクします。

- 割合 t = （今の時間 − k1 の時間）÷（k2 の時間 − k1 の時間）。0〜1 に収める。
- 行列を、平行移動・拡大・回転に分けて補間します（`DecomposeBoneMatrix`。クリップ同士の補間の `Animation::UpdateGlobalPose` と同じ分け方）。
  - 平行移動・拡大: x・y・z を、それぞれ Catmull-Rom の曲線にする。
  - 回転: クォータニオンの隣どうしの向き（内積の符号）をそろえてから、4つの成分をそれぞれ曲線にし、正規化する。
- 曲線は、k1・k2 での傾きを k0 → k2、k1 → k3 の向きから作るエルミート曲線（`Hermite` / `CatmullRom`）。キーフレームの間隔が違っても傾きが合うように、間の時間で割り合いを決める。
- k0・k3 がクリップの外になるときは、端のキーフレームそのものを使う。ループのクリップで、最後のキーフレームが最初と同じポーズ（`IsSameBoneMatrix`）なら、反対側から取る（先頭の前は最後から2つ目、最後の次は2つ目）。
- 最初のキーフレーム（前がない）と、時間の間隔が 0 のときは、補間せずにそのまま使います。
- ループのクリップは、最後のキーフレームを越えた分の時間を次の周回へ持ち越します。越えた分を捨てると、つなぎ目で少し止まって見えるためです。

---

## 3. クリップ同士の補間の進み方（2026-11-07）

`Play` / `PlayFromTime` に補間時間を渡すと、前のクリップのポーズから新しいクリップのポーズへ、その時間をかけて移ります（クロスフェード）。前のクリップも補間の間は時間が進み続けます（ループしないクリップは、最後まで行くと最後のポーズで止まる）。

混ぜる割合は `AnimationPlayController::GetInterpolateRate()`（[AnimationPlayController.h](../../k2EngineLow/graphics/AnimationPlayController.h)）が返します。前は経過時間 ÷ 補間時間（線形）でしたが、今は smoothstep（`t² × (3 − 2t)`）にしています。線形だと、補間の始まりと終わりで動きの速さが急に変わり、カクッと見えるためです。どのキャラクターの、どのクリップの切り替えにも効きます。

---

## 4. 決めたこと

| 候補 | 選ばなかった理由 |
|---|---|
| クリップのキーフレームを増やす（60fps・120fps で書き出す） | クリップごとに作り直しが必要で、ファイルも大きくなる。UE もキーフレームの間は直線で補間するので、曲線で間を埋める処理を別に書く必要がある。エンジンで曲線にすれば、今のクリップのままどの fps でもなめらかになる |
| キーフレームの間を直線で補間する（前の形） | キーフレームのところで手足の動きの向きと速さが急に変わり、240fps ではカクカクして見えた |
| クリップ同士の補間の割合を線形のままにする | 補間の始まりと終わりで動きの速さが急に変わる。smoothstep なら、補間時間を変えずになめらかになる |
