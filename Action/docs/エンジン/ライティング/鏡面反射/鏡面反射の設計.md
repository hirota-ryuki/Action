# 鏡面反射の設計

作成日: 2026-11-08
対象: ディファードライティングとフォワード描画（`model.fx`）の鏡面反射（[PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()`）
経緯: [鏡面反射の経緯](鏡面反射の経緯.md)
手順: [鏡面反射の手順](鏡面反射の手順.md)（どのファイルに何を足し、何を書き換えたか）

PBR のライティングで、光が面に当たって照り返すハイライト（鏡面反射・スペキュラ）の計算のページです。ステージもキャラクターも、ディレクションライト・ポイントライト・スポットライトのどれも、この1つの関数で計算します。

- **GGX 分布と Smith の遮蔽を使う、ふつうのクックトランスモデルにする。** 視線が面すれすれでも明るさが跳ね上がらない。
- **正面から見たときの反射率は 4%（金属でない物の値）に固定する。** 金属らしさは、今までどおり `CalcLighting()` で色を付けて出す。
- **粗さには下限（0.3）、明るさには上限（ライトの色まで）を付ける。** 滑らかな物でも、ハイライトが点になったり、逆光で白く飛んだりしないようにする。

**用語:**

| 用語 | 何のことか |
|---|---|
| PBR | Physically Based Rendering。光の反射を、物理の式に近づけて計算する描き方 |
| 鏡面反射（スペキュラ・ハイライト） | 光が面に当たって、見ている向きへ照り返すこと。つやのある所が白く光って見える |
| ポイントライト | 1点から、まわり全体に広がる光 |
| スポットライト | 1点から、円すい形に照らす光（懐中電灯のような光） |
| クックトランスモデル | 鏡面反射を、D項（分布）・F項（フレネル）・G項（遮蔽）の3つの式から計算するモデル |
| D項・F項・G項 | クックトランスモデルの3つの式。D は分布（`D`）、F はフレネル（`F`）、G は遮蔽（`vis` にまとめている） |
| GGX 分布 | 表面の細かいでこぼこの向きが、どれだけ揃っているかを表す式の1つ。ハイライトの形を決める（D項） |
| ベックマン分布 | GGX と同じく、でこぼこの向きの揃い具合を表す式の1つ（`Beckmann()`）。以前の式で使っていた |
| Smith の遮蔽 | でこぼこが、光や視線を隠してしまう割合を表す式（G項） |
| Schlick-GGX | Smith の遮蔽の G項を、係数 `k = a / 2` で近似した形 |
| Schlick 近似 | フレネルの式を、`f0 + (1 − f0)(1 − u)^5` で軽く近似したもの（`SpcFresnel()` の中身） |
| ハーフベクトル | 光に向かう向きと、視線に向かう向きの真ん中の向き（H）。ハイライトは、法線がこの向きに近い所で強く出る |
| 反射率 | 光が当たったとき、どれだけを反射するかの割合 |
| 粗さ | 表面のでこぼこの大きさ。大きいほど、ハイライトが広く弱くなる。滑らかさの逆（1 − 滑らかさ） |
| 滑らかさ | 表面の滑らかさ（0〜1）。大きいほど、ハイライトが小さく鋭くなる |
| 拡散反射 | 光が面で、いろいろな向きにまんべんなく散らばること。物の色に見える |
| フレネル | 見る角度が浅い（面すれすれ）ほど、反射が強くなる現象 |
| スペキュラカラー | 鏡面反射に付ける色 |
| 金属度 | 金属らしさ（0〜1）。大きいほど、鏡面反射にスペキュラカラーの色が付く |
| スペキュラマップ | 金属度と滑らかさを、ピクセルごとに入れたテクスチャ |
| 分布・遮蔽の式の記号 | N は法線、L は光に向かう向き、V は視線に向かう向き。N·L・N·V・N·H・V·H はその内積 |

## 1. 全体像

```
CalcLighting()（PBRLighting.h）
  ├ 拡散反射 = アルベド × フレネルを考えた拡散反射率 × ライトの色 × N·L / π
  ├ 鏡面反射 = CookTorranceSpecular(L, V, N, 滑らかさ) × ライトの色      ← このページ
  │             │  └ 中で 粗さ = 1 − 滑らかさ（下限 0.3）
  │             × lerp(白, スペキュラカラー, 金属度)
  └ 結果 = 拡散反射 × (1 − 滑らかさ) ＋ 鏡面反射 × 滑らかさ
```

滑らかさと金属度は、G-Buffer の「メタリック・影・スムース」の絵（r が金属度、a が滑らかさ）から読みます。スペキュラマップのないモデル（ステージの地形・草木・岩など）は、エンジンの `specMap_None.DDS`（[DDS](../../../用語集.md#描画)）が使われ、金属度 0・滑らかさ約 0.36 になります。

## 2. 実装方法

`CookTorranceSpecular()` は、N·L を掛けたあとの値を返します。光の当たっていない面（N·L が 0 以下）では 0 を返します。まず、この関数の前半で、次の値を作っておきます。

```hlsl
float NdotL = dot(N, L);                    // 0 以下なら、ここで 0 を返す
float NdotV = max(dot(N, V), 0.001f);       // 面すれすれでも 0 にしない
float3 H = normalize(L + V);                // ハーフベクトル
float NdotH = saturate(dot(N, H));
float VdotH = saturate(dot(V, H));
```

そのあと、D項・F項・G項を計算します。

```hlsl
float roughness = max(1.0f - smooth, SPECULAR_MIN_ROUGHNESS);
float a = roughness * roughness;      // 見た目の粗さに合わせて2乗する
float a2 = a * a;

float d = NdotH * NdotH * (a2 - 1.0f) + 1.0f;
float D = a2 / (PI * d * d);          // D項: GGX 分布

float F = SpcFresnel(SPECULAR_F0, VdotH);   // F項: Schlick 近似

float k = a * 0.5f;                   // G項 ÷ (4·N·L·N·V): Smith の遮蔽（Schlick-GGX）
float vis = 0.25f / ((NdotL * (1 - k) + k) * (NdotV * (1 - k) + k));

return min(D * F * vis * NdotL, SPECULAR_MAX);  // 上限で止める
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 変数 | `roughness` | 粗さを、下限つきで持つため | 滑らかさの逆（`1 − smooth`）。0.3 より小さくしない | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 関数 | `max()` | 大きい方を選ぶため | 2つの値のうち、大きい方を返す | HLSL（シェーダーの言語）の組み込み関数 |
| 引数 | `smooth` | 滑らかさを受け取るため | 0〜1 の滑らかさ。`CalcLighting()` から渡される | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` |
| 変数 | `a` | 見た目の粗さに合わせるため | `roughness` の2乗 | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `a2` | GGX の式で、a の2乗を使うため | `a` の2乗 | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `H` | ハイライトの向きを出すため | 光に向かう向きと視線に向かう向きの真ん中の向き（ハーフベクトル）。`normalize(L + V)` |
| 関数 | `saturate()` | 値を 0〜1 に収めるため | 0 より小さければ 0、1 より大きければ 1 にして返す |
| 変数 | `NdotH` | ハイライトの向きの揃い具合を見るため | 法線 N とハーフベクトル H の内積（0〜1）。上の抜き出しで計算する | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `d` | D項の分母の中身を作るため | `NdotH² × (a² − 1) + 1`。GGX 分布の式の一部 | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `D` | D項（GGX 分布）の値を持つため | 向きが揃っているほど大きくなる | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 値 | `PI` | 円周率を使うため | 3.1415926 | ゲームの [PBRLighting_const.h](../../../../Game/Assets/shader/PBRLighting_const.h) |
| 変数 | `F` | F項（フレネル）の値を持つため | 見る角度が浅いほど大きくなる | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 関数 | `SpcFresnel()` | フレネルを Schlick 近似で出すため | 正面の反射率 `f0` と、視線と H の内積から、反射の割合を返す | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) |
| 変数 | `VdotH` | フレネルの角度を見るため | 視線に向かう向き V と H の内積（0〜1）。上の抜き出しで計算する | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `k` | Schlick-GGX の係数にするため | `a` の半分 | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `vis` | G項を 4·N·L·N·V で割った値を持つため | 分母に `k` が残るので、N·V が 0 に近くても有限になる | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `NdotL` | 光の当たり具合を掛けるため | 法線 N と、光に向かう向き L の内積。上の抜き出しで計算し、0 以下なら 0 を返す | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 変数 | `NdotV` | 視線の浅さを見るため | 法線 N と、視線に向かう向き V の内積。0.001 より小さくしない | ゲームの [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` の中 |
| 関数 | `min()` | 小さい方を選ぶため | 2つの値のうち、小さい方を返す。ここでは `SPECULAR_MAX` で止める | HLSL（シェーダーの言語）の組み込み関数 |

- **G項を 4·N·L·N·V で割った形（vis）でまとめて計算する。** 式どおり G を出してから N·V で割ると、N·V が 0 に近いところで割り算が大きくなる。まとめた形なら分母に k が残るので、視線が面すれすれでも有限の値になる。
- **最後に N·L を掛ける。** 拡散反射と同じく、光が斜めに当たるほど暗くなる。
- **上限（`SPECULAR_MAX`）で止める。** k が残っても、滑らかな物を逆光で面すれすれに見ると、ライトの色の数十倍になる（滑らかさ 0.8 で、視線が面から 10° のとき、つまり N と V の角度が 80° で N·V ≒ 0.17 のとき、約 25 倍）。[ブルーム](../../../用語集.md#描画)で白く光るので、ライトの色超えないようにする。

## 3. 調整用の数値

| 名前 | 値 | 何を決めるか | 上げると | 下げると |
|---|---|---|---|---|
| `SPECULAR_F0` | 0.04 | 正面から見たときの反射率 | 全体がテカる | 照り返しが弱くなる。斜めから見たときの照り返し（フレネル）は残る |
| `SPECULAR_MIN_ROUGHNESS` | 0.3 | 粗さの下限 | ハイライトが広く・弱くなる | ハイライトが小さく・強くなり、ブルームで光りやすい |
| `SPECULAR_MAX` | 1.0 | 鏡面反射の上限（ライトの色に掛ける前） | 逆光のふちが白く光りやすくなる | ハイライトの芯が平らになる |

どれも [PBRLighting.h](../../../../Game/Assets/shader/PBRLighting.h) の `CookTorranceSpecular()` のすぐ上にあります。シェーダーは起動のときにコンパイルされるので、値を変えたらゲームを起動し直せば反映されます。

ハイライトの強さは、このほかに `Game.cpp` の `MAIN_LIGHT_COLOR`（ライトの色、今は 2.0）と、各モデルのスペキュラマップの a（滑らかさ）でも変わります。

## 4. 決めたこと

- 以前の式は、ベックマン分布で、反射率 0.5 固定、粗さの上限 0.5（コメントでは「下限」のつもりだった）、分母が π·N·V·N·H でした。草や地面を斜めから見ると白く光り、すれすれではライトの色の十数倍まで明るくなっていました。くわしくは経緯を見てください。
- `Beckmann()` は使わなくなりましたが、ほかから呼ばれる場合に備えて残しています。
- 拡散反射と鏡面反射を滑らかさで混ぜる部分（`CalcLighting()` の最後の行）は変えていません。

## 5. 既知の課題

- キャラクターのトゥーンのハイライトは、この関数ではなく、[アニメ調ライティングの設計](../アニメ調ライティング/アニメ調ライティングの設計.md) の「ハイライト」で別に作る予定です。
- ステージの草木の照り返しは、ほとんど見えなくなります。もっと照り返しがほしい物は、スペキュラマップで滑らかさを上げます。
