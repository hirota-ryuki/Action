## 2026-11-10 マテリアルの名前が長いと Buffer too small で止まるのを直した（#102）

このページは 2026-11-15 に、コミットの記録から書き起こしました。直したときの画面は残っておらず、直す前のエンジンをビルドし直して撮ることもしていないので、画像はありません。

### 1. 現状の問題

Meshy で作った黒騎士（剣のテクスチャ `BlackKnightSword_albedo` など）を読み込むと、起動の途中で「Buffer too small」のエラーが出て止まった。

**用語:**

| 用語 | 何のことか |
|---|---|
| albedo（アルベド） | 物の表面の色。`_albedo` が付くテクスチャは、色を入れた画像 |
| Buffer too small | 「書き込む入れ物が小さすぎる」というエラー。`sprintf_s` が、書ききれないときに出す |

### 2. ソースコードの問題箇所

[MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp) の `CreateMeshFromTkmMesh` は、マテリアルを見分ける名前を、260文字（`MAX_PATH`）の入れ物に `sprintf_s` で書いていた。

```cpp
char materiayKey[MAX_PATH];
sprintf_s(
    materiayKey,
    MAX_PATH,
    "%s, %s, %s, %s, %d, %d, ... %s, %s, %s",
    fxFilePath,           // シェーダーのファイル
    vsEntryPointFunc,     // 入口の関数（3つ）
    ...
    tkmMat.albedoMapFileName.c_str(),    // テクスチャ3枚の名前
    tkmMat.normalMapFileName.c_str(),
    tkmMat.specularMapFileName.c_str()
);
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 変数 | `materiayKey` | マテリアルを見分ける名前を入れるため | 260文字ぶんの `char` の配列。ここに名前を書いて、マテリアルバンクで探す | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp)（`CreateMeshFromTkmMesh()` の中。綴りは `materiay` のまま） |
| 値 | `MAX_PATH` | 入れ物の大きさを決めるため | ファイルのパスの長さの上限（260） | Windows の API（`<windows.h>`） |
| 関数 | `sprintf_s()` | 名前を、書式に合わせて入れ物に書くため | 書式（`%s`・`%d`）に値を入れて文字列にする。入れ物の大きさを超えそうなときは、エラーを出して止まる | C++ の標準ライブラリ（`<stdio.h>`。[k2EngineLowPreCompile.h](../../../k2EngineLow/k2EngineLowPreCompile.h) で読み込み済み） |
| 引数 | `fxFilePath` | マテリアルが使うシェーダーのファイルを知るため | シェーダー（`.fx`）のファイルのパス | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp) の `CreateMeshFromTkmMesh()` |
| 引数 | `vsEntryPointFunc` | 頂点シェーダーの入口の関数を知るため | 頂点シェーダーの入口になる関数の名前。同じ並びの `vsSkinEntryPointFunc`（スキンあり）、`psEntryPointFunc`（ピクセルシェーダー）も同じ | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp) の `CreateMeshFromTkmMesh()` |
| 変数 | `tkmMat` | tkm の1つのマテリアルを指すため | `TkmFile::SMaterial`。テクスチャのファイル名（`albedoMapFileName`・`normalMapFileName`・`specularMapFileName`）などを持つ | k2EngineLow（エンジン）の [TkmFile.h](../../../k2EngineLow/tkFile/TkmFile.h) |
| 関数 | `c_str()` | `std::string` を、`const char*` を受け取る関数に渡すため | 文字列の先頭を指す `const char*` を返す | C++ の標準ライブラリ（`std::string` のメンバー） |

名前には、シェーダーのファイル・入口の関数・描く先の形式8つ・テクスチャ3枚の名前が入る。テクスチャの名前が長いと 260文字を超え、`sprintf_s` は書ききれないときにエラーを出して止まる。

**用語:**

| 用語 | 何のことか |
|---|---|
| 入口の関数 | シェーダーの中で、最初に呼ばれる関数。頂点シェーダー・スキン付きの頂点シェーダー・ピクセルシェーダーの3つがある |
| 描く先の形式 | 描く先の画像（カラーバッファ）の色の持ち方。8枚ぶんある |
| マテリアルバンク | 作ったマテリアルを、名前を鍵にして覚えておく入れ物。同じ名前なら使い回す |

### 3. 直し方

名前の長さは決まっていないので、入れ物の大きさを決めずに、先に長さを数えてから書く。`snprintf` は、書く先に `nullptr`・大きさ 0 を渡すと、書かずに要る長さだけを返す。同じ書き方を2回使うので、書き方をラムダ式にまとめる。

### 4. ソースコードの直し

```diff
-			char materiayKey[MAX_PATH];
-			sprintf_s(
-				materiayKey,
-				MAX_PATH,
+			// テクスチャの名前が長いと MAX_PATH を超えるので、先に長さを数えてから書く。
+			auto formatMaterialKey = [&](char* buffer, size_t bufferSize) {
+				return snprintf(
+				buffer,
+				bufferSize,
 				"%s, %s, %s, %s, %d, %d, %d, %d, %d, %d, %d, %d, %d, %d, %d, %d, %s, %s, %s",
 				...
-			);
-			auto mat = materialBank.Get(materiayKey);
+				);
+			};
+			std::string materiayKey(formatMaterialKey(nullptr, 0), '\0');
+			formatMaterialKey(&materiayKey[0],materiayKey.size() + 1);
+			auto mat = materialBank.Get(materiayKey.c_str());
 ...
-				materialBank.Regist(materiayKey, mat);
+				materialBank.Regist(materiayKey.c_str(), mat);
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 変数 | `formatMaterialKey` | 同じ書き方を、長さを数えるときと書くときの2回使うため | 書く先と大きさを受け取り、`snprintf` で名前を書くラムダ式 | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp)（`CreateMeshFromTkmMesh()` の中） |
| 引数 | `buffer`・`bufferSize` | 書く先と、その大きさを受け取るため | `formatMaterialKey` の引数。`nullptr`・0 を渡すと、書かずに要る長さだけが返る | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp) の `formatMaterialKey` |
| 関数 | `snprintf()` | 書く先の大きさを超えずに書き、書きたかった長さを返すため | 書式に値を入れて文字列にする。大きさが足りなくても止まらず、切り詰める。書く先が `nullptr`・大きさ 0 のときは、書かずに長さだけを返す | C++ の標準ライブラリ（`<stdio.h>`。[k2EngineLowPreCompile.h](../../../k2EngineLow/k2EngineLowPreCompile.h) で読み込み済み） |
| 型 | `size_t` | 大きさを表すため | 符号なしの整数 | C++ の標準ライブラリ（`<cstddef>`） |
| C++ の書き方 | `std::string(長さ, '\0')` | 長さが決まった入れ物を作るため | `'\0'`（文字列の終わりを表す文字）を長さぶん並べた文字列を作る | C++ の標準ライブラリ（`<string>`） |
| C++ の書き方 | `&materiayKey[0]` | `std::string` の中身に、`snprintf` で直接書くため | 先頭の文字のアドレスを取る。書き込める `char*` として渡せる | C++ の書き方 |
| 変数 | `materialBank` | 作ったマテリアルを覚えておくため | 名前（文字列）から `Material` を探せる入れ物（`TResourceBank<Material>`） | k2EngineLow（エンジン）の [MeshParts.cpp](../../../k2EngineLow/graphics/MeshParts.cpp)（`GetMaterialBank()` が返す） |
| 関数 | `Get()` | 名前から、登録済みのものを探すため | あればそのポインターを、なければ `nullptr` を返す | k2EngineLow（エンジン）の [TResourceBank.h](../../../k2EngineLow/util/TResourceBank.h) |
| 関数 | `Regist()` | 作ったマテリアルを、名前をつけて覚えさせるため | 名前がまだなければ登録する | k2EngineLow（エンジン）の [TResourceBank.h](../../../k2EngineLow/util/TResourceBank.h) |

### 5. どう確かめたか

黒騎士を読み込んで、止まらずに起動することを確かめた（#103 で、敵を Meshy の黒騎士に替えた）。
