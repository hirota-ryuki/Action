# 法線のキャッシュの手順

設計: [法線のキャッシュの設計](法線のキャッシュの設計.md)
経緯: [起動時のモデルロード高速化の経緯](起動時のモデルロード高速化の経緯.md)

tkm を読み込むときに計算する法線・接ベクトル・従ベクトルを、tkm の隣の `.tkmcache` に書いておき、次の起動からはそれを読んで計算を省くまでの手順です。上から順にやると、[法線のキャッシュの設計](法線のキャッシュの設計.md) の形になります。

**出来上がるもの:** 2回目からの起動で、tkm の BSP 作りと法線のスムージングが省かれ、Debug ビルドの起動が速くなります（ボス戦の広間では約19秒が約10秒になった）。見た目は変わりません。

**前提:**

- Visual Studio で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 先に [モデル読み込みの手順](モデル読み込みの手順.md) の手順10（同じ tkm を2回読み込まないようにする）を済ませておく。済ませていなくても動くが、同じ tkm でキャッシュを2回読むことになる。
- 法線の計算（`TkmFile::BuildTangentAndBiNormal()`）と BSP（`BSP` クラス）は、もとからある（変えない）。

| 手順 | 足すもの | 確かめ方 |
|---|---|---|
| 1 | BSP を作る所を関数に分ける | ビルドが通る |
| 2 | 計算した結果をキャッシュに書く | 起動すると `.tkmcache` ができる |
| 3 | キャッシュがあれば読んで、計算を省く | 2回目の起動が速くなる |

**読み方:**

- 足す場所は「〇行目 `その行に書いてあること` の下」で示します。行番号は、それより前の小手順を済ませたときの番号です。
- 枠の左の数字は、足したあとの行番号です。右の枠のコードを、そのまま書きます。
- 消すところは、消す行を枠で示します（番号は消す前の番号）。書き換えるところは、「前」と「後」の枠を並べています。
- VSCode で `Ctrl+Shift+V` を押してプレビューで読みます。

				vertex.binormal.Set(p[6], p[7], p[8]);
				p += NORMAL_CACHE_FLOATS_PER_VERTEX;
			}
		}
		return true;
	}
