## 2026-11-08: ImGui を入れる設計と手順を書いた

### 何をしたか

ライティングを原神のようなアニメ調に変えるにあたり、影の色やリムライトの強さなどを、ゲームを動かしたまま見ながら合わせたいという話から始めた。数値を変えるたびにビルドし直すのは時間がかかるので、ライティングより先に ImGui を入れることにした（[アニメ調ライティングの設計](../ライティング/アニメ調ライティングの設計.md) の実装の順番の1つ目）。

あわせて、実装の方法を「手順書」として書く決まりを作り、このページの [デバッグUIの手順](デバッグUIの手順.md) を最初の手順書にした。ユーザーが手順書を上から順にやって実装する。

決めたこと:

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 版 | ImGui v1.92.9b | v1.93.0 は出てから1か月たっていないため、その前の安定版にした |
| 置き場所 | `exlib/imgui/` にバックエンドも含めて平らに置く | バックエンドが `#include "imgui.h"` で本体を探すので、同じフォルダーなら設定がいらない |
| ビルドするプロジェクト | k2EngineLow | 描く場所がエンジンのフレームの最後なので、エンジン側で呼ぶ必要がある |
| 形 | namespace `DebugUI` | ImGui のコンテキストが1つだけなので、インスタンスを作る意味がない |
| ディスクリプタヒープ | ImGui 専用に64個 | v1.92 からテクスチャごとにディスクリプタを借りる形になったため。エンジンのヒープと分けた |
| 動くビルド | Debug・Preview（`K2_DEBUG`） | 製品のビルドには出さない |
| 出し方 | F1 で出す・隠す。出している間はマウスを ImGui に使う | カメラがカーソルを毎フレーム真ん中に戻して隠すので、そのままではクリックできない |
| Effekseer の中の imgui | 使わない | Effekseer のサンプル用に入っているもので、版が古い（1.80） |

### どう確かめたか

リポジトリとは別の作業用フォルダー（`git worktree` で main を取り出したもの）に、手順書どおりに組み込んで確かめた。組み込んだコードは、リポジトリにはコミットしていない。

- 手順2のあと、k2EngineLow を Debug x64 でビルドし、ImGui の `.cpp` 7つが警告もエラーもなくビルドできた。
- 全手順のあと、k2EngineLow → k2Engine → Game の順に Debug x64 でビルドが通った。
  - はじめ `GraphicsEngine::WaitDraw()` が `private` でビルドが通らなかったので、`public` に移す手順（手順3）を足した。
  - Game のプリコンパイル済みヘッダーが作り直されず、`'DebugUI': 識別子がクラス名でも名前空間名でもありません` と出た。Game をリビルドすると通った。手順4の確かめ方に書いた。
- ゲーム側から ImGui を呼ぶ使い方（`#include <imgui/imgui.h>` と `ImGui::Begin(u8"...")`）を `Game::Update()` に仮に書き、ビルドとリンクが通ることを確かめてから元に戻した。
- ゲームを最小化・非アクティブのまま起動し、25秒動かしてからウィンドウを閉じるメッセージを送ると、落ちずに終了した（ImGui の起動・毎フレームの処理・終了が通ることの確認）。画面は撮っていない。
- **まだ確かめていないこと:** F1 で窓が出ること、日本語が化けないこと、クリックで操作できること、Release ビルドで何も出ないこと。手順書どおりに実装したときに、画面で確かめる。

## 2026-11-08: 手順書に、触るファイルと書き換える行を書き足した

「どこのヘッダーや CPP に何を足して、何を消したりコメントアウトしたのか全くわからない」という指摘を受けて、手順書の決まりに「触るファイルの一覧」「この手順で触るファイル」の表と、書き換える行の diff を足した。このページの手順書も、その形にそろえた。

- 冒頭に「触るファイルの一覧」を足した。消すファイル・コメントアウトする行はない。
- 各手順の頭に「この手順で触るファイル」の表を足した。
- 手順3（`WaitDraw()` を `public` へ移す）と手順7（`IsGameWindowActive()` を `CanUseMouse()` に変える2行）は、もとからあるコードの書き換えなので、diff で前と後を並べた。
- コードの中身は変えていないので、組み込み直しての確かめはしていない。
