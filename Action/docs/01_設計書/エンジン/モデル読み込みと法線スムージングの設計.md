# モデル読み込みと法線スムージングの設計

作成日: 2026-11-05
対象: `k2EngineLow` のモデル読み込み（FBX→tkm 変換、tkm 読み込み、BSP による法線スムージング）
関連コミット: `31fbca03 <Loading>起動時のモデルロードを高速化(BSP探索の空ループ削除・FBX変換時の重複頂点統合)`

このドキュメントでは、`ModelRender::Init()` にモデルを渡してから描画できる状態になるまでに、エンジンの中で何が行われているかを説明します。
起動時間に大きく関わる部分なので、モデル読み込み・FBX インポーター・BSP を触るときは先に読んでください。

---

## 1. 全体の流れ

```
ModelRender::Init("xxx.FBX" または "xxx.tkm")
 │
 ├─ ① FbxRuntimeImporter::ResolveToTkmFilePath()
 │     .fbx なら、必要なときだけ tkm/tks に変換して、tkm のパスを返す（.tkm ならそのまま返す）
 │
 └─ ② Model::Init()
       ├─ tkm バンクにあればそれを使う（同じモデルを2回目以降に読むときは ③ を飛ばす）
       └─ ③ TkmFile::Load()
             ├─ 頂点・インデックスを読む（ファイルの法線は使わず、ここで計算し直す）
             ├─ ④ 面の法線から頂点の法線を作る
             ├─ ⑤ BSP で「同じ座標の頂点」を探して法線を平均する（スムージング）
             └─ 接ベクトル・従ベクトルを作る
```

| 段階 | 処理 | コード |
|---|---|---|
| ① | FBX→tkm/tks/tka 変換とキャッシュ判定 | [FbxRuntimeImporter.cpp](../../../k2EngineLow/tkFile/FbxRuntimeImporter.cpp) |
| ② | tkm バンクの確認 | [Model.cpp](../../../k2EngineLow/graphics/Model.cpp) |
| ③〜⑤ | tkm 読み込みと法線スムージング | [TkmFile.cpp](../../../k2EngineLow/tkFile/TkmFile.cpp) の `Load()`、`BuildTangentAndBiNormal()` |
| ⑤ | 同じ座標の頂点の探索 | [BSP.cpp](../../../k2EngineLow/geometry/BSP.cpp) |

## 2. FBX→tkm 変換とキャッシュ

FBX を渡したときは、毎回変換するのではなく、**ファイルの更新日時を比べて必要なときだけ変換**します。

| 出力 | 作り直す条件 | 関数 |
|---|---|---|
| `xxx.tkm` / `xxx.tks` | tkm が無い、または FBX の方が新しい | `ResolveToTkmFilePath()` → `IsConversionNeeded()` |
| アニメーションの `xxx.tka` | tka が無い、アニメーション FBX の方が新しい、またはスケルトン（tks）の方が新しい | `ResolveAnimationFbxToTka()` |
| テクスチャの `xxx.dds` | dds が無い、または元画像の方が新しい | `ConvertTextureToDDS()`（texconv.exe を起動） |

> **注意: インポーターのコードを変えても、既存の tkm は作り直されません。**
> 判定は日付だけなので、変換処理を直したときは対象の `.tkm` を手で消してから起動してください。
> 変換された tkm/tks/tka は git で管理しているので、作り直したらコミットします。

## 3. 頂点の統合（FBX インポーター）

### 3.1 なぜ必要か

FBX と GPU では、「頂点」の単位が違います。

| | 位置 | 法線・UV |
|---|---|---|
| FBX | 頂点ごとに1つ | **面の角（corner）ごと**に持つ（同じ頂点でも面によって違うことがある） |
| GPU（tkm） | 位置・法線・UV・スキンを**まとめて1つの頂点**として扱う | |

角ごとにそのまま頂点を作ると、同じ頂点が何個も重複します。SK_Player では、頂点数がインデックス数と同じ 124,521 個になっていました。

### 3.2 何をまとめるか

座標・法線・UV・スキンウェイト・ボーン番号（tkm に保存されるものすべて）が**全部同じ頂点だけ**を1つにまとめます。どれか1つでも違えば別の頂点なので、UV の継ぎ目や角ばった部分は別のまま残ります。
やり方は 6.1 にあります。

### 3.3 効果（SK_Player.FBX）

| | 統合前 | 統合後 |
|---|---|---|
| 頂点数 | 124,521 | **28,493** |
| インデックス数（ポリゴン数×3） | 124,521 | 124,521 |
| SK_Player.tkm のサイズ | 7.5MB | 2.1MB |

## 4. tkm 読み込み時の法線スムージング

`TkmFile::Load()` は、**ファイルに入っている法線を使わず**、読み込むたびに法線を計算し直します（`vertex.normal = g_vec3Zero` で捨てている）。

| 手順 | 内容 | 関数 |
|---|---|---|
| 1. 面の法線を足し込む | 三角形ごとの面の法線を、その3頂点に足して正規化する。インデックスで共有されている頂点は周りの面の平均になる | `NormalSmoothing::Execute()` |
| 2. 同じ座標の頂点どうしで平均する | 座標がまったく同じで、向きが近い（内積が正の）頂点の法線を足して平均する。UV の継ぎ目で分かれた頂点も滑らかにつながる。`isFlatShading == false` のときだけ | `BuildTangentAndBiNormal()` |

手順 2 は頂点の数だけ BSP を探索するので、**BSP の探索が速いことが前提**になっています（6.2・6.4）。

## 5. BSP（二分空間分割）

### 5.1 役割

点の集まりを平面で2つに分けることを繰り返し、木にしたものです。「この座標にある頂点はどれか」を、全部の頂点を調べずに探せます。

エンジン内での使い道は次の2つです。

- `TkmFile`: 法線スムージングで、同じ座標の頂点を探す（4章）
- `NaviMesh`: セルの中心座標から近いセルを探す（[NaviMesh.cpp](../../../k2EngineLow/AI/PathFinding/NaviMesh.cpp)）

### 5.2 木の要素

| 要素 | 持っているもの |
|---|---|
| `SNode` | 分割平面、左右の子、中心座標 |
| `SLeaf` | 座標と、付加データ（TkmFile では法線へのポインタ） |
| `SLeafList` | ほぼ同じ場所にある `SLeaf` の配列（木の末端） |

## 6. 実装方法

### 6.1 頂点の統合：属性をバイト列のキーにしてハッシュマップで引く

```cpp
// FbxRuntimeImporter.cpp
struct VertexKey {
    float pos[3];
    float normal[3];
    float uv[2];
    float skinWeights[4];
    int indices[4];
    bool operator==(const VertexKey& rhs) const {
        return std::memcmp(this, &rhs, sizeof(VertexKey)) == 0;   // バイト列で比べる
    }
};
static_assert(sizeof(VertexKey) == 4 * 16, "VertexKeyにパディングが入っています。");

struct VertexKeyHash {   // FNV-1a（64bit）をバイト列にかける
    size_t operator()(const VertexKey& key) const { ... }
};
```

```cpp
// BuildMeshParts()：メッシュごとにマップを1つ持つ
std::unordered_map<VertexKey, uint32_t, VertexKeyHash> vertexIndexMap;
vertexIndexMap.reserve(mesh->num_indices);

// 三角形の角（corner）ごとに頂点を作り…
uint32_t newIndex = (uint32_t)dstMesh.vertexBuffer.size();
auto inserted = vertexIndexMap.emplace(MakeVertexKey(v), newIndex);
if (inserted.second) {
    dstMesh.vertexBuffer.push_back(v);              // 初めて出てきた頂点だけ足す
}
dstIb.indices.push_back(inserted.first->second);  // インデックスは既存の番号を使う
```

| 書き方 | 理由 |
|---|---|
| 全メンバを4バイト型にして `static_assert` で確かめる | パディングがないので、`memcmp` とバイト列のハッシュで正しく比べられる |
| `emplace` の戻り値で、新しいか既存かを1回の検索で判定する | 探してから入れる、の2回の検索をしない |
| マップをメッシュごとに持つ | 1つのメッシュの頂点バッファは、そのメッシュの全マテリアル（インデックスバッファ）で共有しているため |

浮動小数点をバイト単位で比べるので、`0.0` と `-0.0` は別の頂点になります。まとまらないだけで、表示はおかしくなりません。

### 6.2 法線スムージング：頂点ごとに BSP で同じ座標を探す

```cpp
// TkmFile::BuildTangentAndBiNormal()
auto smoothFunc = [&](int startIndex, int endIndex) {
    for (int i = startIndex; i < endIndex; i++) {
        auto& va = smoothVertex[i];
        m_bpsOnVertexPosition.WalkTree(va.vertex->pos, [&](BSP::SLeaf* leaf) {
            if (va.vertex->pos.x == leaf->position.x && ...) {          // 座標がまったく同じ
                auto* normal = static_cast<Vector3*>(leaf->extraData);
                if (va.vertex->normal.Dot(*normal) > 0.0f) {            // 向きが近い
                    va.newNormal += *normal;
                }
            }
        });
    }
};
// 頂点を4等分して4スレッドで smoothFunc を実行し、join してから正規化して書き戻す
```

各スレッドは自分の担当の `newNormal` にだけ書き、元の法線は読むだけなので、ロックなしで並列にできます。

### 6.3 BSP の構築：一番散らばっている方向で2つに分けることを繰り返す

```cpp
BSP::SEntityPtr BSP::CreateBSPTreeEntity(const std::vector<SEntityPtr>& leafArray)
{
    if (leafArray.size() == 1) { return leafArray.front(); }
    Vector3 centerPos = CalcCenterPositionFromLeafList(leafArray);
    float covarianceMatrix[3][3];
    CalcCovarianceMatrixFromLeafNodeList(covarianceMatrix, leafArray, centerPos);   // 共分散行列
    if (どの行も長さ 0.1 未満) {
        return CreateBSPTreeEntity_LeafList(leafArray);   // ほぼ同じ場所の点だけ → 末端
    }
    CalcSplitPlaneFromCovarianceMatrix(newNode->plane, ...);   // ヤコビ法で固有ベクトル → 分割平面
    SplitLeafArray(leftLeafArray, rightLeafArray, newNode->plane, leafArray);
    newNode->leftEntity = CreateBSPTreeEntity(leftLeafArray);   // 左右それぞれで繰り返す
    newNode->rightEntity = CreateBSPTreeEntity(rightLeafArray);
    return newNodePtr;
}
```

片方が空になったときも末端にして、再帰が終わらなくなるのを防いでいます。

### 6.4 BSP の探索：平面のどちら側かで片方の子だけに進む

```cpp
void BSP::WalkTree(const SEntityPtr& entityPtr, const Vector3& pos,
                   const std::function<void(SLeaf* leaf)>& onEndWalk) const   // 引数は const 参照
{
    if (entityPtr->type == enEntityType_Node) {
        SNode* node = static_cast<SNode*>(entityPtr.get());
        if (Dot(pos, node->plane.normal) < node->plane.distance) {
            WalkTree(node->leftEntity, pos, onEndWalk);
        } else {
            WalkTree(node->rightEntity, pos, onEndWalk);
        }
    }
    else if (entityPtr->type == enEntityType_Leaf) { onEndWalk(葉); }
    else if (entityPtr->type == enEntityType_LeafList) { for (葉 : 末端の配列) onEndWalk(葉); }
}
```

1回の探索で通るノードは木の深さぶん（12万点で約17個）なので、全頂点を探索しても **O(N log N)** で済みます。

## 7. 使い方

### FBX インポーターの変換処理を変えたとき

1. 対象の `.tkm`（アニメーションなら `.tka`）を手で消す。日付だけで判定しているので、消さないと作り直されない。
2. 起動して作り直す。
3. 作り直した tkm/tks/tka をコミットする。

### tkm に保存する頂点の属性を足すとき

`VertexKey` にもメンバーを足します。4バイトの型にして、パディングを入れないでください（`static_assert` で確かめています）。足さないと、その属性が違う頂点がまとめられてしまいます。

### BSP を書き換えるとき

- `WalkTree()` は頂点の数だけ呼ばれます。**探索の中に、ノードが持つ点の数に比例する処理を入れないでください。** 全体が O(N²) になります。
- `WalkTree()` は再帰関数なので、引数（`shared_ptr` と `std::function`）は const 参照で受け取っています。値渡しに戻すと、ノードを1つ下りるたびにコピーが発生します。
- `toolsProj/nvmExporter/nvmExporter/bsp/` に同じ BSP の古いコピーがあります。こちらは修正前のままです（空ループが残っています）。
