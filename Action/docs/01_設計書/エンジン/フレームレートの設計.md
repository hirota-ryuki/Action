# フレームレートの設計

作成日: 2026-11-06
対象: `k2EngineLow` のフレームレート制御（FPS の上限、VSync、1フレームの経過時間）
ブランチ: `feature/unlimited-fps`

このドキュメントでは、1フレームの長さがどう決まり、ゲームの処理にどう渡されるかを説明します。
FPS の上限を変えたいとき、動きの速さが FPS で変わってしまうときに読んでください。

- 今は **FPS の上限なし**（`USE_FPS_LIMITTER` を無効）で動かしている。VSync も待たない。
- ゲームの処理は `g_gameTime->GetFrameDeltaTime()` を掛けて動かすので、FPS が変わっても動く速さは変わらない。
- 上限は `k2EngineLowPreCompile.h` の1行で戻せる。

---

## 1. 全体像

1フレームは `K2EngineLow` の `BeginFrame()` から `EndFrame()` までです。

```
K2EngineLow::BeginFrame()
 ├─ FPSLimitter::BeginFrame()      … 上限用のストップウォッチを開始
 ├─ GameTime::BeginMeasurement()   … 経過時間の計測を開始
 └─ GraphicsEngine::BeginRender()

  （ゲームの更新・描画）

K2EngineLow::EndFrame()
 ├─ GraphicsEngine::EndRender()
 │    └─ FrameBuffer::Present(syncInterval)   … USE_FPS_LIMITTER が有効なら 1（VSync 待ち）、無効なら 0
 ├─ FPSLimitter::Wait()            … USE_FPS_LIMITTER が有効なときだけ。最大FPSを超えないよう待つ
 └─ GameTime::EndMeasurement()     … 経過時間を記録 → 次のフレームの GetFrameDeltaTime() になる
```

| 部品 | ファイル | 役割 |
|---|---|---|
| `USE_FPS_LIMITTER` / `MAX_FPS` | [k2EngineLowPreCompile.h](../../../k2EngineLow/k2EngineLowPreCompile.h) | 上限を付けるかどうか、最大FPS（60） |
| `FPSLimitter` | [FPSLimitter.h](../../../k2EngineLow/time/FPSLimitter.h) | 最大FPSに届くまでスピンして待つ |
| `GameTime` | [GameTime.h](../../../k2EngineLow/time/GameTime.h) | 1フレームの経過時間を計り、ゲームに渡す |
| `K2EngineLow::SetFrameRateMode()` | [k2EngineLow.h](../../../k2EngineLow/k2EngineLow.h) | 固定 / 可変フレームレートの切り替え |
| `GraphicsEngine::EndRender()` | [GraphicsEngine.cpp](../../../k2EngineLow/graphics/GraphicsEngine.cpp) | `Present()` の待ち方（VSync）を決める |

---

## 2. 詳細

### 2.1 FPS の上限（USE_FPS_LIMITTER）

`USE_FPS_LIMITTER` は、次の2つをまとめて切り替えます。

| | 有効（以前） | 無効（今） |
|---|---|---|
| `Present()` の待ち | `Present(1)`: モニターの更新（VSync）を待つ | `Present(0)`: 待たない |
| `FPSLimitter::Wait()` | `MAX_FPS`（60）を超えないよう待つ | 呼ばない |
| 結果の FPS | モニターのリフレッシュレートか 60 の低い方 | GPU・CPU が出せるだけ |

スワップチェーンは `DXGI_SWAP_EFFECT_FLIP_DISCARD` なので、`Present(0)` ではモニターより速く描いた分の古いフレームは捨てられ、画面には新しいフレームが出ます。
`DXGI_PRESENT_ALLOW_TEARING` は使っていないため、フルスクリーンでもティアリングを許すモードにはなりません。

### 2.2 1フレームの経過時間（GameTime）

`GameTime` には2つのモードがあります。`SetFrameRateMode()` で切り替えます。

| モード | `GetFrameDeltaTime()` が返す値 | 使う場面 |
|---|---|---|
| 可変（`enFrameRateMode_Variable`、既定） | 計った経過時間の平均（直近30フレーム）。ただし **1/30 秒より大きくはならない** | 普段のゲーム |
| 固定（`enFrameRateMode_Fix`） | `1 / maxFPS` の固定値 | オンライン対戦（完全同期） |

可変モードでは FPS が上がるほど返る値が小さくなり、動きの速さは変わりません。

## 3. 実装方法

### 3.1 上限の切り替えはマクロ1つ

上限は実行時のフラグではなく、プリプロセッサのマクロで切り替えています。

```cpp
// k2EngineLowPreCompile.h
//#define USE_FPS_LIMITTER		// 有効でFPSに上限を設ける。（無効にしてFPS無制限）
static const int MAX_FPS = 60;	// 最大FPS。USE_FPS_LIMITTERが有効なときに使用される。
```

```cpp
// GraphicsEngine::EndRender()
#ifdef USE_FPS_LIMITTER
			m_frameBuffer.Present(1);
#else
			m_frameBuffer.Present(0);
#endif
```

```cpp
// K2EngineLow::EndFrame()
		m_graphicsEngine->EndRender();
#ifdef USE_FPS_LIMITTER
		m_fpsLimitter.Wait();
#endif
		m_gameTime.EndMeasurement();
```

VSync と FPSLimitter を同じマクロで止めているのは、片方だけ止めても FPS が上がらないためです（VSync を止めても FPSLimitter が 60 で待つ、FPSLimitter を止めても VSync がリフレッシュレートで待つ）。

### 3.2 FPSLimitter はスピンで待つ

`Sleep()` は精度が粗い（1〜15ms）ので、ストップウォッチを回し続けて残り時間が 1ms 以下になるまでループします。待っている間も CPU のコアを1つ使います。

```cpp
float frameDeltaTimeMin = 1000.0f / m_maxFPS;
do {
	m_sw.Stop();
	restTime = frameDeltaTimeMin - (int)m_sw.GetElapsedMillisecond();
} while (restTime > 1.0f);
```

### 3.3 経過時間は平均して上限を付ける

1フレームごとの値はぶれるので、直近30フレームの平均を使います。さらに、ロード直後などで1フレームが長くなったときに物が大きく飛ばないよう、1/30 秒で頭打ちにしています。

```cpp
m_frameDeltaTime = min(1.0f / 30.0f, totalTime / m_frameDeltaTimeQue.size());
```

## 4. 使い方

### 4.1 FPS の上限を戻す

[k2EngineLowPreCompile.h](../../../k2EngineLow/k2EngineLowPreCompile.h) の `//#define USE_FPS_LIMITTER` のコメントを外します。最大FPSを変えたいときは `MAX_FPS` を変えます。

### 4.2 今の FPS を見る

Debug ビルド（`K2_DEBUG`）では、画面の左上に `FPS = xx.xx` が出ます（`K2EngineLow::EndFrame()`）。値は `1 / GetFrameDeltaTime()` なので、30フレームの平均です。

### 4.3 ゲームの処理を書くとき

動く量・タイマーには必ず `g_gameTime->GetFrameDeltaTime()` を掛けます。1フレームあたりの固定値で動かすと、FPS 無制限では FPS に比例して速くなります。

---

## 5. 調整用の数値

| 名前 | 場所 | 値 | 意味 |
|---|---|---|---|
| `USE_FPS_LIMITTER` | `k2EngineLowPreCompile.h` | 無効 | 上限と VSync を使うか |
| `MAX_FPS` | `k2EngineLowPreCompile.h` | 60 | 上限を使うときの最大FPS |
| 平均するフレーム数 | `GameTime::PushFrameDeltaTime()` | 30 | 経過時間の平均を取る数 |
| 経過時間の上限 | 同上 | 1/30 秒 | 1フレームの経過時間の最大値 |
| オンライン対戦の FPS | `SyncOnlineTwoPlayerMatchEngine.cpp` | 30 | 固定モードの値 |

---

## 6. 決めたこと

- **FPS の上限をなくした**（2026-11-06）。以前は `USE_FPS_LIMITTER` が有効で、VSync 待ち＋60FPS 上限でした。どこまで FPS が出るかを試すために無効にしています。

---

## 7. 既知の課題

- **オンライン対戦では進みが速くなる**。`SyncOnlineTwoPlayerMatchEngine` は固定モード（1フレーム = 1/30 秒）にしますが、上限がないと 1秒間に30フレームより多く回るため、ゲーム全体が速く進みます。オンライン対戦を使うときは、`USE_FPS_LIMITTER` を戻すか、固定モードのときだけ `FPSLimitter::Wait()` を呼ぶように直す必要があります。
- **ティアリングが出ることがある**。VSync を待たないので、ウィンドウの状態によっては画面の上下でずれが見えることがあります。
- **FPS が高いと GPU・CPU を使い切る**。ノートPCでは発熱や電池の減りが大きくなります。
- **1/30 秒より長いフレームでは遅く見える**。経過時間に上限があるため、FPS が 30 を下回るとゲームの進みがゆっくりになります（上限なしとは関係なく、以前からの仕様）。
