# 動画からアニメーションを作る設計（ロトスコープ）

参考にしたいゲームの動画から、コマごとにキャラクターの関節の位置を読み取り、その角度で SK_Player のポーズを作ってアニメーションにする仕組みです。
今のダッシュ（`DashL` / `DashR`）と走り（`Run`）は、原神の動画から、この手順で作っています。

---

## 1. 全体像

```
参考の動画（mp4）
  │ tools/Rotoscope/detect_pose.py   … MediaPipe で関節の位置（33点）をコマごとに読み取る
  ▼
関節の位置（json）
  │ tools/Rotoscope/pose_to_angles.py … 横から見た角度（太もも・すね・足・上腕・前腕・胴体・首）と、つま先・腰の高さに直す
  │ tools/Rotoscope/clean_angles.py   … ならして、棒人間の絵で確かめる（乱れたコマは手で直す）
  ▼
角度のデータ（tools/UnrealScripts/genshin_*_pose.json）
  │ tools/UnrealScripts/adjust_bone_rotation.py の rotoscope（UE 5.8 のコマンドライン）
  ▼
SK_Player のアニメーション（Game/Assets/modelData/player/Animation/*.fbx）
```

| ファイル | 役割 |
|---|---|
| [detect_pose.py](../../../tools/Rotoscope/detect_pose.py) | 動画の指定した範囲のコマを切り出し、MediaPipe の PoseLandmarker（heavy）で関節の位置を読み取る。確かめ用に骨を描いた画像も出す |
| [pose_to_angles.py](../../../tools/Rotoscope/pose_to_angles.py) | 関節の位置を角度に直す。左右の脚・腕が入れ替わったコマは、前のコマに近い方へそろえる |
| [clean_angles.py](../../../tools/Rotoscope/clean_angles.py) | 3コマの中央値と 1:2:1 の平均でならし、棒人間の絵を描く |
| [adjust_bone_rotation.py](../../../tools/UnrealScripts/adjust_bone_rotation.py) の `rotoscope` | 角度のデータどおりに、コマごとに SK_Player のボーンを回し、腰の高さを決める |
| [dash_roto.json](../../../tools/UnrealScripts/dash_roto.json) | `DashL` / `DashR` / `Run` を作る設定 |
| [genshin_dash_pose.json](../../../tools/UnrealScripts/genshin_dash_pose.json) | 原神の動画の 33.27〜34.25秒の角度（ダッシュは 33.41〜33.94秒を使う） |
| [genshin_run_pose.json](../../../tools/UnrealScripts/genshin_run_pose.json) | 原神の動画の走りの1周期（34.25〜34.72秒） |

元の動画は個人用 OneDrive の `02_Action参考資料/原神/` にあります（ゲームの映像なので、公開リポジトリには入れていません）。

## 2. 角度の測り方

横から見た平面（キャラクターの前後と上下）で、骨の向きを測ります。前 = 0°、真上 = 90°、真下 = -90°、真後ろ = ±180° です。ゲームの側の `segment_angle`（ボーン → 子のボーンの線）と同じ測り方です。

| データの名前 | 動画で測る線（MediaPipe の点） | SK_Player で合わせる線 |
|---|---|---|
| `thigh` / `shin` / `foot` | 腰 → 膝 / 膝 → 足首 / 足首 → つま先 | UpperLeg → LowerLeg / LowerLeg → Foot / Foot → ToeBase |
| `upper` / `fore` | 肩 → 肘 / 肘 → 手首 | UpperArm → LowerArm / LowerArm → Hand |
| `torso` | 両腰の真ん中 → 両肩の真ん中 | Hips → Neck |
| `neck` | 両肩の真ん中 → 両耳の真ん中 | Neck → Head |
| `toeA` / `toeB` / `hipH` | 地面からのつま先・腰の高さ ÷ 脚の長さ（腰 → 膝 → 足首） | 同じ割合 × SK_Player の脚の長さ（76.8cm） |

- 地面は、読み取った全コマで一番低い足の位置とします（カメラが上下に動かない範囲を使う）。
- A・B は脚、a・b は腕です。どれをこのキャラクターの左右に当てるかは、設定の `map` で決めます（`DashR` は `DashL` の左右を入れ替えただけ）。

---

## 3. UE での作り方（rotoscope）

1. 元のクリップ（`ThirdPersonRunPlayer_Run.fbx`）の1コマを、データのコマ数だけくり返したクリップにします（`frames: {start: 0, count: 1, hold: コマ数-1}`）。角度を決めない骨（手の指など）が勝手に動かないようにするためです。
2. コマごとに、親から順に「目標の角度 − 今の角度」だけ、キャラクターの左右の軸まわりに回します。
   - 胴体は、腰・Spine・Chest・UpperChest に 4:2:2:2 で分けて回します（`torso_split`）。
   - 首は Neck を回します。
   - 脚は腰の回転を、腕は胴体の回転を差し引いてから、太もも → すね → 足、上腕 → 前腕の順に回します。
   - 腕は少し横へ開いているので1回では合わないため、測り直して4回くり返します（最後の差は 0.3° 以下）。
3. 腰の高さを決めます。
   - `height: "toe"`（ダッシュ）: コマごとに、一番低いつま先がデータの高さになるようにします。しゃがむ・浮く・着地の高さがそのまま出ます。
   - `height: "hips"`（走り）: 腰の高さの動きをデータに合わせ、クリップ全体で一番低いつま先が 0.5cm になるよう全体を上下させます。走りでは両足が浮くコマがあり、`toe` だとそこで体ごと 15cm 跳ね上がったためです。

## 4. 使い方

### 同じ動画のまま、作り直す

```bash
T=$(cd Action/tools/UnrealScripts && pwd -W)
MSYS_NO_PATHCONV=1 "<UE_5.8>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "<空の>.uproject" -run=pythonscript \
  "-script=$T/adjust_bone_rotation.py $T/dash_roto.json" -unattended -nop4 -nosplash -NullRHI
```

ログは `%TEMP%/adjust_bone_rotation.txt` に出ます（`rotoscope pass 3 worst residual` が小さいことを確かめる）。そのあとゲームを1回起動すると `.tka` が作り直されます。

### 別の動画・別の場面から作る

1. `pip install mediapipe opencv-python-headless` を入れ、モデル `pose_landmarker_heavy.task` をダウンロードする（URL は `detect_pose.py` の先頭）。
2. 動画を1コマずつ見て、使う範囲（秒）と、キャラクターが入る切り出し範囲（ピクセル）を決める。
3. `python detect_pose.py 動画.mp4 33.30 30 pose.json 850 330 1700 980 pose_landmarker_heavy.task check.jpg` で読み取り、`check.jpg` で骨が体に重なっているか確かめる。
4. `python pose_to_angles.py pose.json angles.json` → `python clean_angles.py angles.json clean.json stick.jpg` で角度にして、棒人間の絵で確かめる。腕が上を通って回るなど、読み取りの乱れが残ったコマは `clean.json` を手で直す。
5. `clean.json` を `tools/UnrealScripts/` に置き、設定の `rotoscope.data`・`start`・`count`・`map` を書いて UE で流す。
6. ループさせる走りなどは、同じ形に戻るまでの1周期を選び、最後のコマを最初のコマと同じにする。

| ダッシュのあとの走りの始め | 左足で蹴ったあと f05、右足で蹴ったあと f12（ダッシュの最後と同じ足の形） | `Player.cpp` の `dashLToRunStartTime` など |
| 胴体の回し方の配分（腰・Spine・Chest・UpperChest） | 0.4・0.2・0.2・0.2 | `rotoscope.torso_split` |
| 直したコマ | 33.61・33.64秒の後ろの腕（読み取りでは上を通って回っていたので、下を通るように手で直した） | `genshin_dash_pose.json` |
| 走りの腕 | 読み取りの値を使わず、反対側の太ももの角度から作る。太もも -131°（後ろ）〜 -15°（前）を 0〜1 にして、上腕 = -165° + 120°×割合、肘の曲がり = 60° + 25°×割合（前へ振るほど曲げる） | `genshin_run_pose.json` の `aupper` など |
| ダッシュの着地の腕 | 33.78〜33.94秒の6コマで、読み取りの値から走りの腕の振り方へ 0.2・0.4・0.6・0.8・1・1 の割合で寄せる（ダッシュの最後と走りの始めの腕を合わせる） | `genshin_dash_pose.json` |

## 6. 決めたこと

### 角度を足して直すやり方をやめ、動画から作り直した（2026-11-06）

それまでのダッシュは、Run の骨の角度を足して形を作り、短いクリップ（しゃがみ・一蹴り・着地）を3本つないでいました。ゲームの録画を原神の動画と並べると、次のことがわかりました。

- しゃがみが1コマで終わって見えない
- 滑るポーズが止まった人形のように固まる
- 着地で一気に起き上がる
- しゃがみ込みのクリップの最初の数コマに Run の形が残り、かかとが跳ね上がる

角度を足すやり方では、つなぎ目と途中の形を細かく作り込めないので、動画から関節の角度を読み取って一から作るやり方に変えました。ダッシュは「しゃがむ → 蹴って低く滑る → 着地」を切り替えなしの1本にし、走りも原神の走りの1周期にしました。

| 候補 | 選ばなかった理由 |
|---|---|
| 角度を足すやり方のまま直し続ける | つなぎ目と途中の形が作れず、直すたびに別のところが不自然になった |
| Mixamo などのモーションをリターゲットする | 原神の動きとは違う。リターゲット用の UE プロジェクトもこのPCにない |
| 動画を見ながら手でポーズを打つ | 1コマずつ角度を目で読むのは時間がかかり、ぶれる。MediaPipe で読み取れば、乱れたコマだけ直せばよい |

## 7. 既知の課題

- **読み取りの乱れ**: 奥側の腕・脚は体に隠れるので、MediaPipe の読み取りが乱れることがあります。ならしても残る場合は手で直します。走りの腕は、ならすと振りが打ち消し合ってほとんど振れなかった（片方は -77〜-116° の間だけ、もう片方は同じ側の脚と同じ向き）ので、脚から作っています（「腕がちゃんと振れていない」とのこと、2026-11-06）。
- **ひねり・横の動きはない**: 横から見た平面の角度だけを合わせるので、腰や肩のひねり、腕の開きは元のクリップの1コマのままです。
- **髪・スカートは揺れない**: 揺れもの（`J_Sec_*`）は動かしていません。
- **体の比率の違い**: 原神のキャラクターと SK_Player の脚の長さの比が違うので、角度が同じでも足の位置は少しずれます。
