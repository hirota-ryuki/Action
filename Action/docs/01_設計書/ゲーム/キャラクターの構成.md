# キャラクターの構成

作成日: 2026-11-05（`キャラクター入力・魔法・弾の設計.md` から分割）
対象: `Game/Source/Objects/Player.*`、`Game/Source/Objects/Enemy.*`、`Game/Source/Character/CharacterMover.*`

Player と Enemy が、どの部品を持っていて、1フレームにどの順で呼ぶかをまとめたページです。
それぞれの部品の詳しいことは、下の「関連するページ」を見てください。

---

## 1. 方針

- **キャラクターは入力を受け取って動くだけ**: パッド・マウス・AIのことは知らない（[入力の設計](入力の設計.md)）。
- **継承より部品の組み合わせ**: Player と Enemy は別々のクラスのままにして、共通の処理は部品（コンポーネント）にし、両方に持たせる。
- **差し替えてデバッグできる**: 入力元を入れ替えれば、敵を手で操作したり、プレイヤーをAIで動かしたりできる。

### なぜ基底クラスを作らなかったか

- 基底クラスに処理を集めると、キャラクターの種類が増えるたびに大きくなりやすい
- 部品ごとに、単独で読める・直せる・確かめられる
- 味方NPCは `Enemy` の陣営を変えるだけで作れる。まったく別のキャラクターも、必要な部品を選んで持たせるだけで作れる

## 2. 全体像

```
 ┌──────────────── 入力元（IInputSource） ────────────────┐
 │  PlayerInputSource          NpcInputSource            │
 │  パッド・キーボード・マウス     AI（相手を探して追う・撃つ）  │
 └───────────────┬────────────────────┬──────────────────┘
                 │  CharacterInput（そのフレームの入力の値）  │
                 ▼                    ▼
        ┌──────────────┐      ┌──────────────┐
        │    Player    │      │    Enemy     │   ← 組み立て役。基底クラスはない
        └──────┬───────┘      └──────┬───────┘
               │                     │
     PlayerStateMachine              │   ← Player だけ。歩く・走るなどをステートで切り替える
               │                     │
   ┌───────────┬───┴───────┬───────────┬────────┴──────┐
   ▼           ▼           ▼           ▼               ▼
CharacterModel CharacterMover MagicCaster StatusEffects HitTarget
（見た目）     （移動）       （魔法）    （状態異常）   （当たり判定）
```

| 部品 | 役割 | ページ |
|---|---|---|
| `IInputSource` | そのフレームの入力（`CharacterInput`）を作る | [入力の設計](入力の設計.md) |
| `PlayerStateMachine` | Player の立ち止まる・歩く・走る・空中・ラッシュ・凍結の切り替え | [プレイヤーのステートの設計](プレイヤーのステートの設計.md) |
| `CharacterModel` | モデルとアニメーションの読み込み・描画 | [キャラクターモデルの設計](キャラクターモデルの設計.md) |
| `CharacterMover` | 移動・ジャンプ・重力・向き | このページの 4章 |
| `MagicCaster` | 魔法を持ち、切り替えて撃つ | [魔法と弾の設計](魔法と弾の設計.md) |
| `StatusEffects` | 凍結・燃焼 | [状態異常の設計](状態異常の設計.md) |
| `HitTarget` | 弾に当たる判定と陣営 | [陣営と当たり判定の設計](陣営と当たり判定の設計.md) |

### ファイル構成

```
Game/Source/
├── Character/          キャラクターの部品（入力・見た目・移動・状態異常・陣営・当たり判定）
├── PlayerState/        プレイヤーのステート
├── Magic/              魔法と弾
└── Objects/
    ├── Player.*        プレイヤー（部品の組み立て役）
    └── Enemy.*         敵・NPC（部品の組み立て役）
```

## 3. 1フレームの流れ

### Player

コード: [Player.cpp](../../../Game/Source/Objects/Player.cpp)（`Player::Update`）

```cpp
m_inputSource->Update(context, m_input);       // ① 入力をもらう
m_statusEffects.Update(deltaTime);              // ② 状態異常の時間を進める
m_stateMachine.Update(m_input, deltaTime);      // ③ ステートが動かす（凍結中は Frozen ステートになる）
m_magicCaster.Update(m_input, position, forward, deltaTime, m_statusEffects.CanAct());  // ④ 魔法
RespawnIfNeeded();                              // ⑤ 落ちたら戻す
m_hitTarget.SetPosition(m_mover.GetPosition()); // ⑥ 当たり判定の位置を合わせる
```

### Enemy

コード: [Enemy.cpp](../../../Game/Source/Objects/Enemy.cpp)（`Enemy::Update`）

Enemy は動きが少ない（立ち止まるか歩くだけ）ので、ステートを持たず、`CharacterMover::Update(input)` で入力どおりに動かします。

```cpp
m_inputSource->Update(context, m_input);
m_statusEffects.Update(deltaTime);
if (canAct) { m_mover.Update(m_input, deltaTime); UpdateAnimation(); }
else        { m_mover.Update(CharacterInput(), deltaTime); }   // 凍結中は空の入力で、重力だけ
m_magicCaster.Update(m_input, position, forward, deltaTime, canAct);
m_hitTarget.SetPosition(m_mover.GetPosition());
```

## 4. CharacterMover：移動

コード: [CharacterMover.h](../../../Game/Source/Character/CharacterMover.h)、[CharacterMover.cpp](../../../Game/Source/Character/CharacterMover.cpp)

`CharacterController` を包み、移動・ジャンプ・重力・向きを処理します。使い方が2通りあります。

| 使い方 | 関数 | 使っているところ |
|---|---|---|
| 入力どおりに動かす | `Update(input)`: 走る入力なら `runSpeedMultiplier` 倍、ジャンプボタンで跳ぶ | Enemy |
| 1つずつ操作する | `Move(水平の速度)`、`MoveByInput(input, 速さ)`、`Jump(初速)`、`FaceTo(向き)` | Player のステート |

どちらの使い方でも、1フレームに `Move` 系を1回だけ呼びます（重力はそこでかかります）。

向きの決め方（`MoveByInput`）: `lookDirection` の指定があればそちらを向き、なければ移動方向を向きます。

| 設定（`CharacterMoveSettings`） | Player | Enemy |
|---|---|---|
| `walkSpeed` | 300 | 140 |
| `runSpeedMultiplier` | 1.6 | 1.0（走れない） |
| `jumpSpeed` | 400 | 0（ジャンプできない） |
| `gravity` | 980 | 980 |
| カプセルの半径 / 高さ | 20 / 100 | 20 / 100 |

ラッシュは Player だけの動きなので、`CharacterMover` ではなく Player のステート（`PlayerRushState`）にあります。

## 5. それぞれのクラスに残っている処理

| クラス | 固有の処理 |
|---|---|
| [Player](../../../Game/Source/Objects/Player.h) | 使うモデルのデータ（`MakeModelDesc`）、剣を右手のボーンに追従させる処理、落下時のリスポーン（Y < -1000）、一人称で体を消す処理 |
| [Enemy](../../../Game/Source/Objects/Enemy.h) | 使うモデルのデータ（`MakeModelDesc`）、移動に合わせたアニメーションの切り替え、陣営の設定（`SetFaction`） |

モデルとアニメーションの読み込みは、どちらも `CharacterModel` に任せています（[キャラクターモデルの設計](キャラクターモデルの設計.md)）。

## 7. 既知の課題・今後

- **ダメージ・HPはまだない**: 入れるときは `HitTarget::SetOnHit` を使うか、`StatusEffects` の隣に体力の部品を足す想定です。
- **デバッグ表示は未実装**: `GetInput()` で受け取った入力を、`GetStateName()` で Player の今のステートを、`HitTargetRegistry::GetTargets()` で当たり判定の一覧を取得できるので、画面表示や `dbgVectorRenderer` での可視化を追加できます。
