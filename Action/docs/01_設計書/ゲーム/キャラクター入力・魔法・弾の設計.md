# キャラクター入力・魔法・弾の設計

作成日: 2026-11-05
ブランチ: `feature/character-input`

このドキュメントは、プレイヤーとNPCの入力を分け、魔法と弾の仕組みを作り直したときの設計をまとめたものです。
コードを読む前に全体像をつかむこと、新しい弾・魔法・NPCを追加するときの手引きにすることを目的にしています。

## 1. 何を解決したか

| 以前の問題 | 今の形 |
|---|---|
| Player が `g_pad` や `GetAsyncKeyState` を、移動・アニメーション・魔法の中で直接読んでいた | 入力元が `CharacterInput` を作り、キャラクターはそれを受け取って動くだけ |
| Enemy の中で、追跡するかの判断と移動処理が混ざっていた | 判断は `NpcInputSource`（AI）、移動は `CharacterMover` に分けた |
| IceMagic 1つのクラスに、飛ぶ処理・当たり判定・エフェクト・凍結が全部入っていた | 魔法（どう撃つか）、弾の基底クラス（共通処理）、氷の弾（氷に固有の部分）に分けた |
| 弾の当たり判定が `QueryGOs<Enemy>` の決め打ちで、敵にしか当たらなかった | 陣営と当たり判定の登録制にして、味方・中立・敵を同じように扱える |
| 敵は弾を撃てなかった | 敵も同じ仕組みで氷魔法を撃つ |

### 設計の方針

- **キャラクターは入力を受け取って動くだけ**: パッド・マウス・AIのことを知らない。
- **継承より部品の組み合わせ**: Player と Enemy は別のクラスのままで、共通の処理は部品（コンポーネント）にして両方に持たせる。
- **差し替えてデバッグできる**: 入力元を入れ替えれば、敵を手で操作したり、プレイヤーをAIで動かしたりできる。

## 2. 全体像

```

                 │  CharacterInput（そのフレームの入力の値）  │
                 ▼                    ▼
        ┌──────────────┐      ┌──────────────┐
        │    Player    │      │    Enemy     │   ← 組み立て役。基底クラスはない
        └──────┬───────┘      └──────┬───────┘

                 ▼                             │ 一覧から相手を探す
```

## 3. 1フレームの流れ

`Player::Update()` と `Enemy::Update()` はほぼ同じ流れです。

```cpp
// ① 入力をもらう
m_inputSource->Update(context, m_input);

// ② 状態異常の時間を進める
m_statusEffects.Update(deltaTime);
const bool canAct = m_statusEffects.CanAct();

// ③ 動く（凍結中は空の入力を渡し、重力だけがかかる）
if (canAct) { m_mover.Update(m_input, deltaTime); UpdateAnimation(); }
else        { m_mover.CancelRush(); m_mover.Update(CharacterInput(), deltaTime); }

// ④ 魔法（凍結中は撃てない）
m_magicCaster.Update(m_input, position, forward, deltaTime, canAct);

// ⑤ 当たり判定の位置を更新
m_hitTarget.SetPosition(m_mover.GetPosition());
```

コード: [Player.cpp](../../../Game/Source/Objects/Player.cpp)（`Player::Update`）、[Enemy.cpp](../../../Game/Source/Objects/Enemy.cpp)（`Enemy::Update`）

> **ポイント**: 凍結中は「空の入力」を渡すだけで止まります。`CharacterMover` は、凍結という状態があることを知りません。

## 4. 入力

コード: [CharacterInput.h](../../../Game/Source/Character/CharacterInput.h)

### 4.1 ButtonState：押した瞬間・押している・離した瞬間

```cpp
struct ButtonState {
    bool isTrigger;  // このフレームで押された
    bool isPress;    // 押されている
    bool isRelease;  // このフレームで離された

    void Update(bool isPressNow) {
        isTrigger = isPressNow && !isPress;
        isRelease = !isPressNow && isPress;
        isPress   = isPressNow;
    }
};
```

入力元は「今押しているか」を `Update()` に渡すだけです。あとの判定は前フレームの値から自動で決まります。
3つの状態があるので、長押しの魔法を追加しても入力元を変える必要がありません。

### 4.2 CharacterInput：キャラクターが受け取るもの

| メンバー | 意味 |
|---|---|
| `moveDirection` | 移動したい方向（**ワールド座標**のXZ）。長さ0〜1で速さの割合を表す |
| `lookDirection` | 向きたい方向。ゼロなら移動方向を向く |
| `isRun` | 走る |
| `jump` / `rush` / `fire` | ボタンの状態（ButtonState） |
| `magicSwitch` | -1: 前の魔法へ、+1: 次の魔法へ、0: 切り替えない |
| `hasAim` / `aimOrigin` / `aimDirection` | 照準。`hasAim` が false ならキャラクターの正面へ撃つ |

値だけの構造体なので、画面に表示したり、記録して再生したりしやすい形です。

### 4.3 IInputSource：入力元のインターフェース

```cpp
class IInputSource {
public:
    virtual void Update(const InputSourceContext& context, CharacterInput& input) = 0;
};
```

`InputSourceContext` は、入力元が操作対象について**知ってよい情報**だけをまとめたものです（自分自身、陣営、位置、正面の向き、経過時間、一人称かどうか）。
入力元はキャラクター本体に直接触れません。

### 4.4 PlayerInputSource：プレイヤーの入力元

コード: [PlayerInputSource.cpp](../../../Game/Source/Character/PlayerInputSource.cpp)

- デバイスを読む処理は**すべてここに**まとめてある
- スティックの値はカメラ基準なので、カメラの水平な前方向・右方向を使ってワールドの向きに変換する
- マウスのボタンは、ゲームのウィンドウが前面のときだけ反応する
- 一人称のときだけ、照準をカメラの位置と向きにする（`hasAim = true`）

### 4.5 NpcInputSource：NPCのAI

コード: [NpcInputSource.cpp](../../../Game/Source/Character/NpcInputSource.cpp)

AIも、プレイヤーと**同じ形の入力**を作るだけです。

```
敵対する相手を探す（HitTargetRegistry::FindNearestHostile）
  ├─ 見つからない → 何もしない
  └─ 見つかった
       ├─ 相手の方を向く（lookDirection）
       ├─ 停止距離より遠ければ近づく（moveDirection）
       └─ 射程内で、撃つ間隔が来ていたら発射ボタンを押す（fire）
            照準は相手の胸のあたり（hasAim = true）
```

AIは Player クラスを知りません。相手は当たり判定の一覧から陣営で探します。

### 4.6 入力元の差し替え

```cpp
// Player.h / Enemy.h
IInputSource* m_inputSource = &m_playerInputSource;  // 既定の入力元
void SetInputSource(IInputSource* inputSource);       // nullptr を渡すと既定に戻る
```

| やりたいこと | 書き方 |
|---|---|
| 敵を手で操作してデバッグする | `enemy->SetInputSource(&somePlayerInputSource);` |
| プレイヤーをAIで動かす | `player->SetInputSource(&someNpcInputSource);` |
| 元に戻す | `SetInputSource(nullptr);` |

## 5. キャラクター本体

Player と Enemy は**組み立て役**です。部品を持ち、毎フレーム順番に呼ぶだけです。
それぞれのクラスに残っているのは、**そのキャラクターにしかない処理**だけです。

| クラス | 固有の処理 |
|---|---|
| [Player](../../../Game/Source/Objects/Player.h) | モデルとアニメーション、剣をボーンに追従させる処理、落下時のリスポーン、一人称で体を消す処理 |
| [Enemy](../../../Game/Source/Objects/Enemy.h) | モデルとアニメーション、陣営の設定（`SetFaction`） |

### なぜ基底クラスを作らなかったか

- 基底クラスに処理を集めると、キャラクターの種類が増えるたびに肥大化しやすい
- 部品ごとに単独で読める・直せる・確かめられる
- 味方NPCは `Enemy` の陣営を変えるだけで作れる。まったく別のキャラクターを作るときも、必要な部品を選んで持たせるだけで済む

## 6. 部品

### 6.1 CharacterMover：移動

コード: [CharacterMover.cpp](../../../Game/Source/Character/CharacterMover.cpp)

`CharacterController` を包み、移動・ジャンプ・ラッシュ・重力・向きを処理します。性能は `CharacterMoveSettings` で決めます。

| 設定 | Player | Enemy |
|---|---|---|
| `walkSpeed` | 300 | 140 |
| `runSpeedMultiplier` | 1.6 | 1.0（走れない） |
| `jumpSpeed` | 400 | 0（ジャンプできない） |
| `rushDistance` | 300 | 0（ラッシュできない） |

向きの決め方: `lookDirection` の指定があればそちらを向き、なければ移動方向を向きます（ラッシュ中は移動方向を優先）。

### 6.2 StatusEffects：状態異常

コード: [StatusEffects.cpp](../../../Game/Source/Character/StatusEffects.cpp)

今は凍結だけです。もともと Enemy にあった処理を移しました。

- 凍った瞬間: モデルを水色にし、アニメーションを止める
- 解ける直前（0.4秒）: 元の色へなめらかに戻す
- 外には `CanAct()`（行動できるか）だけを伝える

部品にしたので、**プレイヤーも凍る**ようになりました。

### 6.3 Faction：陣営

コード: [Faction.h](../../../Game/Source/Character/Faction.h)

```
Player ─┐                ┌─ Enemy
        ├─ 敵対している ─┤
Ally ───┘                └─

Neutral … 誰とも敵対しない（弾も当たらない）
```

`IsHostile(a, b)` は、弾が当たるかとAIが狙うかの両方の判断に使います。

### 6.4 HitTarget / HitTargetRegistry：当たり判定と、その一覧

コード: [HitTarget.h](../../../Game/Source/Character/HitTarget.h)、[HitTarget.cpp](../../../Game/Source/Character/HitTarget.cpp)

```
HitTarget（キャラクターがメンバーとして持つ）
  Init() したとき     → 一覧に登録
  デストラクタ        → 一覧から登録を解除
  持ち主が削除待ち    → 当たらない

HitTargetRegistry（一覧）
  FindHitOnSegment()   弾の通り道に、敵対する相手がいるか（撃った本人は除く）
  FindNearestHostile() 一番近い敵対する相手（AIの索敵）
  GetTargets()         全件（デバッグ表示用）
```

当たったときの効果を受ける窓口は2つあります。

| 窓口 | 用途 |
|---|---|
| `SetStatusEffects()` | 弾が状態異常（凍結など）をかける先 |
| `SetOnHit()` | 当たったことを持ち主に知らせる処理（ひるみ・反撃など、今後用） |

当たり判定は「弾の半径 + 相手の半径」の球で判定します。

| | 半径 | 足元からの中心の高さ |
|---|---|---|
| Player | 45 | 70 |
| Enemy | 45 | 60 |
| 氷の弾 | 10 | - |

## 7. 魔法と弾

**魔法 =「どう撃つか」**、**弾 =「飛んで当たる物」** と役割を分けています。
こうすると、長押しの魔法を追加しても弾の側は変わりません。

```
MagicCaster ──ボタンの状態に応じて呼ぶ──▶ MagicBase（IceMagic など）
                                              │ 生成する
                                              ▼
                                         BulletBase（IceBullet など）
```

### 7.1 MagicBase：魔法の基底クラス

コード: [MagicBase.h](../../../Game/Source/Magic/MagicBase.h)

| 関数 | 呼ばれるとき |
|---|---|
| `OnPress` | 発射ボタンを押した瞬間 |
| `OnHold` | 押している間、毎フレーム（押した瞬間のフレームも含む） |
| `OnRelease` | 離した瞬間 |
| `OnCancel` | 押している途中で中断されたとき（凍結した、魔法を切り替えた） |

撃ち方の違いは、どの関数を上書きするかで表します。

| 撃ち方 | 上書きする関数 |
|---|---|
| 単発（今の氷魔法） | `OnPress` で撃つ |
| 溜め撃ち | `OnHold` で溜めて、`OnRelease` で撃つ。`OnCancel` で溜めを捨てる |
| 出し続ける | `OnHold` の間ずっと出す |

クールダウンは `StartCooldown()` / `IsReady()` で管理します。

### 7.2 MagicCaster：魔法の所持・切り替え・発射

コード: [MagicCaster.cpp](../../../Game/Source/Magic/MagicCaster.cpp)

```
毎フレーム:
  全部の魔法のクールダウンを進める
  行動できない（凍結中など）→ 押している途中なら OnCancel して終わり
  magicSwitch があれば魔法を切り替える（押している途中なら OnCancel）
  fire が押された瞬間      → OnPress
  fire を押している間      → OnHold
  fire が離された瞬間      → OnRelease
```

撃つ位置と向きの決め方:
- `hasAim` が true なら、入力の `aimOrigin` / `aimDirection`
- false なら、足元から `castHeight` の高さ、キャラクターの正面（水平）
- どちらの場合も、自分のカプセルに当たらないよう `castForward` だけ前に出す

### 7.3 IceMagic：氷魔法

コード: [IceMagic.cpp](../../../Game/Source/Magic/IceMagic.cpp)

`OnPress` で、使える状態なら `IceBullet` を1発生成し、クールダウン（0.35秒）を始めます。それだけです。

### 7.4 BulletBase：弾の基底クラス

コード: [BulletBase.h](../../../Game/Source/Magic/BulletBase.h)、[BulletBase.cpp](../../../Game/Source/Magic/BulletBase.cpp)

共通の流れは基底クラスにあり、派生クラスから変えられないように `final` にしています。

```
Flying（飛翔中）
  毎フレーム、今の位置 → 次の位置 の線分で調べる
    ① 敵対する相手に当たった → NotifyHit → OnHitTarget → 着弾
    ② 地形に当たった（レイ判定） → 着弾
    ③ 射程を超えた               → 空中で着弾
    ④ どれでもない               → 進んで OnMove
        │
        ▼ 着弾（OnExplode）
Vanishing（演出待ち）
  IsVanishFinished() が true になったら自分を削除
```

派生クラスが書くのは次の5つの関数だけです。

| 関数 | 書くこと |
|---|---|
| `OnStart()` | エフェクトやモデルの読み込み。失敗したら false を返すとすぐ削除される |
| `OnMove()` | 位置が変わったとき、見た目を合わせる |
| `OnHitTarget()` | 敵対する相手に当たったときの効果 |
| `OnExplode()` | 着弾の演出（相手・地形・射程切れのすべてで呼ばれる） |
| `IsVanishFinished()` | 着弾後の演出が終わったか |

弾の性能は `BulletSettings`（速さ、射程、半径）で決めます。
`owner`（撃った本人）は削除済みになっていることがあるので、**比較にだけ使い、中身には触れません**。

### 7.5 IceBullet：氷の弾

コード: [IceBullet.cpp](../../../Game/Source/Magic/IceBullet.cpp)

以前の `IceMagic` の中身のうち、氷に固有の部分だけが残っています。

| 関数 | やっていること |
|---|---|
| `OnStart` | `ice_bullet.efk` と `ice_hit.efk` を読み込み、弾のエフェクトを再生する |
| `OnMove` | エフェクトのルートだけを動かす（軌跡は発生した場所に残る） |
| `OnHitTarget` | 相手の `StatusEffects` を2.5秒凍らせる |
| `OnExplode` | 弾本体を消し、着弾エフェクトを再生する |
| `IsVanishFinished` | 軌跡と着弾エフェクトが両方消えたか |

### 7.6 後片付け

弾は `BulletBase::kObjectName`（`"bullet"`）という名前で生成されます。
[Game.cpp](../../../Game/Source/Core/Game.cpp) のデストラクタで、この名前の弾を種類を問わずまとめて削除します。

## 8. 拡張のしかた

### 新しい弾を作る（例: 炎の弾）

```cpp
class FireBullet : public BulletBase {
public:
    FireBullet() : BulletBase(MakeSettings()) {}   // 速さ・射程・半径を決める
protected:
    bool OnStart() override;                        // エフェクト読み込み
    void OnMove() override;                         // 見た目を位置に合わせる
    void OnHitTarget(HitTarget& target, const Vector3& pos) override;  // 命中時の効果
    void OnExplode(const Vector3& pos) override;    // 着弾演出
    bool IsVanishFinished() const override;         // 演出が終わったか
};
```

新しいエフェクトを使うときは、[EffectId.h](../../../Game/Source/Core/EffectId.h) に番号を追加します。

### 長押しの魔法を作る（例: 溜め撃ち）

```cpp
class ChargeMagic : public MagicBase {
    float m_charge = 0.0f;
public:
    const char* GetName() const override { return "ChargeMagic"; }
    void OnHold(const MagicCastContext& c) override    { m_charge += c.deltaTime; }
    void OnRelease(const MagicCastContext& c) override { /* m_charge に応じて弾を撃つ */ m_charge = 0.0f; }
    void OnCancel() override                           { m_charge = 0.0f; }
};

// キャラクターの Start() で
m_magicCaster.AddMagic(std::make_unique<ChargeMagic>());
```

魔法が2つ以上になれば、Q/E キーやパッドの LB/RB で切り替えられます。

### 味方・中立のNPCを作る

```cpp
Enemy* ally = NewGO<Enemy>(1, "ally");
ally->SetFaction(Faction::Ally);     // 敵を狙い、敵の弾が当たる
```

撃たせたくないときは、`NpcInputSource::Settings::canFire = false` にします。

### 新しい状態異常を作る（例: 毒）

`StatusEffects` に、凍結と同じ形で追加します（タイマー、かける関数、`Update` での処理）。
行動を止めるものなら `CanAct()` の条件にも含めます。

### 拡張先の早見表

| やりたいこと | 触る場所 |
|---|---|
| 新しい弾 | `BulletBase` を継承する |
| 新しい撃ち方 | `MagicBase` を継承し、`AddMagic` で持たせる |
| 味方・中立のNPC | `Enemy::SetFaction` |
| AIの動き方 | `NpcInputSource`、または新しい `IInputSource` を作る |
| 状態異常 | `StatusEffects` |
| 敵対関係のルール | `Faction.h` の `IsHostile` |
| 操作の割り当て | `PlayerInputSource.cpp` |

## 9. 操作の割り当て

| 操作 | キーボード・マウス | パッド |
|---|---|---|
| 移動 | WASD | 左スティック |
| 走る | 左Shift | - |
| ジャンプ | J | A |
| ラッシュ | L | X |
| 発射 | マウス左ボタン / I | Y |
| 魔法の切り替え | Q / E | LB / RB |
| 視点の切り替え（GameCamera） | K | B |

> パッドが接続されていないときは、エンジンがパッドのボタンをキーボードで代用します（A=J、X=L、Y=I など）。

## 10. 調整用の数値

| 内容 | 値 | 場所 |
|---|---|---|
| 氷魔法の連射間隔 | 0.35秒 | `IceMagic` のコンストラクタ引数 |
| 氷の弾の速さ / 射程 | 1500 / 2000 | `IceBullet.cpp` の `MakeSettings` |
| 凍結時間 | 2.5秒 | `IceBullet.cpp` の `kFreezeSeconds` |
| 敵が相手を探す範囲 | 900 | `Enemy.cpp` の `MakeAiSettings` |
| 敵が止まる距離 | 90 | 同上 |
| 敵が撃つ射程 / 間隔 | 700 / 4秒 | 同上 |
| 敵が相手を見つけてから最初に撃つまで | 1.5秒 | 同上 |

> 敵が撃つ間隔（4秒）を凍結時間（2.5秒）より長くしているのは、プレイヤーが凍らされ続けないようにするためです。

## 11. 既知の課題・今後

- **ダメージ・HPはまだない**: 今回は入れていません。入れるときは `HitTarget::SetOnHit` を使うか、`StatusEffects` の隣に体力の部品を足す想定です。
- **三人称で弾が飛ぶ向き**: 動作確認のとき、キャラクターがカメラの方を向いているのに、弾はカメラから遠ざかる方向へ飛んでいました。モデルの見た目の向きと `GetForward()` が逆になっている可能性があります。今回の変更より前からある動きです。
- **ウィンドウを前に出すクリックでも撃つ**: ゲームのウィンドウが裏にあるとき、左クリックで前に出すと、そのクリックでも1発出ます。
- **デバッグ表示は未実装**: `GetInput()` で受け取った入力を、`HitTargetRegistry::GetTargets()` で当たり判定の一覧を取得できるので、画面表示や `dbgVectorRenderer` での可視化を追加できます。
- **入力の記録・再生は未実装**: `CharacterInput` は値だけの構造体なので、記録した入力を流し直す `IInputSource` を作れば、バグを同じ条件で再現できます。
