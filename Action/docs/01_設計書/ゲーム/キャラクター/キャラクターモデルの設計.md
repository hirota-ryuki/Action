# キャラクターモデルの設計

作成日: 2026-11-06
対象: `Game/Source/Character/CharacterModel.*`

Player と Enemy のモデル・アニメーションを読み込む共通の部品 `CharacterModel` のページです。
ほかの部品との関係は [キャラクターの構成](キャラクターの構成.md) を見てください。

- **キャラクターが持つのはデータだけ**: どのモデル・アニメーションを使うかを `CharacterModelDesc` に書いて渡す。
- **読み込みの決まりは部品の中に閉じ込める**: FBX の変換・リターゲット・「クリップを先に読む」は `CharacterModel` だけが知っている。

---

## 1. 全体像

```
Player / Enemy
  │ Start(): m_model.Init(MakeModelDesc())   ← Desc は各キャラクターの .cpp に書いたデータ
  ▼
CharacterModel ── 持つ ──▶ ModelRender ◀── 参照: StatusEffects（色）・ステート（アニメーション）・剣（ボーン）
  │
  └─ Init のときだけ使う ─▶ FbxRuntimeImporter（FBX → tkm / tks / tka）
```

---

## 2. CharacterModelDesc：キャラクターごとのデータ

| 項目 | 内容 | Player | Enemy |
|---|---|---|---|
| `modelPath` | `.tkm` か `.fbx` | `SK_Player.FBX` | `unityChan.tkm` |
| `upAxis` | モデルの上方向 | Z（3ds Max） | Y |
| `scale` | 大きさ | 1.128 | 1.08 |
| `clips` | クリップの一覧。**添字がクリップの番号** | 4つ（Idle・Walk・Run の FBX。Jump は暫定で Run） | idle・run の tka |

---

## 3. CharacterModel：関数

コード: [CharacterModel.h](../../../../Game/Source/Character/CharacterModel.h)、[CharacterModel.cpp](../../../../Game/Source/Character/CharacterModel.cpp)

| 関数 | 呼ぶとき | 内容 |
|---|---|---|
| `Init(desc)` | `Start()` で1回 | クリップを読み込み、モデルを初期化する |
| `SetTransform(位置, 回転)` | 毎フレーム | 大きさは Desc のもの |
| `Update()` / `Draw(rc)` | 毎フレーム | `ModelRender` にそのまま渡す |
| `PlayAnimation(番号, 補間秒)` | アニメーションを変えるとき | 番号は `clips` の添字 |
| `GetModelRender()` | ほかの部品に渡すとき | アニメーション速度・ボーン・状態異常の色など |

## 4. 実装方法

### Init の流れ

```cpp
void CharacterModel::Init(const CharacterModelDesc& desc)
{
    m_scale = Vector3(desc.scale, desc.scale, desc.scale);
    m_animClips = std::make_unique<AnimationClip[]>(numClips);   // ① クリップの入れ物

    std::string tksPath;
    for (int i = 0; i < numClips; i++) {
        std::string tkaPath = desc.clips[i].path;
        if (EndsWithFbx(tkaPath)) {                                // ② FBX なら変換
            if (tksPath.empty()) {
                tksPath = ToTksPath(FbxRuntimeImporter::ResolveToTkmFilePath(desc.modelPath));
            }
            tkaPath = FbxRuntimeImporter::ResolveAnimationFbxToTka(desc.clips[i].path, tksPath.c_str());
        }
        if (tkaPath.empty()) { continue; }                         //    変換に失敗したクリップは飛ばす
        m_animClips[i].Load(tkaPath.c_str());                      // ③ 読む
        m_animClips[i].SetLoopFlag(desc.clips[i].isLoop);
    }
    m_modelRender.Init(desc.modelPath, m_animClips.get(), numClips, desc.upAxis);  // ④ 最後にモデル
}
```

| 書き方 | 理由 |
|---|---|
| クリップの入れ物を `unique_ptr<AnimationClip[]>` で確保する | `ModelRender` がクリップの配列を指し続けるので、あとで動かない入れ物にする（`vector` は伸びると場所が変わる）。数は Desc で決まる |
| FBX かどうかは拡張子（大文字小文字を区別しない）で見分ける | Desc にフラグを足さずに済む。パスを書くだけでリターゲットされる |
| スケルトンの変換は、最初に FBX のクリップが来たときに1回だけ | tka しか使わないキャラクター（Enemy）では変換しない |
| `.tks` のパスは tkm の拡張子を差し替えて作る | FBX→tkm 変換が同じフォルダ・同じ名前で `.tks` を作る決まりなので |
| モデルの Init は最後 | `ModelRender::Init` が中で 0 番のクリップを再生するので、先にクリップを読んでおく必要がある |

変換結果は更新日時でキャッシュされるので、同じ FBX を何度渡しても変換は1回です（Player は Run と Jump の枠に同じ run を入れています）。

### 大きさは Init で決めておく

`SetTransform()` は `SetTRS(位置, 回転, m_scale)` を呼ぶだけです。大きさは毎フレーム変わらないので、持ち主は位置と回転だけを渡します。

## 5. 使い方

| やりたいこと | すること |
|---|---|
| 新しいキャラクターにモデルを持たせる | `CharacterModel` をメンバーにし、`.cpp` に `MakeModelDesc()` を書いて `Start()` で `Init` する |
| アニメーションを足す | クリップ番号の enum に足し、`MakeModelDesc()` の `clips` に1行足す。FBX ならパスを書くだけでリターゲットされる |
| Player に新しいモーションを入れる | UE で SK_Player にリターゲットした FBX を作る（[プレイヤーのアニメーションの設計](../アニメーション制作/プレイヤーのアニメーションの設計.md)）。そのあと Player の `MakeModelDesc()` で、その番号にパスを入れる |

```cpp
// Enemy.cpp
CharacterModelDesc MakeModelDesc()
{
    CharacterModelDesc desc;
    desc.modelPath = "Assets/modelData/unityChan.tkm";
    desc.upAxis = enModelUpAxisY;
    desc.scale = 1.08f;
    desc.clips.resize(Enemy::enAnimClip_Num);
    desc.clips[Enemy::enAnimClip_Idle] = { "Assets/animData/idle.tka", true };
    desc.clips[Enemy::enAnimClip_Run] = { "Assets/animData/run.tka", true };
    return desc;
}
```

## 6. 決めたこと

### プレイヤー専用のクラスにしなかった

`PlayerModel` を作ると、コードの置き場所が変わるだけで、使うのは Player だけになります。
Enemy も同じ読み込み方（クリップを読む → `ModelRender::Init`）をしていたので、汎用の部品にして、違い（パス・向き・大きさ）をデータにしました。

### Init は持ち主が呼ぶ

ほかの部品と同じく、Player・Enemy が自分の `Start()` で呼びます。`NewGO` は引数を取れないので、外から Desc を渡すには `Start()` より前に Setter を呼ぶしかなく、呼び忘れに気づきにくいためです。

---

## 7. 既知の課題

- **Player の Jump はまだ run**: SK_Player 用のジャンプのモーションがないので、Jump の枠に run を入れています。
- **見た目の差し替え（キャラクター選択など）はできない**: 必要になったら、`MakeModelDesc()` の中身を外から渡す形にします。
