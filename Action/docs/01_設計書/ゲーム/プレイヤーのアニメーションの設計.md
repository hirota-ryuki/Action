# プレイヤーのアニメーションの設計

作成日: 2026-11-06
対象: `Game/Assets/modelData/player/Animation/`、`tools/UnrealScripts/`、Player の `MakeModelDesc()`・`MakeStateSettings()`

プレイヤー（SK_Player、VRM のモデル）のモーションを、どこから持ってきて、どうやってゲームで使える形にしているかのページです。
読み込みの仕組みは [キャラクターモデルの設計](キャラクターモデルの設計.md)、どのステートでどのモーションを流すかは [プレイヤーのステートの設計](プレイヤーのステートの設計.md) を見てください。

- **リターゲットは UE で行い、ゲームには SK_Player の骨格になった FBX だけを置く**: エンジンはボーン名が完全に一致したものを丸ごとコピーするだけなので、骨格の違いはゲームの外で解決する。
- **UE の作業はスクリプトにして、コマンドラインで流す**: モーションを足すたびに、エディターで手作業をしなくて済む。
- **歩くモーションは、足が地面を送る速さに合わせて再生速度を変える**: 足が地面の上を滑らないようにする。

## 1. 全体像

```
Mixamo など（元のモーション。骨格は mixamorig:* など）
  │ ダウンロード（D:\04_dawnload\mixamo\）
  ▼
UE 5.8「AssetMigrate_Combat 5.8 - 2」 ← tools/UnrealScripts/retarget_to_player.py をコマンドラインで実行
  │ ① FBX を読み込む  ② 元の骨格の IK Rig を自動で作る
  │ ③ IK_Player_Mannequin（SK_Player 用）へリターゲット  ④ FBX で書き出す
  ▼

  ▼
Game/Assets/modelData/player/Animation/〇〇.fbx（SK_Player と同じ 247 本のボーン）
  │ 起動時に FbxRuntimeImporter が .tka へ変換（キャッシュ）
  ▼
Player の MakeModelDesc() の clips → ステートが PlayAnimation(番号, 再生速度)
```

## 3. 実装方法

### UE のプロジェクトに用意してあるもの

| 資産 | 内容 |
|---|---|
| `/Game/01_PlayerVRM/SK_Player` | VRM4U で読み込んだプレイヤーのモデル。ゲームの `SK_Player.FBX` はここから書き出したもの |
| `/Game/01_PlayerVRM/IK_Player_Mannequin` | リターゲット先の IK Rig。チェーン名は UE のマネキン式（Spine・LeftArm など）、手足に IK ゴールがある |
| `/Game/04_Retarget/<作業名>/` | スクリプトが作る資産（元のモデル・元の IK Rig・リターゲッター・結果のアニメーション） |

### retarget_to_player.py の流れ

コード: [retarget_to_player.py](../../../tools/UnrealScripts/retarget_to_player.py)

| 手順 | 使う API | 書き方の理由 |
|---|---|---|
| 元のモデル（Y Bot）を読み込む | `AssetImportTask` + `FbxImportUI`（スケルタルメッシュ） | アニメーションだけの FBX には骨格の基準がないので、スキン付きのモデルを先に読む |
| モーションを読み込む | 同上（アニメーション、`skeleton` に元の骨格） | 長さは FBX に書かれた範囲。キーは間引かない |
| 元の IK Rig を作る | `IKRigController.apply_auto_generated_retarget_definition()`・`apply_auto_fbik()` | Mixamo やマネキンは UE が骨格を見分けて、チェーンを自動で作れる |
| リターゲッターを作る | `IKRetargeterController`：`add_default_ops()`・`auto_map_chains(FUZZY)` | 元と先でチェーン名がほぼ同じなので、名前の近さで対応づけられる |
| ポーズを合わせる（必要なときだけ） | `create_retarget_pose()`・`auto_align_all_bones(SOURCE)` | 元が A ポーズ（UE4 マネキン）のとき。Mixamo と VRM はどちらも T ポーズなので不要 |
| リターゲットする | `IKRetargetBatchOperation.run_batch_retarget()` | 5.8 では `duplicate_and_retarget` が非推奨になった |
| FBX で書き出す | `AnimSequenceExporterFBX` + `FbxExportOption`（`export_preview_mesh = False`） | メッシュを含めず、骨格とアニメーションだけにする。Run と同じ形（AnimStack 名は `Unreal Take`）になる |

作った IK Rig とリターゲッターは、2回目以降は作り直さずに使い回します。UE では、読み込み済みの資産を消してから同じ名前で作ろうとすると失敗するためです。

### adjust_bone_rotation.py の流れ（姿勢を少し直す）

コード: [adjust_bone_rotation.py](../../../tools/UnrealScripts/adjust_bone_rotation.py)、設定: [walk_upright.json](../../../tools/UnrealScripts/walk_upright.json)（Walk を起こす）、[run_pelvis.json](../../../tools/UnrealScripts/run_pelvis.json)（Run の骨盤を起こす）、[dash_lean.json](../../../tools/UnrealScripts/dash_lean.json)（Run から前へ倒した一蹴り DashL / DashR を作る）

リターゲットの結果に、指定したボーンを前後に傾ける角度を、全フレーム同じだけ足します。リターゲットポーズを直すのと同じ効果です。
リポジトリにある `SK_Player.FBX` とアニメーションの FBX だけで動くので、元のモーションやリターゲット用の UE プロジェクトがない PC でも使えます（UE のプロジェクトは空のものでよい）。

| 手順 | 使う API | 書き方の理由 |
|---|---|---|
| `SK_Player.FBX` と直したい FBX を読み込む | `AssetImportTask` + `FbxImportUI` | retarget_to_player.py と同じ |
| 左右の軸を決める | `AnimPoseExtensions.get_reference_pose` で T ポーズのかかと→つま先 | モーション中は足が開いていて、つま先の向きが前とずれる |
| 全フレームの元の値を読む | `get_anim_pose_at_frame`（RAW）・`get_bone_pose`（LOCAL と WORLD） | 先に全部読んでから書く。書きながら読むと、あとのフレームの値が変わる |
| ローカルの回転に角度を足す | 親の向き = 自分のワールドの向き × ローカルの向きの逆。左右の軸を親の向きで見た軸に直し、その軸まわりの回転をローカルの回転の前に掛ける | 親も同じ軸で回しているので、親の補正と子の補正がそのまま足し算になる |
| 振り幅を変える（`swing_scale`、省略可） | 全フレームの回転の平均（向きをそろえて足して正規化）を中心に、そこからの回転の角度を k 倍する | 角度を足す前にかける。足の振りを大きくして、蹴り足を後ろへ伸ばす |
| コマを切り出す（`clips[].frames`、省略可） | `set_number_of_frames` でコマ数を変え、残すコマの全ボーンのキーを `set_bone_track_keys` で書き直す。`hold` を書くと最後のコマをその数だけくり返して足す | ループのクリップは最後のコマが最初と同じ姿勢なので、最後のコマを飛ばして先頭へ戻る（例: 10〜17・0・1） |
| 足を地面に合わせる（`keep_feet_on_ground`、省略可） | 書き換えたあと、全フレームでのつま先の一番低い高さを元と比べ、その差だけ腰（Hips）をワールドの上下に動かす | 脚ごと倒すと足が浮いたり沈んだりするため |
| 決めたポーズへ寄せる（`clips[].pose_to`、省略可） | 最後のコマで、太もも・すね・足・上腕・前腕の向き（ボーン→子のボーンの線の角度）が目標になるよう、左右の軸まわりの角度を求める。`ramp_start` のコマから最後のコマ（`ramp_end` を書けばそのコマ。あとはそのまま）へ smoothstep で寄せる。腰は `lift_ramp_start` のコマから `lift_cm` 上下させる（負なら下げる） | 親から順に「目標との差 − 親に足した分」を足す。腕は横へ少し開いているので1回では合わず、測り直して3回くり返す。`ground_toe_cm` を書くと、`lift_cm` の代わりに、最後のコマで一番低いつま先がその高さになるよう腰を上下させる（しゃがんで両足を地面に着けるとき） |
| 膝が反らないようにする（`pose_to` の中） | すべてのコマで「太ももの向き − すねの向き」（膝の曲がり）を測り、`min_knee_deg`（3°）より小さいコマは、すねをその分だけ曲げる | 伸ばす補正を途中のコマにも割合で足すので、もともと伸び気味のコマで膝が伸び切りを越える |
| 膝を曲げて腰を落とす（`clips[].crouch`、省略可） | コマごとの割合 `weights` × `lower_cm` だけ腰を下げ、両足とも足首の位置が元のままになるよう、太もも・すねの向きを2本の骨の IK（余弦定理、膝は前へ）で決める。足（Foot）は太もも・すねを回した分を逆に回し、地面に対する向きを元のままにする | 足を動かさずに膝だけ曲がる。足を逆に回さないと、つま先が地面にめり込む |
| コマごとの形を書き出す（`clips[].log_frames`、省略可） | コマごとに、腰の高さ、太もも・すね・足の向き、膝の曲がり、足首の前後、つま先の高さ、腕の向きをログに出す。`out_skip` を書くと FBX を書き出さない | 目標の角度を決めるとき、元のコマの形を測るため |
| 別のクリップのポーズから始める（`clips[].blend_from`、省略可） | 同じ実行で先に作ったクリップの最後のコマのポーズを、最初のコマから `weights` の割合で混ぜる（全ボーンのローカルの回転と位置）。混ぜたコマで、つま先が `ground_toe_cm`（0.5cm）より下なら、その分だけ腰を上げる | しゃがんだポーズから一蹴りへ、ゲームの補間に頼らずなめらかにつなぐため |
| しゃがみ込みのあとに腰をさらに落とす（`clips[].crouch_after_pose`） | `crouch` を `pose_to` のあとにかける | 決めたしゃがみのポーズから、足を動かさずにもう少し沈むため |
| クリップごとの上書き | `clips[]` に `pitch_deg`・`swing_scale`・`keep_feet_on_ground` を書くと、そのクリップだけ全体の設定の代わりに使う | 着地は飛ぶところほど倒さないため |
| キーを書き戻して FBX で書き出す | `AnimationDataController.set_bone_track_keys`、`AnimSequenceExporterFBX` | 書き出しの設定は retarget_to_player.py と同じ |

ログの `shape` の行には、全フレームの平均で「上半身（腰→首）の前傾」「脚（両足の真ん中→腰）の前傾」「その差＝体の折れ」「つま先の一番低い高さ」が出ます。体の折れが大きいほど、腰で「く」の字に曲がってお尻が突き出て見えます。

UE の Python の `Quat` には逆・回転の関数が無いものがあるので、クォータニオンの計算はスクリプトの中に書いています。

### 歩くモーションの再生速度

```cpp
// PlayerWalkState.h
float GetAnimSpeed(const PlayerStateContext& context) const override
{
    const float animMoveSpeed = context.settings.walkAnimMoveSpeed;
    if (animMoveSpeed <= 0.0f) {
        return 1.0f;
    }
    return GetMoveSpeed(context) / animMoveSpeed;
}
```

- `walkAnimMoveSpeed` は、Walk を等速で再生したときに、接地している足が後ろへ動く速さです（ゲームの単位）。
- [measure_foot_speed.py](../../../tools/UnrealScripts/measure_foot_speed.py) で UE の値（114.7 cm/秒）を測り、モデルの大きさ 1.128 を掛けて 130 にしました。
- 測るときは、接地しているフレーム間の速さの**中央値**を使います。平均にすると、かかとが着く瞬間やつま先が離れる瞬間の遅いフレームに引っぱられて、108 と小さく出ます。

## 4. 使い方

### モーションを差し替える・足す（Mixamo の場合）

1. Mixamo から次の2つをダウンロードし、`D:\04_dawnload\mixamo\` に置く。
   - キャラクター「Y Bot」：FBX Binary・T-pose
   - モーション：FBX Binary・Without Skin・30fps・Keyframe Reduction は none。移動するモーションは **In Place** にチェックを入れる
2. [mixamo_idle_walk.json](../../../tools/UnrealScripts/mixamo_idle_walk.json) の `clips` に `{"name": "書き出す名前", "fbx": "元のFBX"}` を足す。`export_dir` はゲームの `Animation/` フォルダ。
3. UE のエディターを閉じてから、コマンドラインで実行する。Git Bash から実行するときは、`/Game/...` が Windows のパスに書き換えられないよう `MSYS_NO_PATHCONV=1` を付ける。

   ```bash
   # Git Bash
   T=D:/02_git/01_my/01_Action/Action/tools/UnrealScripts
   MSYS_NO_PATHCONV=1 "D:/01_software/13_UnrealEngine/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" \
     "D:/03_data/AssetMigrate_Combat 5.8 - 2/AssetMigrate_Combat.uproject" -run=pythonscript \
     "-script=$T/retarget_to_player.py $T/mixamo_idle_walk.json" \
     -unattended -nop4 -nosplash -NullRHI
   ```

4. `log` に書いたファイルの最後が `DONE` になっていることを確かめる。
5. 新しいクリップなら `EnPlayerAnimClip` に番号を足し、Player の `MakeModelDesc()` にパスを書く。
6. ゲームを1回起動すると `.tka` ができる。`.fbx` と `.tka` の両方をコミットする。

### 姿勢を少し直す（上半身がのけぞる・前かがみになる など）

1. 設定の JSON（例: [walk_upright.json](../../../tools/UnrealScripts/walk_upright.json)）の `pitch_deg` に、ボーンと角度（度、正が前に倒す）を書く。パスは JSON からの相対パスで書ける。
2. 空の UE プロジェクト（`{"FileVersion":3,"EngineAssociation":"5.8"}` だけの `.uproject` でよい）を用意して、コマンドラインで実行する。

   ```bash
   # Git Bash
   T=<リポジトリ>/Action/tools/UnrealScripts
   MSYS_NO_PATHCONV=1 "<UE_5.8>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "<空の>.uproject" -run=pythonscript      "-script=$T/adjust_bone_rotation.py $T/walk_upright.json" -unattended -nop4 -nosplash -NullRHI
   ```

3. `%TEMP%djust_bone_rotation.txt` の最後が `DONE` になっていることを確かめる。`before` / `after` の行に、0フレーム目で頭が腰より何 cm 前にあるかと、腰→頭の線の前傾の角度（`lean(deg)`、まっすぐ立って 0°）が出る。
4. ゲームを1回起動して `.tka` を作り直し、`.fbx` と `.tka` の両方をコミットする。`MaxData/player/model/` の控えも差し替える。

**`in` と `out` が同じファイルなので、実行するたびに角度が足されていきます。** Walk をリターゲットし直したときに、1回だけ実行してください。
`dash_lean.json` は `in`（Run）と `out`（DashL / DashR）が別のファイルなので、角度を変えて何度実行しても足されません。Run を差し替えたときは、`run_pelvis.json` → `dash_lean.json` の順に流し直してください。

### 歩く速さを変える

`MakeMoveSettings()` の `walkSpeed` を変えるだけです。再生速度は自動で合います。
ただし、1.0 から大きく離れる（目安として 0.7〜1.5 の外）と、早送りやスローに見えます。そのときは、モーション自体を速い歩きのものに替えてください。

### 歩くモーションを替えたとき

`measure_foot_speed.py <AnimSequence のパス> <結果の txt>` で足の速さを測り、`× 1.128` した値を `MakeStateSettings()` の `walkAnimMoveSpeed` に入れます。

## 6. 決めたこと

### モーションは Mixamo から持ってくる

原神のような「軽くて女性らしい歩き」「穏やかに呼吸する待機」に近いものが、無料で手に入るためです。

| 候補 | 選ばなかった理由 |
|---|---|
| UE の Game Animation Sample | 品質は高いが、リアル寄りでアニメ調ではない |
| UE4 マネキンの Idle・Walk（プロジェクトにある） | 硬くて男性的。リターゲットの手順を試すのにだけ使った |
| Basic Motions FREE（Unity） | 汎用的で癖がない。以前 FBX にしたときにアニメーションが抜けていた |

### 歩く速さを 300 から 170 に下げた（2026-11-06）

Female Walk を等速で再生すると、足が地面を送る速さは約130でした。300 のままだと約2.3倍で再生することになり、早送りのように見えます。
そこで、原神の歩きに近い落ち着いた速さ（170、約1.3倍で再生）にしました。走る速さは以前と同じ 480 です。

### 起動直後に T ポーズになるエンジンの不具合を直した（2026-11-06）

`Animation::PlayCommon`（[Animation.h](../../../k2EngineLow/graphics/Animation.h)）は「同じクリップがもう再生中なら何もしない」を確かめるのに、最後に再生したコントローラーを見ます。
まだ何も再生していないときは、その番号が -1 になって配列の外を読んでいました。そこのゴミが偶然 0 番のクリップ（Idle）と一致すると、最初の再生が無視され、別のクリップ（Walk など）に切り替わるまで T ポーズのままになります。
何も再生していないときは確かめずに、補間なしで再生するようにしました。`IsPlaying()` も同じ理由で、何も再生していなければ `false` を返します。

### Walk の上半身を前へ 20° 起こした（2026-11-06）

リターゲットは、元のモーションの「基準のポーズからの動き」を、SK_Player の基準のポーズに足します。そのため、背骨の曲がり方は VRM の T ポーズのものが残ります。
SK_Player は胸から首にかけて後ろへ傾いた形（UpperChest→Neck が後ろへ約16°）です。Walk では歩くあいだずっと上半身がのけぞって見えていました（頭が腰より 4.7cm 後ろ）。
そこで、背骨の3本で合わせて前へ 20° 傾け、首で 8° 戻しました。頭は腰より 4.6cm 前になりました。歩くときは少し前に傾いている方が自然なので、まっすぐ（10°）より強めにしています。
また、元の Walk は顎が上がっていました（頭が平均 15° 上向き）。頭は戻しすぎず前へ 6° にして、平均 3° 下向き（0.5〜7.8°）＝顎を引いた形にしています。
Idle も同じ形（頭が腰より 2.8cm 後ろ）ですが、反りが小さく目立たないので直していません。

| 候補 | 選ばなかった理由 |
|---|---|
| リターゲッターのリターゲットポーズ（ターゲット側）を直して、リターゲットし直す | 元のモーションと UE のプロジェクトがある PC でしかできない。効果は同じ |
| ゲーム側（エンジン）でボーンに角度を足す | ゲームに置く FBX は SK_Player の骨格そのまま、という決まりから外れる |
| `.tka` を直接書き換える | FBX の方が新しいと、起動時に `.tka` が作り直されて消える |

### Run の上半身を前のめりにした（2026-11-06）

「走るモーションの上体が起きすぎている。もっと前のめりに」とのことで、`run_pelvis.json` で背骨（Spine・Chest・UpperChest）をさらに 10・9・7° 前へ倒し、首・頭を 9° ずつ戻して前を見るようにしました。上半身の前傾は全フレームの平均で 31° → 47° です。骨盤は起こしたまま（74°）なので、お尻は上がりません。ダッシュの着地（47.5°）とほぼ同じ角度になり、着地から走りへ体の角度が変わらずにつながります。

ダッシュのクリップは Run から作るので、`dash_lean.json` の背骨・首・頭の角度は同じだけ差し引いて、ダッシュの形は変えていません（しゃがみ込み 45°、一蹴り 65°、着地 47.5° のまま）。

### 一蹴りを、原神の動画に合わせて「低く滑るポーズ」にした（2026-11-06）

原神のサンプル動画（個人用 OneDrive の `02_Action参考資料/原神/`、33秒あたり）を1コマずつ見ると、ダッシュは「しゃがむ（約0.1秒）→ 同じポーズのまま低く滑る（約0.2秒）→ 上半身を起こしながら着地して走りへ（約0.1秒）」でした。滑るところは足を回さず、頭から後ろ足までほぼ一直線で、頭は起こして前を見ています。前の版（下の「まっすぐ走り出す1歩目」）は前傾を 45° に起こしたので、低く滑る感じがありませんでした。

- DashL は Run の f14〜f16 の3コマに、f16 を7コマくり返して足した10コマ（0.3秒）です（`frames.hold`）。`pose_to` は3コマ目で目標に着き（`ramp_end`）、あとはそのポーズで止まります。DashR は f05〜f07 です。

### Run とダッシュの骨盤を起こした（2026-11-06）

「走っているときとダッシュのとき、お尻が上がっているところがある」とのことで、骨盤（腰 → 背骨の付け根の線）の向きを測りました（`log_frames` の `pelvis`。真上 = 90°）。

| | 直す前 | 今 |
|---|---|---|
| Walk（比べるため。直していない） | 78〜80° | — |
| Run | 58〜60° | 73〜75° |
| ダッシュ（一蹴り・しゃがみ込み） | 26〜28° | 49〜51° |
| 着地 | — | 65〜67° |

Run は歩きより骨盤が 20° 前へ倒れていて、ダッシュはさらに腰から 32° 倒していたので、体の前傾を骨盤だけで作っていました。そのため、前の太ももを上げたときに腰で大きく折れ、お尻が上を向いていました。

- **Run**（`run_pelvis.json`）: 腰（Hips）を 15° 起こし、そのぶん背骨（Spine）と両方の太ももを 15° 前へ回します。上半身と脚の向きは元のまま、骨盤だけが起きます。`ThirdPersonRunPlayer_Run.fbx` から `Run.fbx` を書き出し、ゲームの Run・Jump は `Run.fbx` を使います。

### Dash は Run を前へ倒して作った（2026-11-06）

ダッシュは以前、Run の1コマで止めた仮の状態でした。体全体をぐっと前へ出し、地面を一蹴りして飛び出す動きにするため、Run から `DashL.fbx`・`DashR.fbx` を作りました。

- **脚ごと全身を倒す**: 腰（Hips）を前へ 32° 回し、太ももは戻しません。後ろの足から頭まで、体が一直線に近いまま前へ倒れます（短距離走の加速の形）。
- **背骨は少しだけ**: Spine・Chest・UpperChest で合わせて 14°。腰と合わせて、上半身（腰→首）の前傾は全フレームの平均で 73° です（90° が地面と平行）。
- **首と頭で前を見る**: 首 22°・頭 20° 戻して、地面ではなく進む先を見るようにしました。
- **足を地面に合わせる**: `keep_feet_on_ground` で、つま先の一番低い高さを元（0.66cm）にそろえています。着地は腰の真下になります。
- **蹴って宙へ飛び出す1歩にする**: 参考画像（原神のキャラクターが宙を飛ぶように走る1コマ）の形に合わせました。頭から後ろ足までほぼ一直線で地面とほぼ平行、後ろ足は水平近くまで伸ばし、前足は膝を前へ、片腕は拳を前へ突き出し、もう片腕は後ろへ引いた形です。
  - 倒したあとのコマごとの足の位置を測ると、左足は f15〜f16 で接地して f17 でつま先が離れ、右足は f05〜f07 で接地して f08 で離れます。
  - DashL（左足で蹴る）は f14〜f17・f00〜f05 の10コマ（0.3秒）です。着地して蹴り（〜3コマ目）、蹴った左足が後ろへ伸びていく f05 で終わります。f05 は Run の中で参考画像にいちばん近いコマでした。DashR は半周期ずらした f05〜f14 です。
  - 1コマ目から最後のコマへ、`pose_to` で腕・脚を目標の向きへゆっくり寄せます。蹴った足が離れる3コマ目からは、腰を 8cm 下げます。最後のコマでは、体は地面すれすれを低く飛び、前の足は膝を前・上へ引き上げて、足の一番低いところが地面から 15〜17cm です（どのコマでもつま先は地面より上）。
  - 経緯: 最初は 3コマ目から寄せて腰を 15cm 持ち上げ、1.5倍で流していました（足は 27〜29cm 浮く）。「姿勢を低く」「バタバタして見える」とのことで、腰を下げ、寄せ始めを早め、等速にしました。そのあと「前の足の着地が早すぎる」とのことで、前の太ももを -50° から -25° に上げました（前の足は地面から 4〜6cm → 15〜17cm）。
  - 連打したときは、飛び出したポーズから次の蹴りの着地へ 0.05秒の補間で移ります（着地して、また蹴る）。
- **蹴る前にしゃがみ込む**（`DashCrouchL` / `DashCrouchR`）: 参考画像（片膝を深く曲げて低く構え、片腕を前へ垂らし、もう片腕を後ろへ引いた形）に合わせ、地面から出すときは一度しゃがんでから蹴ります。
  - DashCrouchL は Run の f10〜f14 の5コマに、f14 を4コマくり返して足した9コマ（0.27秒）です。f14 は Run の中で DashL の最初のコマと同じで、蹴る左足が前へ下りてくるところです。DashCrouchR は f01〜f05 です。
  - `pose_to` で最後のコマを次の形にします（角度は前 = 0、真下 = -90）。

    | | 太もも | すね | 足 | 膝の曲がり |
    |---|---|---|---|---|
    | 前の足（蹴る足） | -15° | -100° | -12°（ほぼ平ら） | 85° |
    | 後ろの足 | -115° | -160° | -50°（つま先立ち） | 45° |

    腕は、前の足と反対の腕を前へ垂らし（上腕 -85°・前腕 -45°）、同じ側の腕を後ろへ引きます（上腕 165°・前腕 -165°）。
  - 4コマ目で `pose_to` の形に着きます（`ramp_end`）。腰は `ground_toe_cm`（0.5cm）で、両足とも地面に着く高さまで下げます。腰の高さは 88cm から 58cm になります。
  - そのあとの4コマは踏ん張るところで、`crouch`（`crouch_after_pose`）で足を動かさずに腰をさらに 6cm 落とします（52cm、前の膝は 96°）。
  - DashL / DashR は `blend_from` で、しゃがみ込みの最後のポーズから始まります（混ぜる割合 1・0.7・0.4・0.15）。蹴る足のつま先が地面にめり込むコマ（最大 9cm）は腰を上げたので、腰は 52 → 65 → 81cm と2コマで一気に伸び上がり、蹴る足は3コマ目まで地面に着いたままです。
  - ゲームでは、しゃがみ込みへ 0.05秒の補間で入り、2.5倍で約0.1秒流したあと、一蹴りへ 0.03秒で移ります。一蹴りがしゃがんだポーズから始まるので、補間は短くてよいです。連打で続けて蹴るときは、しゃがんだところを飛ばして f02 から流します。
  - 経緯: 最初はしゃがむ 0.13秒のあと、ふつうの一蹴りへ 0.1秒の補間でつないでいました。「もっと滑らかに」「しゃがんで踏ん張って力を溜めてから一気に飛び出す感じ」とのことで、踏ん張る間と `blend_from` を足しました。そのあと「溜めはいるが、もっと一瞬で」とのことで、0.27秒（等速）から約0.1秒（2.5倍）にしました（2026-11-06）。
- **足の振りを少し大きく**: 太ももの振り幅を 1.15倍にしました。1.3倍だと、脚ごと倒した分と合わさって、振り上げたかかとが腰より高く（115cm）上がりすぎました（1.15倍で 109cm）。
- 前傾の経緯（2026-11-06）:

  | | 腰→頭の前傾 | 体の折れ | 直した理由 |
  |---|---|---|---|
  | 1回目: 腰 8°・太もも -4°・背骨 10° | 47° | — | もっと倒してほしい |
  | 2回目: 腰 20°・太もも -14°・背骨 35° | 73° | 40° | 腰で「く」の字に折れ、お尻が突き出て見える |
  | 今: 腰 32°・太もも 0°・背骨 14° | 72° | 15° | — |

  体の折れは `shape` の行の `bend`。元の Run は 6° です。
- ゲームでは等速（0.3秒）で流し、入るときの補間を 0.05秒、出るときの補間を 0.5秒にしています。入りは一気に前へ出るため短く、出るときは飛び出したポーズが残ったまま走りへ移るよう長くしています。

| 候補 | 選ばなかった理由 |
|---|---|
| Mixamo の Sprint などをリターゲットする | ダウンロード元とリターゲット用の UE プロジェクトがこのPCにない。走りの足の運びは Run と同じでよい |
| ゲーム側（エンジン）でダッシュ中だけボーンを傾ける | ゲームに置く FBX は SK_Player の骨格そのまま、という決まりから外れる |
| Run の1コマで止めたまま、前傾だけ足す | 足が動かず、滑って見える（以前の仮の状態） |

| 前へ倒した Run をループで流す（いったんこうした） | 0.2秒の間に足が回るだけで、地面を蹴って飛び出した感じが出ない |

### エンジンでのリターゲットは作らなかった

エンジンの変換（`ConvertAnimationFbxToTka`）は、ボーン名が一致したものの姿勢をそのままコピーするだけです。骨の長さや基準のポーズの違いを吸収するには、IK Rig のような仕組みが必要になります。UE にすでにあるので、そちらを使っています。

## 7. 既知の課題

- **Jump のモーションがない**: 空中では Run が流れます。Mixamo の「Jump」などを、同じ手順で足せます。
- **髪・スカートが揺れない**: `J_Sec_*` のボーン（揺れもの）はモーションに含まれないので、基準のポーズのまま止まっています。原神らしさを上げるには、揺れものの物理（スプリングボーン）が別に必要です。
- **UE のプロジェクトとダウンロードした元のファイルはリポジトリにない**: `D:\03_data\AssetMigrate_Combat 5.8 - 2` と `D:\04_dawnload\mixamo\` は、このPCにしかありません。別のPCでリターゲットするには、どちらも用意する必要があります。
- **Walk をリターゲットし直すと補正が消える**: retarget_to_player.py は `Walk.fbx` を上書きするので、そのあとに adjust_bone_rotation.py を1回流し直す必要があります。
- **Idle は補正していない**: Idle も背骨の形は同じですが、反りは小さめです。気になったら、同じ手順で `clips` に足せます。
- **見た目の確認は実機だけ**: スクリプトで確かめているのは、ボーン構成が Run と同じであることと、ループの最初と最後の姿勢が合っていることだけです。
