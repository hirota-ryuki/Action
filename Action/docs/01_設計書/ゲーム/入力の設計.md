# 入力の設計

作成日: 2026-11-05（2026-11-06 に構成を見直し）
対象: `Game/Source/Character/CharacterInput.h`、`PlayerInputSource.*`、`NpcInputSource.*`

プレイヤーの操作と NPC の AI が、同じ形の入力（`CharacterInput`）を作る仕組みのページです。
キャラクター全体の構成は [キャラクターの構成](キャラクターの構成.md) を見てください。

- **デバイスを読むのは入力元だけ**: キャラクターは `CharacterInput` を受け取って動くだけ。
- **AI も同じ形の入力を作る**: 入力元を差し替えれば、敵を手で操作したり、プレイヤーを AI で動かしたりできる。

---

## 1. 全体像

```
 PlayerInputSource（パッド・キーボード・マウス）─┐
                                              ├─ IInputSource::Update(context, input)
 NpcInputSource（AI）─────────────────────────┘
                                │ CharacterInput（値だけの構造体）
                                ▼
                       Player ／ Enemy
```

`InputSourceContext` は、入力元が操作対象について**知ってよい情報**だけです（自分・陣営・位置・正面・経過時間・一人称か）。入力元はキャラクター本体に触れません。

---

## 2. CharacterInput：キャラクターが受け取るもの

コード: [CharacterInput.h](../../../Game/Source/Character/CharacterInput.h)

| メンバー | 意味 |
|---|---|
| `moveDirection` | 移動したい方向（**ワールド**の XZ）。長さ 0〜1 が速さの割合 |
| `lookDirection` | 向きたい方向。ゼロなら移動方向を向く |
| `isRun` | 走る。プレイヤーではラッシュボタンを押しっぱなしにしていること |
| `jump` / `rush` | ボタン（`ButtonState`） |
| `fire` / `subFire` | メイン / サブの魔法を撃つ（`ButtonState`） |
| `magicSwitch` | -1: 前の魔法へ、+1: 次の魔法へ、0: そのまま |
| `hasAim` / `aimOrigin` / `aimDirection` | 照準。`hasAim` が false ならキャラクターの正面へ撃つ |

`ButtonState` は `isTrigger`（押した瞬間）・`isPress`（押している）・`isRelease`（離した瞬間）の3つを持ちます。

## 3. PlayerInputSource：プレイヤーの入力元

コード: [PlayerInputSource.cpp](../../../Game/Source/Character/PlayerInputSource.cpp)

### 操作の割り当て

| 操作 | キーボード・マウス | パッド |
|---|---|---|
| 移動 | WASD | 左スティック |
| ラッシュ / 走る | 左Shift（押した瞬間にラッシュ、押しっぱなしで走る、連打でラッシュが続く） | X |
| ジャンプ | スペース（J でも可） | A |
| 発射（氷魔法） | マウス左 / I | Y |
| サブの発射（炎魔法） | マウス右 / 8 | RB2（右トリガー） |
| 魔法の切り替え | Q / E | LB / RB |
| 視点の切り替え（GameCamera） | K | B |

> パッドがないときは、エンジンがパッドのボタンをキーボードで代用します（A=J、X=L、Y=I、RB2=8 など）。

## 4. NpcInputSource：NPC の AI

コード: [NpcInputSource.cpp](../../../Game/Source/Character/NpcInputSource.cpp)

```
敵対する相手を探す（HitTargetRegistry::FindNearestHostile）
  ├─ いない → 何もしない
  └─ いる
       ├─ 相手の方を向く（lookDirection）
       ├─ 止まる距離より遠ければ近づく（moveDirection）
       └─ 射程内で撃つ間隔が来たら撃つ（fire、照準は相手の胸）
```

相手は Player クラスではなく、当たり判定の一覧から陣営で探します（[陣営と当たり判定の設計](陣営と当たり判定の設計.md)）。

## 5. 実装方法

### ButtonState：前のフレームの「押している」と比べるだけ

```cpp
struct ButtonState {
    bool isTrigger = false;
    bool isPress = false;
    bool isRelease = false;

    void Update(bool isPressNow) {
        isTrigger = isPressNow && !isPress;   // 今押していて、前は押していない
        isRelease = !isPressNow && isPress;   // 今押していなくて、前は押していた
        isPress   = isPressNow;
    }
};
```

`IInputSource::Update` には**前のフレームの値が入ったままの** `CharacterInput` が渡されます。入力元が毎フレーム `Update(押しているか)` を呼ぶだけで、押した瞬間・離した瞬間が決まります。

### スティックの向きをワールドの向きにする

```cpp
Vector3 cameraForward = g_camera3D->GetForward();
Vector3 cameraRight = g_camera3D->GetRight();
cameraForward.y = 0.0f;   // 水平にする
cameraRight.y = 0.0f;
cameraForward.Normalize();
cameraRight.Normalize();
input.moveDirection = cameraForward * pad.GetLStickYF() + cameraRight * pad.GetLStickXF();
```

カメラが下を向いていても、水平な前・右だけを使うので速さが落ちません。

### ボタンはパッドとキーボードを OR でまとめる

```cpp
const bool isDashPress = IsKeyPressed(VK_LSHIFT) || pad.IsPress(enButtonX);
input.rush.Update(isDashPress);   // 押した瞬間 → ラッシュ
input.isRun = isDashPress;        // 押している間 → 走る（ラッシュが終わったあと）
input.fire.Update((IsGameWindowActive() && IsKeyPressed(VK_LBUTTON)) || pad.IsPress(enButtonY));
```

ラッシュと走るは同じボタンの「押した瞬間」と「押している」を別のメンバーに入れるだけです。どちらを優先するかはステートが決めます（[プレイヤーのステートの設計](プレイヤーのステートの設計.md)）。

- キーは `GetAsyncKeyState(key) & 0x8000`（最上位ビットが「今押している」）で読む。
- マウスのボタンは、ゲームのウィンドウが前面のときだけ見る（ほかのウィンドウでのクリックで撃たないように）。
- 魔法の切り替え（Q/E）は、入力元の中に `ButtonState` を持って押した瞬間だけ ±1 する。
- 一人称のときだけ `hasAim = true` にして、照準をカメラの位置と向きにする。

### AI：毎フレーム入力を作り直す

```cpp
input.moveDirection = Vector3::Zero;   // まず全部「何もしない」にする
input.jump.Update(false);
...
const HitTarget* target = HitTargetRegistry::FindNearestHostile(
    context.position, m_settings.searchRange, context.faction, context.self);   // 自分は除く
if (target == nullptr) { input.fire.Update(false); return; }

Vector3 toTarget = target->GetCenter() - context.position;
toTarget.y = 0.0f;                     // 高低差は無視して水平に追う
input.lookDirection = 正規化した toTarget;
if (距離 > stopDistance) { input.moveDirection = input.lookDirection * m_settings.moveRate; }
```

撃つときは「押している」を `fireHoldSeconds` の間続けてから離します。人と同じように押す・離すが起きるので、溜め撃ちの魔法でも同じ入力で動きます。
間隔はタイマーで数えます。相手を見つけた直後は `firstFireDelay` だけ待ちます。

## 6. 使い方

### 入力元を差し替える

`Player` と `Enemy` の `SetInputSource()` で差し替えます。`nullptr` で既定に戻ります。

| やりたいこと | 書き方 |
|---|---|
| 敵を手で操作してデバッグする | `enemy->SetInputSource(&somePlayerInputSource);` |
| プレイヤーを AI で動かす | `player->SetInputSource(&someNpcInputSource);` |
| 元に戻す | `SetInputSource(nullptr);` |

### ボタンを足す

1. `CharacterInput` に `ButtonState` のメンバーを足す（例: `ButtonState crouch;`）。
2. `PlayerInputSource::Update` で、押しているかを渡す。
   ```cpp
   input.crouch.Update(IsKeyPressed('C') || pad.IsPress(enButtonLB2));
   ```
3. 使う側（ステート・`MagicCaster` など）で `isTrigger` / `isPress` / `isRelease` を見る。
4. AI にも押させるなら、`NpcInputSource::Update` でも同じメンバーを埋める。
5. 3章の操作の割り当ての表に1行足す。

### 新しい入力元を作る（例: 記録した入力の再生）

```cpp
class ReplayInputSource : public IInputSource {
public:
    void Update(const InputSourceContext& context, CharacterInput& input) override {
        input = m_frames[m_frameNo++];   // 記録しておいた入力を1フレームずつ渡す
    }
};
player->SetInputSource(&replayInputSource);
```

## 7. 調整用の数値

AI の数値です（`Enemy.cpp` の `MakeAiSettings`）。

| 内容 | 値 |
|---|---|
| 相手を探す範囲 | 0（今は敵を止めている。動かすときは 900） |
| 止まる距離 | 90 |
| 移動入力の大きさ（`moveRate`） | 1 |
| 撃つ射程 / 間隔 | 700 / 4秒 |
| 見つけてから最初に撃つまで | 1.5秒 |

- 撃つ間隔（4秒）を凍結時間（2.5秒）より長くして、プレイヤーが凍らされ続けないようにしています。
- 撃たせたくないときは `canFire = false`。
- 今は `searchRange = 0` で、敵は何もしません（2026-11-06、ダッシュの見た目を確かめやすくするため）。相手が見つからないので、動かず、向きも変えず、撃ちません。

## 8. 決めたこと

| 以前 | 今 |
|---|---|
| Player が `g_pad` や `GetAsyncKeyState` を、移動・アニメーション・魔法の中で直接読んでいた | 入力元が `CharacterInput` を作り、キャラクターは受け取るだけ |
| Enemy の中で、追うかの判断と移動処理が混ざっていた | 判断は `NpcInputSource`、移動は `CharacterMover` |

- **ボタンを3つの状態で持つ**: 押した瞬間・押している・離した瞬間があるので、長押しの魔法を足しても入力元を変えずに済む。
- **値だけの構造体にする**: 画面に表示したり、記録して再生したりしやすい。

---

## 9. 既知の課題

- **ウィンドウを前に出すクリックでも撃つ**: 裏にあるウィンドウを左クリックで前に出すと、1発出ます。
- **入力の記録・再生はまだない**: 6章の `ReplayInputSource` のような入力元を作れば、バグを同じ条件で再現できます。
