# プレイヤーのステートの設計

作成日: 2026-11-05
ブランチ: `feature/player-state`
対象: `Game/Source/PlayerState/`、`Game/Source/Objects/Player.*`、`Game/Source/Character/CharacterMover.*`

プレイヤーの「立ち止まる・歩く・走る・空中・ラッシュ・凍結」を、ステートパターンで切り替える仕組みをまとめたページです。
キャラクター全体の構成は [キャラクターの構成](キャラクターの構成.md) を見てください。

---

## 1. 何を解決したか

| 以前の問題 | 今の形 |
|---|---|
| `Player::UpdateAnimation()` が、ラッシュ中か・空中か・入力の大きさ・走る入力を if で並べて、毎フレームアニメーションを決めていた | ステートごとのクラスが、入ったときに自分のアニメーションを流す |
| 移動の速さ（歩く・走る）とアニメーションの判断が、`CharacterMover` と `Player` に分かれていた | 「歩く」なら速さもアニメーションも `PlayerWalkState` の中にある |
| ラッシュの残り距離が `CharacterMover` に、ラッシュ中のポーズのフラグが `Player` にあった | ラッシュに関することは `PlayerRushState` だけにある |
| 凍結中の処理が `Player::Update()` の if/else に書かれていた | 凍結中は `PlayerFrozenState` になる |

### 設計の方針

- **1つのステートが、自分の動き方と、次にどこへ移るかを決める**: ほかのステートの中身は知らない。
- **ステートは Player を知らない**: 触ってよいもの（`CharacterMover`・`ModelRender`・`StatusEffects`・数値）だけを `PlayerStateContext` で受け取る。
- **入力は今までどおり `CharacterInput`**: ステートも入力元のことは知らない。AIでプレイヤーを動かしても、同じステートで動く。

## 2. ステートと遷移

```
                  ┌──────── ラッシュボタン ────────┐
                  │                                ▼
 ┌─────────────────────────────┐            ┌──────────┐
 │ 地面（PlayerGroundState）     │            │   Rush   │ 決まった距離を一気に進む
 │                             │            └────┬─────┘
 │  Idle ⇄ Walk ⇄ Run          │ ◀── 進み切った ──┘（空中なら Air へ）
 │  入力の大きさと走る入力で決まる  │
 └──────┬──────────────────────┘
        │ ジャンプボタン／足場がない       ▲
        ▼                              │ 着地
 ┌──────────┐ ───────────────────────────┘
 │   Air    │ ── ラッシュボタン ──▶ Rush
 └──────────┘

 ┌──────────┐  どのステートからでも、行動できなくなったら（凍結）ここへ移る。
 │  Frozen  │  行動できるようになったら、入力と足場に合わせて Idle / Walk / Run / Air へ
 └──────────┘
```

| ステート | 動き | アニメーション | 次へ移る条件 |
|---|---|---|---|
| `Idle` | 動かない。向きたい方向（一人称の視線など）には向く | Idle | 地面の共通ルール（下記） |
| `Walk` | `walkSpeed` で入力の方向へ進む | Walk | 地面の共通ルール |
| `Run` | `walkSpeed × runSpeedMultiplier` で進む | Run | 地面の共通ルール |
| `Air` | ジャンプボタンで入ったら跳ぶ。空中でも入力の方向へ動ける（走る入力なら走る速さ） | Jump | ラッシュボタン → Rush、着地 → Idle / Walk / Run |
| `Rush` | 入った瞬間の移動方向（入力がなければ正面）へ、`rushDistance` を `rushSpeed` で進む。向きは変えられない。重力はかかる | Run の疾走ポーズで止める | 進み切った → Idle / Walk / Run / Air |
| `Frozen` | 入力を無視して、重力で落ちるだけ | 触らない（`StatusEffects` が止める） | 行動できるようになった → Idle / Walk / Run / Air |

### 地面の共通ルール（Idle・Walk・Run）

上から順に調べて、最初に当てはまったものへ移ります。

1. ラッシュボタンを押した → `Rush`
2. ジャンプボタンを押した（地面にいて、跳べる設定のとき） → `Air`（跳ぶ）
3. 足場がない → `Air`（落ちる）
4. 移動入力の長さが `moveThreshold` より小さい → `Idle`
5. 走る入力がある → `Run`
6. それ以外 → `Walk`

3〜6 は `PlayerGroundState::SelectByInput()` にまとめてあり、Air・Rush・Frozen が「終わったあとの行き先」を決めるときにも使います。

### PlayerState：ステートの基底クラス

| 関数 | 呼ばれるとき | 書くこと |
|---|---|---|
| `GetId()` / `GetName()` | - | ステートの種類と、デバッグ表示用の名前 |
| `Enter(context, input)` | このステートに入ったとき | アニメーションの切り替え、跳ぶ・ラッシュの方向を決める、など |
| `CheckTransition(context, input)` | 毎フレーム、動く前 | 次のステートを返す。移らないなら自分の `GetId()` |
| `Update(context, input, deltaTime)` | 毎フレーム | `CharacterMover` の `Move` 系の関数を**1回だけ**呼ぶ（重力はそこでかかる） |
| `Exit(context)` | このステートから出るとき | 後片付け |

## 4. 1フレームの流れ

コード: [PlayerStateMachine.cpp](../../../Game/Source/PlayerState/PlayerStateMachine.cpp)（`PlayerStateMachine::Update`）

```cpp
// ① 次のステートを決める。行動できなければ、今のステートによらず Frozen
next = CanAct() ? m_current->CheckTransition(context, input) : PlayerStateId::Frozen;

// ② 移るなら、今のステートの Exit → 次のステートの Enter
if (next != m_current->GetId()) { ChangeState(next, input); }

// ③ 今のステートの動き
m_current->Update(context, input, deltaTime);
```

遷移を決めてから動くので、ジャンプボタンを押したフレームのうちに跳び始めます（遷移が1フレーム遅れません）。
1フレームに移るのは1回だけです。

## 5. 決めたこと

### 関数テーブルではなく、ステートごとのクラスにした

ステートの番号で関数（Enter・遷移の判定・Update）を引く表を Player の中に作る、という方法もあります。比べて、クラスにする方を選びました（2026-11-06）。

| | クラス（採用） | 関数テーブル |
|---|---|---|
| ファイル数・流れの追いやすさ | ファイルが多く、流れを追うのにファイルをまたぐ | Player の中だけで済み、上から読める |
| ステートだけが使うデータ | そのステートのクラスに閉じ込められる | Player のメンバー変数になり、ステートが増えるほど Player が膨らむ |
| Enemy などへの流用 | ステートが Player を知らないので流用しやすい | Player のメンバー関数なので流用しにくい |

今の6ステートだけなら関数テーブルでも足ります。
ただ、これから剣の連続攻撃（何段目か・入力の受付時間）、回避（無敵時間）、被弾ののけぞり（吹き飛ぶ方向）など、ステートごとにデータを持つ動きを足す予定なので、クラスにしました。

### 凍結への遷移はステートマシンが行う

凍結はどのステートからでも起こるので、各ステートの `CheckTransition` に書くと全部に同じ行が並びます。
そのため「行動できないなら Frozen」だけは `PlayerStateMachine` が先に見ます。ステートは凍結のことを考えなくてよくなります。

### アニメーションの速さは、入るときに戻す（出るときには戻さない）

ラッシュは疾走ポーズでアニメーションを止めます（速さ0）。凍結も、`StatusEffects` がアニメーションを止めます。
もし `PlayerRushState::Exit` で速さを1に戻すと、**ラッシュ中に凍ったとき、凍結で止めたアニメーションが動き出して**しまいます。
そのため、アニメーションを流すステートは、`Enter` で `PlayerStateContext::PlayAnimation()`（切り替えて速さを1にする）を呼びます。Frozen はアニメーションに触りません。

### CharacterMover は「1つずつの操作」も持つ

以前の `CharacterMover::Update(input)` は、入力を見て、歩く・走る・跳ぶ・ラッシュを全部まとめて処理していました。
ステートごとに速さや動き方を変えられるように、`Move`（水平の速度で動かす）、`MoveByInput`（入力の方向に決まった速さで動かす）、`Jump`、`FaceTo` を分けました。
Enemy はステートを持たないので、今までどおり `Update(input)`（内部でこれらを呼ぶ）を使います。
ラッシュは Player だけの動きなので、`CharacterMover` から `PlayerRushState` へ移しました。

### 以前と動きが変わったところ

| 内容 | 以前 | 今 |
|---|---|---|
| ラッシュ中のジャンプ | ラッシュ中もジャンプできた | ラッシュ中はジャンプできない（ラッシュが終わってから） |
| ごく小さい移動入力（長さ 0.1 未満） | 待機アニメーションのまま、ゆっくり動いた | 動かない（Idle） |

## 6. 新しいステートを足す（例: しゃがみ）

1. [PlayerState.h](../../../Game/Source/PlayerState/PlayerState.h) の `PlayerStateId` に `Crouch` を足す（`Num` より前）。
2. `PlayerState` を継承したクラスを作る。

```cpp
class PlayerCrouchState : public PlayerState {
public:
    PlayerStateId GetId() const override { return PlayerStateId::Crouch; }
    const char* GetName() const override { return "Crouch"; }

    void Enter(PlayerStateContext& c, const CharacterInput& input) override {
        c.PlayAnimation(enPlayerAnimClip_Crouch);   // クリップの番号も EnPlayerAnimClip に足す
    }
    PlayerStateId CheckTransition(const PlayerStateContext& c, const CharacterInput& input) const override {
        if (!input.crouch.isPress) {                // CharacterInput にボタンを足す
            return PlayerGroundState::SelectByInput(c, input);
        }
        return PlayerStateId::Crouch;
    }
    void Update(PlayerStateContext& c, const CharacterInput& input, float deltaTime) override {
        c.mover->MoveByInput(input, c.mover->GetSettings().walkSpeed * 0.5f, deltaTime);
    }
};
```

3. [PlayerStateMachine.cpp](../../../Game/Source/PlayerState/PlayerStateMachine.cpp) のコンストラクタで `m_states[...] = std::make_unique<PlayerCrouchState>();` を足す。
4. どこから入るかを決める。地面から入るなら `PlayerGroundState::CheckTransition` に条件を足す。
5. `Game.vcxproj` と `Game.vcxproj.filters` にファイルを足す（フィルタは `Source\PlayerState`）。

> ボタンを足すときは、`CharacterInput` にメンバーを、`PlayerInputSource` にキーの割り当てを足します（[入力の設計](入力の設計.md)）。

## 8. 既知の課題・今後

- **アニメーションは Run の1本だけ**: SK_Player のスケルトンに合うアニメーションが Run しかないので、Idle・Walk・Jump の枠にも同じ Run を入れています（[Player.cpp](../../../Game/Source/Objects/Player.cpp) の `Start`）。ステートは正しく切り替わっていても、見た目は走るモーションのままです。アニメーションを足したら、`Player::Start()` で各枠に読み込むだけで、ステート側は変えなくて済みます。
- **今のステートの表示**: `Player::GetStateName()` で今のステートの名前を取れるので、デバッグ表示に使えます。
