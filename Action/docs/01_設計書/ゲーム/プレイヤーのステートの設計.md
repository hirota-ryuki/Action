# プレイヤーのステートの設計

作成日: 2026-11-05（2026-11-06 に構成を見直し）
対象: `Game/Source/PlayerState/`

プレイヤーの「立ち止まる・歩く・走る・空中・ダッシュ・凍結」をステートパターンで切り替える仕組みのページです。
キャラクター全体の構成は [キャラクターの構成](キャラクターの構成.md) を見てください。

- **1つのステートが、自分の動き方と次の行き先を決める**: ほかのステートの中身は知らない。
- **ステートは Player を知らない**: 触ってよいもの（`CharacterMover`・`ModelRender`・`StatusEffects`・数値）だけを `PlayerStateContext` で受け取る。
- **入力は `CharacterInput`**: 入力元を知らないので、AI でプレイヤーを動かしても同じステートで動く。

---

## 1. ステートと遷移

ダッシュボタン（キーボードは左Shift、パッドは X）1つで、ダッシュと走るを使い分けます。

| 操作 | 動き |
|---|---|
| 移動だけ | 歩く（Walk） |
| ダッシュボタンを押す | ダッシュ（Dash）が1回出て、離していれば歩くに戻る |
| 押しっぱなし | ダッシュのあと、押している間は走る（Run） |
| 走っていて移動の入力を離す | 勢いで滑りながら踏ん張って止まる（Stop。[走りから止まる設計](走りから止まる設計.md)） |
| 連打 | ダッシュが続けて出る（ダッシュ中に押した分は、進み切ったらすぐ次を出す） |

```
                  ┌──────── ダッシュボタンを押す ────────┐
                  │                                      ▼
 ┌─────────────────────────────┐                  ┌──────────┐
 │ 地面（PlayerGroundState）     │                  │   Dash   │ 決まった距離を一気に進む
 │                             │                  └────┬─────┘ ダッシュ中に押すと、進み切ったあと次のダッシュ
 │  Idle ⇄ Walk ⇄ Run          │ ◀──── 進み切った ──────┘（押しっぱなしなら Run、空中なら Air へ）
 │  ふだんは Walk。Run はダッシュ  │
 │  ボタンを押している間だけ       │
 └──────┬──────────────────────┘
        │ ジャンプボタン／足場がない       ▲
        ▼                              │ 着地
 ┌──────────┐ ───────────────────────────┘
 │   Air    │ ── ダッシュボタン ──▶ Dash
 └──────────┘

 ┌──────────┐  どのステートからでも、行動できなくなったら（凍結）ここへ移る。
 │  Frozen  │  行動できるようになったら Idle / Walk / Run / Air へ
 └──────────┘

 Run ── 移動の入力を離した ──▶ Stop ── 止まり切った ──▶ Idle
                              （移動の入力 → Walk / Run、ダッシュ → Dash、ジャンプ・足場がない → Air）
```

| ステート | 動き | アニメーション | 次へ移る条件 |
|---|---|---|---|
| `Idle` | 動かない。向きたい方向には向く | Idle | 地面の共通ルール |
| `Walk` | `walkSpeed` で進む | Walk | 地面の共通ルール |
| `Run` | `walkSpeed × runSpeedMultiplier` で進む。ダッシュボタンを押している間だけ | Run | 地面の共通ルール（離すと Walk）。ただし Idle になるときは Stop |
| `Stop` | 入った瞬間の正面へ、走る速さから `stopSlideSeconds` で 0 まで遅くなりながら滑る | StopL / StopR（前の足を突っ張って滑る → 起き上がる）。走りで前に着こうとしている足の方 | 移動の入力 → Walk / Run、ダッシュ → Dash、ジャンプ・足場がない → Air、`stopSeconds` たった → Idle |
| `Air` | ジャンプで入ったら跳ぶ。空中でも入力の方向へ動ける | Jump | ダッシュ → Dash、着地 → 地面 |
| `Dash` | 入った瞬間の移動方向（なければ正面）へ、一蹴りで `dashDistance` 進む（最初が速く、だんだん止まる）。重力はかかる | DashL / DashR（しゃがむ → 蹴って低く滑る → 着地の通しの1本）を交互に1回ずつ流す。出るときは 0.15秒で走りへ移る | 進み切った → ダッシュ中に押していれば次の Dash、そうでなければ地面 / Air |
| `Frozen` | 入力を無視して重力で落ちるだけ | 触らない（`StatusEffects` が止める） | 行動できる → 地面 / Air |

### 地面の共通ルール（Idle・Walk・Run）

上から順に調べ、最初に当てはまったものへ移ります。

| 順 | 条件 | 行き先 |
|---|---|---|
| 1 | ダッシュボタンを押した | `Dash` |
| 2 | ジャンプボタンを押した（跳べる設定のとき） | `Air`（跳ぶ） |
| 3 | 足場がない | `Air`（落ちる） |
| 4 | 移動入力の長さが `moveThreshold` 未満 | `Idle` |
| 5 | 走る入力（`isRun`）がある。プレイヤーではダッシュボタンを押しっぱなし | `Run` |
| 6 | それ以外 | `Walk` |

3〜6 は `PlayerGroundState::SelectByInput()` にあり、Air・Dash・Stop・Frozen が終わったあとの行き先にも使います。
Run だけは、4 で `Idle` になるとき、代わりに `Stop` へ移ります（`stopSeconds` が 0 なら `Idle`）。Run から来て `stopAfterRunSeconds`（0.2秒）以内の Walk も同じです。

## 2. クラス

```
Player ── 持つ ──▶ PlayerStateMachine ── 持つ ──▶ PlayerState（基底クラス）
                     │                              ├── PlayerGroundState（地面の共通部分）
                     │ PlayerStateContext            │     ├── PlayerIdleState
                     │（mover・modelRender・          │     ├── PlayerWalkState
                     │  statusEffects・数値）         │     └── PlayerRunState
                     │                              ├── PlayerAirState
                     │                              ├── PlayerDashState
                     │                              ├── PlayerStopState
                     │                              └── PlayerFrozenState
```

| ファイル | 内容 |
|---|---|
| [PlayerState.h](../../../Game/Source/PlayerState/PlayerState.h) | ステートの種類・アニメーションの番号・調整値・`PlayerStateContext`・基底クラス |
| [PlayerStateMachine](../../../Game/Source/PlayerState/PlayerStateMachine.cpp) | ステートを全部持ち、毎フレーム遷移と更新を行う |
| [PlayerGroundState](../../../Game/Source/PlayerState/PlayerGroundState.cpp) | Idle・Walk・Run の共通部分。派生クラスはアニメーションと速さを返すだけ |
| [Air](../../../Game/Source/PlayerState/PlayerAirState.cpp) / [Dash](../../../Game/Source/PlayerState/PlayerDashState.cpp) / [Stop](../../../Game/Source/PlayerState/PlayerStopState.cpp) / [Frozen](../../../Game/Source/PlayerState/PlayerFrozenState.cpp) | 各ステート。Dash は進む方向・経過時間・次に蹴る足を持つ。Stop は滑る方向・速さ・経過時間を持つ |

### 基底クラス PlayerState

| 関数 | 呼ばれるとき | 書くこと |
|---|---|---|
| `GetId()` / `GetName()` | - | 種類とデバッグ表示用の名前 |
| `Enter(context, input)` | 入ったとき | アニメーションの切り替え、跳ぶ・ダッシュの方向を決める |
| `CheckTransition(context, input)` | 毎フレーム、動く前 | 次のステート。移らないなら自分の `GetId()` |
| `Update(context, input, deltaTime)` | 毎フレーム | `CharacterMover` の `Move` 系を**1回だけ**呼ぶ |
| `Exit(context)` | 出るとき | 後片付け |

## 3. 実装方法

### ステートは最初に全部作り、番号で引く配列に入れておく

```cpp
// PlayerStateMachine.h
std::unique_ptr<PlayerState> m_states[static_cast<int>(PlayerStateId::Num)];
PlayerState* m_current = nullptr;   // 今のステート（配列の中を指すだけ）

// PlayerStateMachine.cpp（コンストラクタ）
m_states[static_cast<int>(PlayerStateId::Idle)] = std::make_unique<PlayerIdleState>();
m_states[static_cast<int>(PlayerStateId::Walk)] = std::make_unique<PlayerWalkState>();
...
```

切り替えのたびに `new` しません。ステートが持つデータ（ダッシュの経過時間など）は残るので、`Enter` で必ず初期化します。

### 1フレームの流れ：遷移を決めてから動く

```cpp
void PlayerStateMachine::Update(const CharacterInput& input, float deltaTime)
{
    // ① 次のステートを決める。行動できなければ、今のステートによらず Frozen
    const PlayerStateId next = CanAct() ? m_current->CheckTransition(m_context, input) : PlayerStateId::Frozen;
    // ② 移るなら Exit → Enter
    if (next != m_current->GetId()) {
        ChangeState(next, input);
    }
    // ③ 今のステートの動き
    m_current->Update(m_context, input, deltaTime);
}

void PlayerStateMachine::ChangeState(PlayerStateId next, const CharacterInput& input)
{
    if (m_current != nullptr) { m_current->Exit(m_context); }
    m_current = m_states[static_cast<int>(next)].get();
    m_current->Enter(m_context, input);
}
```

- 遷移を先に決めるので、ジャンプを押したそのフレームに跳び始める。
- 1フレームに移るのは1回だけ（移った先の `CheckTransition` は次のフレームまで呼ばない）。
- `Enter` に入力を渡すので、Air は「ジャンプボタンで入ったか」を見て跳ぶかを決められる。

### 地面の3ステートは基底クラスにまとめ、違いだけを派生で返す

```cpp
class PlayerGroundState : public PlayerState {
public:
    void Enter(...) override { context.PlayAnimation(GetAnimClip(), GetAnimSpeed(context)); }
    void Update(...) override { context.mover->MoveByInput(input, GetMoveSpeed(context), deltaTime); }
    PlayerStateId CheckTransition(...) const override;   // 地面の共通ルール
protected:
    virtual int GetAnimClip() const = 0;
    virtual float GetMoveSpeed(const PlayerStateContext& context) const = 0;
    virtual float GetAnimSpeed(const PlayerStateContext& context) const { return 1.0f; }  // 再生速度
};

class PlayerWalkState : public PlayerGroundState {   // ヘッダーだけで書ける
    int GetAnimClip() const override { return enPlayerAnimClip_Walk; }
    float GetMoveSpeed(const PlayerStateContext& c) const override { return c.mover->GetSettings().walkSpeed; }
    // 足が地面を送る速さ（walkAnimMoveSpeed）と、進む速さをそろえる。
    float GetAnimSpeed(const PlayerStateContext& c) const override { return GetMoveSpeed(c) / c.settings.walkAnimMoveSpeed; }
};
```

再生速度は `Enter` で1回だけ決めます。歩く速さは途中で変わらないので、毎フレーム計算しなくて済みます。

### 行き先の判定は static 関数にして使い回す

`PlayerGroundState::SelectByInput()` は「足場・入力の大きさ・走る入力」から Idle / Walk / Run / Air を返す static 関数です。Air の着地、Dash の終わり、Frozen が解けたとき、のどれもこれを呼びます。

### ダッシュ：一蹴りで飛び出し、だんだん止まる

```cpp
// Begin: 方向とかかる時間を決め、蹴る足を入れ替えて一蹴りのアニメーションを流す
m_duration = context.settings.dashDistance / context.settings.dashSpeed;   // 300 ÷ 約1333 = 0.225秒
m_isLeftKick = !m_isLeftKick;
const int clip = m_isLeftKick ? enPlayerAnimClip_DashL : enPlayerAnimClip_DashR;
context.modelRender->PlayAnimation(clip, context.settings.dashAnimBlendSeconds);
context.modelRender->SetAnimationSpeed(context.settings.dashAnimSpeed);

// Update: 進んだ割合（ease-out）の、前のフレームとの差だけ進む
const float before = CalcDashProgress(m_elapsed / m_duration);   // 1 - (1 - t)^2
m_elapsed = min(m_elapsed + deltaTime, m_duration);
const float after = CalcDashProgress(m_elapsed / m_duration);
velocity = m_direction * ((after - before) * context.settings.dashDistance / deltaTime);
context.mover->Move(velocity, deltaTime);   // Move なので重力もかかる
```

- 速さは時間の割合 t に対して `2(1 - t)` 倍です。蹴った瞬間に平均（`dashSpeed`）の2倍で飛び出し、終わりで0になります。一定の速さで滑るより、地面を蹴って前へ出た感じになります。
- 割合は最後に1で止まるので、ダッシュの距離はフレームレートによらず `dashDistance` ちょうどになります。
- アニメーション（DashL / DashR）は、原神の動画から作った「しゃがむ（f00〜f04）→ 蹴って低く滑る（f04〜f11）→ 着地（f11〜f16）」の通しの1本（0.53秒）です。ダッシュの間はクリップを切り替えず、区間ごとに進み方だけを変えます。`dashCrouchSeconds`（4コマ）・距離÷`dashSpeed`（7コマ）・`dashLandSeconds`（5コマ）を、クリップの区間の長さに合わせてあります。
- `Exit` で `context.nextBlendSeconds` に `dashExitBlendSeconds`（0.15秒）を入れます。次のステートの `PlayAnimation()` は、それがあれば1回だけふだんの 0.2秒の代わりに使います。走りへ移るときに飛び出したポーズがすぐ消えず、ダッシュの勢いが残って見えます。
- 地面から出すときは、しゃがむところから流します。`Enter` で方向と蹴る足を決め、ダッシュのクリップを最初から `dashCrouchBlendSeconds`（0.1秒）の補間で流します。しゃがむ間は `dashCrouchSpeed`（200）から0まで遅くなり、終わったら飛ぶところに入ります（アニメーションはそのまま流れ続ける）。空中で出したときと、連打で続けて出すときは、クリップを `dashKickStartTime`（f04）から流してしゃがみを飛ばします（`Begin` は方向と蹴る足を決めるだけで、アニメーションは `PlayKick` で流します）。
- ダッシュの時間（2026-11-06）: 今は原神の動画と同じ長さ（しゃがむ 0.13秒・飛ぶ 0.23秒・着地 0.17秒）です。それより前は、平均の速さ 1000（0.3秒）・着地 0.2秒でしたが、「ダッシュ時間を2分の1にして速く」とのことで、平均の速さ 2000（0.15秒）、一蹴りと着地のアニメーションを2倍、着地を 0.1秒にしました。しゃがみ込み（約0.1秒）はそのままです。そのあと「元の4分の3の時間でいい」とのことで、平均の速さ 約1333（0.225秒）、アニメーション約1.33倍、着地 0.15秒にしました。さらに、ゲームの録画を原神の動画と並べて見たところ、しゃがみが1コマで終わって見えず、着地で一気に起き上がっていたので、しゃがみ込みを約0.15秒（1.8倍、入る補間 0.1秒）、着地を 0.25秒（0.8倍）にのばしました。
- 飛び終わったら（予約がなければ）着地に入ります（`BeginLanding`）。クリップは着地のところへ流れ続け、`dashLandSeconds` の間は `dashEndSpeed`（480、走る速さ）で進みます。飛ぶところの速さも、0 まで落とさず `dashEndSpeed` で終わるようにしています（`CalcDashProgress(t, 終わり÷平均)`）。着地の間にもう一度押すと、すぐ次のダッシュになります。
- 同じく `Exit` で `context.nextStartTimes[走り・歩き]` に、最後に蹴った足に合わせた開始位置を入れます。`PlayAnimation()` はそれがあれば `ModelRender::PlayAnimationFromTime()` で途中から（補間つきで）再生します。

  | 最後に蹴った足 | 走り（Run）の始め | 歩き（Walk）の始め |
  |---|---|---|
  | 左（右足で着地） | f05 | f00 |
  | 右（左足で着地） | f12 | f17 |

  走りはダッシュの最後（原神の動画の 33.94秒）と前後の足が同じコマです。歩きは前のやり方のときに測った値のままです（着地を足す前は、飛んだポーズに合わせて Run f04/f13、Walk f22/f04 にしていました）。最初のコマから始めると前後の足が逆になり、補間の間に足が入れ替わって、前の足だけ先に下りてつまずいたように見えました（2026-11-06）。

### 連打：ダッシュ中に押された分を覚えておき、進み切ったらその場で次を始める

```cpp
PlayerStateId PlayerDashState::CheckTransition(...) const
{
    // 進み切っていない、または次のダッシュを予約している間はダッシュのまま
    if (!IsFinished() || m_isNextDashQueued || input.dash.isTrigger) {
        return PlayerStateId::Dash;
    }
    return PlayerGroundState::SelectByInput(context, input);   // 押しっぱなしなら Run
}

void PlayerDashState::Update(...)
{
    // 入ったフレームの押下は、このダッシュを始めた押下なので数えない
    if (input.dash.isTrigger && !m_isFirstFrame) { m_isNextDashQueued = true; }
    m_isFirstFrame = false;

    // 進み切っていて予約があれば、そのときの入力の方向へ次のダッシュを始める
    if (IsFinished() && m_isNextDashQueued) {
        m_isNextDashQueued = false;
        Begin(context, input);     // 方向と時間を決め直し、反対の足で蹴る（Enter は呼ばない）
    }
    ...
}
```

| 書き方 | 理由 |
|---|---|
| 次のダッシュはステートを出ずに、同じステートの中で始め直す | ステートマシンは同じステートへの遷移をしない（`Enter` が呼ばれない）ため。蹴る足は毎回入れ替えるので、別のクリップへの切り替えになり、着地からもう一度流れる |
| 方向・時間・アニメーションを決める処理を `Begin()` に分け、`Enter` と連打の両方から呼ぶ | 最初のダッシュと2回目以降で、方向の決め方を同じにする |
| `CheckTransition` で `input.dash.isTrigger` も見る | 進み切ったちょうどのフレームに押されたとき、`Update` で予約される前にステートを出てしまわないように |
| 入ったフレームの押下を数えない（`m_isFirstFrame`） | `Enter` と同じフレームの `Update` にも同じ押下が来るので、数えると1回押しただけで2回出てしまう |

走るのは、プレイヤーの入力元が「ダッシュボタンを押しているか」をそのまま `isRun` に入れているためです（[入力の設計](入力の設計.md)）。ダッシュの間は `isRun` を見ないので、押しっぱなしでもまずダッシュが出て、終わったあと `SelectByInput()` で Run になります。

### Frozen：何もしないステート

`Update` は `Move(Vector3::Zero)`（重力だけ）、`CheckTransition` は `SelectByInput()` を返すだけです。凍っている間はステートマシンが `CheckTransition` を呼ばないので、呼ばれたときは解けています。

## 4. 使い方

### 新しいステートを足す（例: しゃがみ）

1. `PlayerStateId` に `Crouch` を足す（`Num` より前）。
2. `PlayerState` を継承したクラスを作る。

```cpp
class PlayerCrouchState : public PlayerState {
public:
    PlayerStateId GetId() const override { return PlayerStateId::Crouch; }
    const char* GetName() const override { return "Crouch"; }

    void Enter(PlayerStateContext& c, const CharacterInput& input) override {
        c.PlayAnimation(enPlayerAnimClip_Crouch);   // クリップの番号も足す
    }
    PlayerStateId CheckTransition(const PlayerStateContext& c, const CharacterInput& input) const override {
        if (!input.crouch.isPress) {                // CharacterInput にボタンを足す
            return PlayerGroundState::SelectByInput(c, input);
        }
        return PlayerStateId::Crouch;
    }
    void Update(PlayerStateContext& c, const CharacterInput& input, float deltaTime) override {
        c.mover->MoveByInput(input, c.mover->GetSettings().walkSpeed * 0.5f, deltaTime);
    }
};
```

3. `PlayerStateMachine.cpp` のコンストラクタで `m_states[...] = std::make_unique<PlayerCrouchState>();` を足す。
4. 入口を決める。地面から入るなら `PlayerGroundState::CheckTransition` に条件を足す。
5. `Game.vcxproj` と `.filters` にファイルを足す（フィルタは `Source\PlayerState`）。

| 一緒に足すもの | 場所 |
|---|---|
| ボタン | `CharacterInput` と `PlayerInputSource`（[入力の設計](入力の設計.md)） |
| アニメーション | `EnPlayerAnimClip` と Player の `MakeModelDesc()`（[キャラクターモデルの設計](キャラクターモデルの設計.md)） |

| しゃがむ長さ / 入るときの補間 / 進む速さ / 蹴り始めるところ | 4コマ（約0.13秒） / 0.1秒 / 200 → 0 / f04 | 同上 |
| 着地の長さ | 5コマ（約0.17秒） | 同上 |
| 走りから止まる（Stop）の長さ / 滑る長さ | 1.0秒 / 0.47秒（約112 滑る）。ほかの数値は [走りから止まる設計](走りから止まる設計.md) | 同上 |
| 立ち止まっているとみなす移動入力の長さ | 0.1 | 同上 |
| アニメーションの切り替えの補間時間 | 0.2秒 | 同上 |

## 6. 決めたこと

### ステートパターンにした（以前は Player の中の if）

| 以前 | 今 |
|---|---|
| `Player::UpdateAnimation()` が if を並べて、毎フレームアニメーションを決めていた | ステートが、入ったときに自分のアニメーションを流す |
| 速さは `CharacterMover`、アニメーションは `Player` と、判断が分かれていた | 「歩く」なら速さもアニメーションも `PlayerWalkState` にある |
| ダッシュの残り距離は `CharacterMover`、ポーズのフラグは `Player` にあった | ダッシュのことは `PlayerDashState` だけにある |

### 関数テーブルではなく、ステートごとのクラスにした

| | クラス（採用） | 関数テーブル |
|---|---|---|
| 流れの追いやすさ | ファイルをまたぐ | Player の中だけで上から読める |
| ステートだけが使うデータ | そのクラスに閉じ込められる | Player のメンバーになり、Player が膨らむ |
| Enemy などへの流用 | しやすい | しにくい |

今の6ステートなら関数テーブルでも足りますが、剣の連続攻撃・回避・のけぞりなど、ステートごとにデータを持つ動きを足す予定なのでクラスにしました。

### ダッシュと走るを1つのボタンにした（2026-11-06）

ふだんは歩き、ボタンを押すとダッシュ、押しっぱなしで走る、連打でダッシュが続く、という操作にしました（原神のダッシュに近い操作）。

| 以前 | 今 |
|---|---|
| 走る（左Shift を押している間）とダッシュ（L）が別のボタン | 左Shift 1つ。押した瞬間にダッシュ、押しっぱなしで走る |
| 左Shift を押すとすぐ走る | 押した瞬間はダッシュが出て、走るのはそのあと |
| ダッシュ中に押しても何も起きない | ダッシュ中に押すと、進み切ったあと続けてダッシュが出る |

ステートの側は、ダッシュの連打（予約）を足しただけです。「押しっぱなしで走る」は、入力元が `isRun` にダッシュボタンの押下を入れるだけで実現しています。

### ラッシュをダッシュと呼ぶことにした（2026-11-06）

以前は「ラッシュ（Rush）」と呼んでいました。走りの一部として素早く前へ出る動きなので、「ダッシュ（Dash）」に名前を変えました。
ステート（`PlayerDashState`・`PlayerStateId::Dash`）、入力（`CharacterInput::dash`）、数値（`dashDistance` など）の名前をまとめて変えただけで、動きは変えていません。

### ダッシュを止めたポーズから、前へ倒した走りに変えた（2026-11-06）

以前は Run の疾走ポーズ（0.23秒の位置）で止めたまま滑っていました（仮の状態）。
今は、Run の体全体を前へ倒し、1歩分（着地して蹴り、宙へ飛び出す）にした `DashL` / `DashR` を1回流し、飛び出したポーズで止めます。等速で流し、入るときの補間を 0.05秒と短く、出るときを 0.5秒と長くしています（はじめ 0.4秒。前の足が早く着地して見えたので延ばした）。
2026-11-06 に「バタバタして見える」「走りへ移るのが早い」とのことで、0.2秒・1.5倍から 0.3秒・等速に変え、出るときの補間を足しました。
移動も一定の速さをやめ、蹴った瞬間に平均の2倍で飛び出して、だんだん止まる（ease-out）ようにしました。「地面を一蹴りして前へ出る」感じを出すためです。

| 候補 | 選ばなかった理由 |
|---|---|
| 前へ倒した走りをループで流す（いったんこうした） | ダッシュの 0.2秒の間に足が回るだけで、蹴って飛び出した感じが出ない |
| 一定の速さで進む | 滑っているように見え、蹴った勢いが伝わらない |
モーションの作り方と角度は [プレイヤーのアニメーションの設計](プレイヤーのアニメーションの設計.md) にあります。

### 凍結への遷移はステートマシンが行う

凍結はどのステートからでも起こるので、各ステートに書くと同じ行が並びます。「行動できないなら Frozen」だけは `PlayerStateMachine` が先に見ます。

### アニメーションの速さは、入るときに戻す

凍結は `StatusEffects` がアニメーションを止めます（速さ0）。ダッシュなどの `Exit` で速さを戻すと、**ダッシュ中に凍ったとき、止めたアニメーションが動き出して**しまいます。
そのため、アニメーションを流すステートは `Enter` で `PlayAnimation()`（切り替えて、そのステートの速さにする。Walk とダッシュ以外は1）を呼び、Frozen は触りません。

### 以前と動きが変わったところ

| 内容 | 以前 | 今 |
|---|---|---|
| ダッシュ中のジャンプ | できた | できない（終わってから） |
| ごく小さい移動入力（0.1 未満） | 待機アニメーションのまま、ゆっくり動いた | 動かない（Idle） |
