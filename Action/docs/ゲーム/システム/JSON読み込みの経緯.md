## 2026-11-08: JSON を読む仕組みを入れた

### 何をしたか

「ヘッダーと CPP を入れるだけで JSON が使え、あとは中身を使うだけ」という形にしたいという要望から始めた。

次の2つの案を比べた。

| 案 | 内容 | 結果 |
|---|---|---|
| 1 | nlohmann/json（`json.hpp` 1ファイル）と、読み込み係の `JsonFile.h` / `.cpp` を入れる | **これにした** |
| 2 | 自前のパーサーを `Json.h` / `Json.cpp` の2ファイルで書く | 外のライブラリは入らないが、細かい仕様を自分で保守することになるのでやめた |

まずは読み込みの仕組みだけを入れ、`PlayerConfig` などの調整値を JSON に出すのは後でやることにした。JSON の置き場所は `Assets/data/` にした。

### どう確かめたか

- Game.sln を Debug x64 でビルドし、`JsonFile.cpp` に警告もエラーも出ないことを確かめた。
- ゲームは起動せず、`JsonFile.cpp` だけを小さなテスト用のプログラムと一緒に `/W4` でビルドして動かした。
  - 数値・文字列・配列・入れ子・コメント入りの JSON が読めた。
  - ないキーは `value()` の既定値になった。
  - `Assets/data/` から数えたパスと、`Assets/` から書いたパスの両方で読めた。
  - ファイルがないとき・書き方が壊れているときは `TryLoad` が false を返し、`Load` の結果から `value()` で既定値が取れた（落ちない）。
- 確かめに使ったプログラムと JSON は、リポジトリには入れていない。

## 2026-11-08: プレイヤーの調整値を player.json に出した

設計: [プレイヤーの調整値の設計](../プレイヤー/プレイヤーの調整値の設計.md)

### 何をしたか

`JsonFile::Load("player.json")` を Player で直接呼ぶか、分けるかを相談した。Player が JSON を知る形にはせず、もとからあった `PlayerConfig`（数値とパスだけを置く場所）に読ませることにした。新しく `PlayerConfigLoader` のようなクラスを作る案は、「数値を用意する場所」が2つになるのでやめた。

あわせて次のことを決めた。

| 決めたこと | 内容 |
|---|---|
| 読む回数 | 最初の1回だけ読んで取っておく |
| 構造体への詰め方 | 相談では「値が 10個くらいまでで、読む場所が1か所なら `value()`、それより多ければ `from_json`」を目安にした。Player は約50個あるが、JSON の段と構造体が1対1でなく、コマ数から秒への計算もあるので、段ごとの関数の中で1つずつ読む形にした |
| JSON に出す範囲 | 数値に加えて、モデルとアニメーションのパスも出す。剣のパスも出す。剣を付けるボーンの名前はコードに残す |
| 計算で作る値 | JSON には元の値（ダッシュの距離と 7コマ、走る速さ 480）を書き、計算はコードに残す |
| ファイルの分け方 | `player.json` 1つにし、中を `move`・`dash`・`stop`・`model`・`animation`・`sword` などの段に分ける |
| 敵・魔法 | 同じ形にしたいが、まず Player だけで作る |

パスを JSON から読むと `const char*` では指す先が消えるので、`AnimClipDesc::path`・`CharacterModelDesc::modelPath`・`WeaponAttachmentDesc::modelPath` を `std::string` にした。

### どう確かめたか

- Game.sln を Debug x64 でビルドし、エラーが出ないことを確かめた。
- ゲームは起動せず、`player.json` を `JsonFile` で読む小さなプログラムを作り、次を確かめた。
  - ファイルの頭のコメントも含めて、`player.json` が読めた。
  - `PlayerConfig.cpp` が読むキーが、全部 `player.json` にあった（クリップの名前は `CLIP_TABLE` と同じ）。
- `player.json` の値は、書き換える前の `PlayerConfig.cpp` の値をそのまま写した。コマ数で書いたものは、前の `4.0f / 30.0f` などと同じ計算になる。
- ゲームの中での動き（見た目が前と変わらないこと、出力ウィンドウに `[PlayerConfig]` が出ないこと）は、ユーザーに確かめてもらう。

## 2026-11-08: プレイヤーの調整値の手順書を書いた

手順: [プレイヤーの調整値の手順](../プレイヤー/プレイヤーの調整値の手順.md)

main に「実装の方法は手順書に書く」決まりが入ったので、`player-json` ブランチに手順書を足した。JSON を読む仕組み（`JsonFile`）の手順書は、別の作業で [JSON読み込みの手順](JSON読み込みの手順.md) として書かれているので、それを前提にした。

### どう確かめたか

- 作業用フォルダー（git worktree）に `player-json` を出し、`CharacterModel.h/.cpp`・`WeaponAttachment.h/.cpp`・`PlayerConfig.cpp` を main のもの（JSON を読む前）に戻し、`player.json` を消した状態を作った。この状態でソリューションのビルドが通ることを確かめた。
- 手順書の `<!-- new: … -->`・`<!-- edit: … -->` の印が付いたコードを、手順1から順に当てるスクリプトを作った。手順1だけ、手順1〜2、…、手順1〜9 と9回当て、そのたびに Game をビルドした。9回とも、エラーなくビルドが通った。
- 手順9まで当てた結果は、`player-json` の5つのファイルと `player.json` に、1行も違いがなかった。
- ゲームの画面での確かめ（各手順の「確かめ方」の起動して見るところ）はしていない。ユーザーに確かめてもらう。
