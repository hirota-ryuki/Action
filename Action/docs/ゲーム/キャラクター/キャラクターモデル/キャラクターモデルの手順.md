# キャラクターモデルの手順

設計: [キャラクターモデルの設計](キャラクターモデルの設計.md)

キャラクターのモデルとアニメーションの部品（`CharacterModel`）を作り、キャラクターに持たせて、Player と Enemy のモデルを出すまでの手順です。

**出来上がるもの:** Player（SK_Player）と Enemy（黒騎士）のモデルが表示され、入力で動きます。アニメーションのクリップは、ステートの手順（[敵のステートの手順](../../敵/敵のステート/敵のステートの手順.md)・[プレイヤーのステートの手順](../../プレイヤー/プレイヤーのステート/プレイヤーのステートの手順.md)）で足します。

**前提:**

- Visual Studio で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 先に [移動の手順](../移動/移動の手順.md) を済ませておく（順番は [README の「ゲームを作る順番」](../../../README.md#ゲームを作る順番)）。
- モデル（`Assets/modelData/player/Model/SK_Player.FBX`・`Assets/modelData/enemy/BlackKnight/BlackKnight.fbx`）は、リポジトリにもとからある。黒騎士の作り方は [黒騎士のMeshyプロンプト](../../敵/黒騎士のMeshyプロンプト/黒騎士のMeshyプロンプト.md) にある。FBX をそのまま読む仕組みは、エンジンにもとからある（[モデル読み込みの設計](../../../エンジン/モデル読み込み/モデル読み込みの設計.md)）。
- この手順書では、パスを `const char*` で持つ形で書く。[プレイヤーの調整値の手順](../../プレイヤー/プレイヤーの調整値/プレイヤーの調整値の手順.md)（ゲームの手順書の最後）の手順1で `std::string` に変える。

| 手順 | 足すもの | 確かめ方 |
|---|---|---|
| 1 | モデルとアニメーションの部品 `CharacterModel` | ビルドが通る |
| 2 | キャラクターに持たせる | モデルが見えて、動く |

**読み方:**

- 足す場所は「〇行目 `その行に書いてあること` の下」で示します。行番号は、それより前の小手順を済ませたときの番号です。
- 枠の左の数字は、足したあとの行番号です。右の枠のコードを、そのまま書きます。
- コードの下に、3つを置きます。
  - 「行・何をしているか」の表: 1行ずつの動き。
  - 「なぜ」「効果」: その小手順でそう書く理由と、書くと何ができるようになるか。
  - 「初めて出てくる名前」の表: このページで初めて出てくる変数・引数・関数・型・値・C++ の書き方を、コードに出てくる順に並べます。2回目からは載せないので、わからない名前はページ内検索（`Ctrl+F`）で最初に出てきた所を探してください。「どこから来たもの」で、このゲームで作ったもの・エンジン（k2Engine）の機能・C++ の標準ライブラリ・C++ の書き方のどれかがわかります。
- [前提知識](../../../前提知識.md) で「よく知っている」にあるもの（クラス・ポインター・`std::vector`・`std::string`・`ModelRender`・`AnimationClip`・`Vector3`・`Quaternion`・`std::unique_ptr`・`static_cast`・`namespace`・三項演算子・範囲 for・`nullptr` など）は、表に載せません。「まあまあ」にある `std::make_unique` は載せます。
- VSCode で `Ctrl+Shift+V` を押してプレビューで読みます。

	bool EndsWithFbx(const std::string& path)
