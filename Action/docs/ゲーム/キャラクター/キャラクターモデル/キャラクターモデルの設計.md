# キャラクターモデルの設計

作成日: 2026-11-06
対象: `Game/Source/Character/Components/CharacterModel.*`
経緯: [キャラクターモデルの経緯](キャラクターモデルの経緯.md)
手順: [キャラクターモデルの手順](キャラクターモデルの手順.md)（何もない状態から、どのファイルに何を足すか）

Player と Enemy のモデル・アニメーションを読み込む共通の部品 `CharacterModel` のページです。
ほかの部品との関係は [キャラクターの構成](../キャラクターの構成/キャラクターの構成.md) を見てください。

- **キャラクターが持つのはデータだけ**: どのモデル・アニメーションを使うかを `CharacterModelDesc` に書いて渡す。
- **読み込みの決まりは部品の中に閉じ込める**: FBX の変換・リターゲット・「クリップを先に読む」は `CharacterModel` だけが知っている。

**用語:**

| 用語 | 何のことか |
|---|---|
| FBX | 3D モデルやアニメーションをやりとりするためのファイル形式（`.fbx`）。ゲームではそのまま読まず、tkm・tka に変換して使う |
| tkm・tks・tka | k2Engine 独自のファイル。tkm はモデル（頂点・面・マテリアル）、tks はスケルトン（ボーンの並び）、tka は1つのアニメーションクリップ |
| スケルトン・ボーン | ボーンは、モデルの中に入れた「関節」の1本。ボーンを木のようにつないだ全体がスケルトンで、ボーンを動かすとモデルが動く |
| リターゲット | あるモデル用に作ったアニメーションを、別の骨格のモデルに移すこと。ここでは、ボーンの名前が同じものどうしに動きを移す |

---

## 1. 全体像

```
Player / Enemy
  │ Character::Start(): m_model.Init(MakeConfig().model)   ← Desc は各キャラクターの Config に書いたデータ
  ▼
CharacterModel ── 持つ ──▶ ModelRender ◀── 参照: StatusEffects（色）・ステート（アニメーション）
  │
  └─ Init のときだけ使う ─▶ FbxRuntimeImporter（FBX → tkm / tks / tka）
```

---

## 2. CharacterModelDesc：キャラクターごとのデータ

| 項目 | 内容 | Player | Enemy |
|---|---|---|---|
| `modelPath` | `.tkm` か `.fbx` | `SK_Player.FBX` | `BlackKnight.fbx`（黒騎士。SK_Player と同じ骨格） |
| `upAxis` | モデルの上方向 | Z（3ds Max） | Z |
| `scale` | 大きさ | 1.128 | 1.4（兜を Player の顔と同じ大きさにする） |
| `clips` | クリップの一覧。**添字がクリップの番号** | 12個（Idle・Walk・Run・JumpStart・JumpLoop・JumpLand・Dash・StopL・StopR・Attack1〜3 の FBX。パスは player.json） | 8つ（Idle・Walk・Run・Attack1〜3・Hit・Dead の FBX。既存のモーションを `retarget_black_knight.py` で黒騎士へ移したもの。[黒騎士のモーションの設計](../../アニメーション制作/黒騎士のモーション/黒騎士のモーションの設計.md)） |

## 3. CharacterModel：関数

コード: [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h)、[CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp)

| 関数 | 呼ぶとき | 内容 |
|---|---|---|
| `Init(desc)` | `Start()` で1回 | クリップを読み込み、モデルを初期化する |
| `SetTransform(位置, 回転)` | 毎フレーム | 大きさは Desc のもの |
| `Update()` / `Draw(rc)` | 毎フレーム | `ModelRender` にそのまま渡す |
| `PlayAnimation(番号, 補間秒)` | アニメーションを変えるとき | 番号は `clips` の添字 |
| `IsPlayingAnimation()` | ループしないクリップが終わったかを見るとき | 攻撃・ひるみ・着地などのステートが、終わったら次へ移るのに使う |
| `GetModelRender()` | ほかの部品に渡すとき | アニメーション速度・ボーン・状態異常の色など |

## 4. 実装方法

### Init の流れ

```cpp
void CharacterModel::Init(const CharacterModelDesc& desc)
{
    m_scale = Vector3(desc.scale, desc.scale, desc.scale);
    m_animClips = std::make_unique<AnimationClip[]>(numClips);   // ① クリップの入れ物

    std::string tksPath;
    for (int i = 0; i < numClips; i++) {
        std::string tkaPath = desc.clips[i].path;
        if (EndsWithFbx(tkaPath)) {                                // ② FBX なら変換
            if (tksPath.empty()) {
                tksPath = ToTksPath(FbxRuntimeImporter::ResolveToTkmFilePath(desc.modelPath));
            }
            tkaPath = FbxRuntimeImporter::ResolveAnimationFbxToTka(desc.clips[i].path, tksPath.c_str());
        }
        if (tkaPath.empty()) { continue; }                         //    変換に失敗したクリップは飛ばす
        m_animClips[i].Load(tkaPath.c_str());                      // ③ 読む
        m_animClips[i].SetLoopFlag(desc.clips[i].isLoop);
    }
    m_modelRender.Init(desc.modelPath, m_animClips.get(), numClips, desc.upAxis);  // ④ 最後にモデル
}
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 型 | `CharacterModelDesc` | キャラクターごとの違いを、データだけで渡すため | モデルのパス・上方向・大きさ・クリップの一覧を持つ構造体 | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) |
| メンバー変数 | `m_scale` | 大きさを Init で決めておくため | モデルの大きさ（`Vector3`）。`SetTransform()` が毎回使う | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) の `CharacterModel` クラス |
| メンバー変数 | `m_animClips` | クリップを、動かない場所に置いておくため | `AnimationClip` の配列。`ModelRender` がこの配列を指し続ける | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) の `CharacterModel` クラス |
| 変数 | `numClips` | クリップの数を持つため | `desc.clips` の数（`int`）。配列の大きさと、ループの回数に使う | ゲームの [CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp) の `Init()` の中 |
| 関数 | `std::make_unique` | 配列を確保して、`unique_ptr` に入れるため | `AnimationClip[]` を `numClips` 個作って返す | C++ の標準ライブラリ（`<memory>`。[k2EngineLowPreCompile.h](../../../../k2EngineLow/k2EngineLowPreCompile.h) で読み込み済み） |
| 変数 | `tksPath` | スケルトン（`.tks`）のパスを、1回だけ作って使い回すため | `.tks` のパス。空のうちは、まだ作っていない | ゲームの [CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp) の `Init()` の中 |
| 変数 | `tkaPath` | 読み込むクリップのパスを持つため | 初めは Desc のパス。FBX なら変換後の `.tka` のパスに置き換える | ゲームの [CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp) の `Init()` の中 |
| 関数 | `EndsWithFbx()` | FBX かどうかを、拡張子で見分けるため | 末尾が `.fbx`（大文字小文字は区別しない）なら `true` を返す | ゲームの [CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp)（名前のない `namespace` の中） |
| 関数 | `ToTksPath()` | tkm のパスから、`.tks` のパスを作るため | 拡張子を `.tks` に差し替えたパスを返す | ゲームの [CharacterModel.cpp](../../../../Game/Source/Character/Components/CharacterModel.cpp)（名前のない `namespace` の中） |
| 関数 | `FbxRuntimeImporter::ResolveToTkmFilePath()` | FBX を、読める tkm にするため | FBX なら tkm・tks に変換（済みなら変換しない）して、使う tkm のパスを返す | k2EngineLow（エンジン）の [FbxRuntimeImporter.h](../../../../k2EngineLow/tkFile/FbxRuntimeImporter.h) |
| 関数 | `FbxRuntimeImporter::ResolveAnimationFbxToTka()` | アニメーションの FBX を、モデルの骨格に合わせた tka にするため | スケルトン（`.tks`）のボーン名でリターゲットして `.tka` に変換し、そのパスを返す。失敗したら空の文字列 | k2EngineLow（エンジン）の [FbxRuntimeImporter.h](../../../../k2EngineLow/tkFile/FbxRuntimeImporter.h) |
| メンバー変数 | `path`・`isLoop` | クリップごとのファイルと、ループするかを渡すため | `.tka` か `.fbx` のパスと、ループ再生するか。`desc.clips[i]` が持つ | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) の `AnimClipDesc` |
| メンバー変数 | `m_modelRender` | モデルの表示とアニメーション再生を任せるため | `ModelRender`。`CharacterModel` の関数は、これに渡すだけ | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) の `CharacterModel` クラス |
| メンバー変数 | `upAxis` | モデルの上方向を渡すため | 上方向の種類（`EnModelUpAxis`）。3ds Max のモデルは Z | ゲームの [CharacterModel.h](../../../../Game/Source/Character/Components/CharacterModel.h) の `CharacterModelDesc` |

| 書き方 | 理由 |
|---|---|
| クリップの入れ物を `unique_ptr<AnimationClip[]>` で確保する | `ModelRender` がクリップの配列を指し続けるので、あとで動かない入れ物にする（`vector` は伸びると場所が変わる）。数は Desc で決まる |
| FBX かどうかは拡張子（大文字小文字を区別しない）で見分ける | Desc にフラグを足さずに済む。パスを書くだけでリターゲットされる |
| スケルトンの変換は、最初に FBX のクリップが来たときに1回だけ | tka しか使わないキャラクターでは変換しない |
| `.tks` のパスは tkm の拡張子を差し替えて作る | FBX→tkm 変換が同じフォルダ・同じ名前で `.tks` を作る決まりなので |
| モデルの Init は最後 | `ModelRender::Init` が中で 0 番のクリップを再生するので、先にクリップを読んでおく必要がある |

変換結果は更新日時でキャッシュされるので、同じ FBX を何度渡しても変換は1回です。

### 大きさは Init で決めておく

`SetTransform()` は `SetTRS(位置, 回転, m_scale)` を呼ぶだけです。大きさは毎フレーム変わらないので、持ち主は位置と回転だけを渡します。

## 5. 使い方

| やりたいこと | すること |
|---|---|
| 新しいキャラクターにモデルを持たせる | `Character` を継承し、`MakeConfig()` の `model` に Desc を入れる（Init は `Character` が行う） |
| アニメーションを足す | クリップ番号の enum に足し、`MakeModelDesc()` の `clips` に1行足す。FBX ならパスを書くだけでリターゲットされる |
| Player に新しいモーションを入れる | UE で SK_Player にリターゲットした FBX を作る（[プレイヤーのアニメーションの設計](../../アニメーション制作/プレイヤーのアニメーション/プレイヤーのアニメーションの設計.md)）。そのあと `Assets/data/player.json` の `animation.clips` にパスを書く（[プレイヤーの調整値の設計](../../プレイヤー/プレイヤーの調整値/プレイヤーの調整値の設計.md)） |

```cpp
// Enemy.cpp
CharacterModelDesc MakeModelDesc()
{
    CharacterModelDesc desc;
    desc.modelPath = "Assets/modelData/enemy/BlackKnight/BlackKnight.fbx";
    desc.upAxis = enModelUpAxisZ;
    desc.scale = MODEL_SCALE;  // 1.4
    desc.clips.resize(enEnemyAnimClip_Num);
    desc.clips[enEnemyAnimClip_Idle] = { "Assets/modelData/enemy/BlackKnight/Animation/Idle.fbx", true };
    desc.clips[enEnemyAnimClip_Walk] = { "Assets/modelData/enemy/BlackKnight/Animation/Walk.fbx", true };
    // ……Run・Attack1〜3・Hit・Dead も同じ形（攻撃・ひるみ・倒れるはループしない）
    return desc;
}
```

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `MODEL_SCALE` | 敵の大きさを1か所で決めるため | 敵の大きさ（`1.4f`）。`Enemy.cpp` の名前のない `namespace` の中の定数 | ゲームの [Enemy.cpp](../../../../Game/Source/Enemy/Enemy.cpp) |
| 値 | `enModelUpAxisZ` | モデルの上方向が Z 軸だと伝えるため | `EnModelUpAxis` の値。上方向が Z のモデル（3ds Max）で使う | k2EngineLow（エンジン）の [GraphicsEngine.h](../../../../k2EngineLow/graphics/GraphicsEngine.h) |
| 関数 | `resize()` | 配列の数を、クリップの数に合わせるため | `std::vector` の要素の数を変える。ここでは敵のクリップの数にする | C++ の標準ライブラリ（`std::vector` のメンバー） |
| 値 | `enEnemyAnimClip_Num` | クリップの数を、enum から決めるため | 敵のクリップの種類の数（8）。enum の最後に置いた値 | ゲームの [EnemyState.h](../../../../Game/Source/Enemy/State/EnemyState.h)（`EnEnemyAnimClip`） |
| 値 | `enEnemyAnimClip_Idle`・`enEnemyAnimClip_Walk` | クリップの番号を、名前で書くため | `clips` の添字になる番号（Idle は 0、Walk は 1） | ゲームの [EnemyState.h](../../../../Game/Source/Enemy/State/EnemyState.h)（`EnEnemyAnimClip`） |
| C++ の書き方 | `{ "パス", true }` | `AnimClipDesc` を1行で作るため | 波かっこで、`path` と `isLoop` を順に入れた `AnimClipDesc` を作る | C++ の書き方 |

## 6. 決めたこと

### プレイヤー専用のクラスにしなかった

`PlayerModel` を作ると、コードの置き場所が変わるだけで、使うのは Player だけになります。
Enemy も同じ読み込み方（クリップを読む → `ModelRender::Init`）をしていたので、汎用の部品にして、違い（パス・向き・大きさ）をデータにしました。

### Init は持ち主が呼ぶ

ほかの部品と同じく、Player・Enemy が自分の `Start()` で呼びます。`NewGO` は引数を取れないので、外から Desc を渡すには `Start()` より前に Setter を呼ぶしかなく、呼び忘れに気づきにくいためです。

---

## 7. 既知の課題

- **アニメーションの FBX は、キャラクターごとに別のファイルにする**: tka はアニメーションの FBX の隣に1つだけ作られ、tka のボーンの番号はモデルのボーンの並び（モデルごとに違う）で決まる。同じ FBX を2つのモデルで使うと tka を上書きし合う。今は黒騎士のアニメーションを黒騎士用に作っているので起きないが、ほかのキャラクターとアニメーションを分け合うときは、FBX をそのキャラクターのフォルダに写して使う。
- **見た目の差し替え（キャラクター選択など）はできない**: 必要になったら、`MakeModelDesc()` の中身を外から渡す形にします。
