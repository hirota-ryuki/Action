# 骨の調整の層の経緯

設計: [骨の調整の層の設計](骨の調整の層の設計.md)

## 2026-11-19 骨の調整を層にまとめ、焼き込めるようにした

### 何をしたか

ゲームのコードで骨に手を加えている所（体の連動・揺れ物・照準へのひねり・黒騎士の右腕の調整・一人称の腕）を、1つの部品 `PoseLayers` に「層」として並べるようにした。あわせて、層を重ねた姿勢をクリップに焼き込む `PoseBaker` と、それを FBX にする Blender のスクリプト `pose_bake_to_fbx.py` を作った。最初に焼き込みに使ったのは、一人称の腕（[一人称の腕の経緯](../../プレイヤー/一人称の腕/一人称の腕の経緯.md) の 2026-11-19）。

### なぜ

1. **骨の計算のあとの処理を、それぞれが登録していた。** エンジンの `Skeleton` は、骨のワールド行列を計算したあとに呼ぶ関数を1つしか持てない。Character は「体の連動 → 派生クラス（`OnPostBodyLink`）→ 揺れ物」を登録し、黒騎士はそれを自分の右腕の調整で上書きし、一人称の腕は別のモデルに自分で登録していた。どこで何が重なるかを、コードを3か所読まないとわからなかった。
2. **毎回同じ形になる調整も、毎フレーム計算していた。** 一人称の腕の拳・腕の置き方は、カメラから見ると毎回同じ形なので、クリップにできる（ユーザーと相談して決めた）。

### 決めたこと

- 層は `std::function` で持つ。体の連動・揺れ物などの部品はそのままにし、`Update` を呼ぶラムダを層として足す（部品の中は変えない）。
- 焼き込みは、ゲームで作った姿勢を JSON に書き、Blender で FBX にする。層の計算を Blender に写さない。
- 座標の対応は、骨の位置から最小二乗で求める（設計の「決めたこと」）。

### 作り直したこと

最初は別のPC で作り、F1 の窓「骨の調整」（層ごとの入り切り・効き 0〜1 のスライダー・選んだクリップを JSON に焼き込むボタン）と、焼き込みの起動の指定を Release ビルドにも入れた形で main にマージした（#199）。その main は push する前にそのPC が使えなくなったので、このPC で作り直した。作り直すときに、ユーザーと相談して次のように変えた。

| 前のPC の形 | 作り直した形 | 理由 |
|---|---|---|
| F1 の窓「骨の調整」で層の入り切り・効き・焼き込みができた | 窓は入れない。層は関数と「焼き込むか」だけを持つ | 窓の焼き込むボタンは、その場の状態（走る速さ・向き）で体の連動が変わり、焼き込んだクリップの使い道も決まっていなかった。効きを弱める処理は、大きさ 0 の骨（腕以外を見せない層）を正しく混ぜられなかった |
| 焼き込み・確かめの起動の指定が Release ビルドにもあった | Debug ビルドだけ（`#ifdef _DEBUG`） | 開発のときにだけ使う |

### どう確かめたか

- `Game.sln` を Debug / x64 と Release / x64 でビルドし、どちらも通ることを見た。
- 一人称の腕の6本を焼き込み、Blender（5.1）で FBX にした。Blender で求めた座標の対応のずれは、246本の骨で最大 0.000554（アーマチュアの単位）。キーを打った姿勢とゲームの姿勢の、骨の位置のずれは最大 0.000128。
- ゲームで FBX を読み、層を重ねずに流した姿勢と JSON の姿勢を比べた（`-verifyFirstPersonArms`）。6本とも骨の位置のずれは最大 0.0005（モデルの単位、cm）。
- ゲームを動かし、一人称の腕を、コードで形を作る前の版と並べて撮った（画像は [一人称の腕の経緯](../../プレイヤー/一人称の腕/一人称の腕の経緯.md)）。
- Player の体の連動・揺れ物・照準へのひねり、黒騎士の右腕の窓は、層に移しただけで中身は変えていない。画面では確かめていない。
