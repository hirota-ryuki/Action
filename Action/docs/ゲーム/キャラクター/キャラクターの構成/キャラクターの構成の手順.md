# キャラクターの構成の手順

設計: [キャラクターの構成](キャラクターの構成.md)
経緯: [キャラクターの構成の経緯](キャラクターの構成の経緯.md)

キャラクターの基底クラス（`Actor` → `Character`）と、まだ何もできない `Player`・`Enemy` を作り、`Game` から置くまでの手順です。`Character` が持つ部品（入力・移動・モデル・状態異常・当たり判定・魔法）は、このあとの手順書で1つずつ足していきます。

**出来上がるもの:** `Character` が「初期化の順番」と「1フレームの順番」を決め、派生クラスは「動く」部分（`UpdateAction()`）だけを書く形ができます。`Game` が Player と Enemy を作りますが、まだモデルがないので、画面には何も増えません。

**前提:**

- Visual Studio で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 先に [ゲームの土台の手順](../../土台/ゲームの土台/ゲームの土台の手順.md) を済ませておく（順番は [README の「ゲームを作る順番」](../../../README.md#ゲームを作る順番)）。

| 手順 | 足すもの | 確かめ方 |
|---|---|---|
| 1 | 位置だけを持つ基底クラス `Actor` | ビルドが通る |
| 2 | 変わる値 `Status` と、キャラクターの基底クラス `Character` | ビルドが通る |
| 3 | `Player`（と、調整値の `PlayerConfig`） | ビルドが通る |
| 4 | `Enemy` | ビルドが通る |
| 5 | `Game` から Player と Enemy を作る | 起動して落ちない |

**読み方:**

- 足す場所は「〇行目 `その行に書いてあること` の下」で示します。行番号は、それより前の小手順を済ませたときの番号です。
- 枠の左の数字は、足したあとの行番号です。右の枠のコードを、そのまま書きます。
- 書き換えるところは、「前」と「後」の枠を並べています。
- コードの下に、3つを置きます。
  - 「行・何をしているか」の表: 1行ずつの動き。
  - 「なぜ」「効果」: その小手順でそう書く理由と、書くと何ができるようになるか。
  - 「初めて出てくる名前」の表: このページで初めて出てくる変数・引数・関数・型・マクロ・C++ の書き方を、コードに出てくる順に並べます。2回目からは載せないので、わからない名前はページ内検索（`Ctrl+F`）で最初に出てきた所を探してください。「どこから来たもの」で、このゲームで作ったもの・エンジン（k2Engine）の機能・C++ の標準ライブラリ・C++ の書き方のどれかがわかります。
- [前提知識](../../../前提知識.md) で「よく知っている」にあるもの（クラス・継承・ポインター・テンプレート・`std::unique_ptr`・`K2_ASSERT`・`nullptr` など）は、表に載せません。「まあまあ」「怪しい」「微妙」にあるもの（`std::make_unique`・`std::move` など）は載せます。
- VSCode で `Ctrl+Shift+V` を押してプレビューで読みます。
