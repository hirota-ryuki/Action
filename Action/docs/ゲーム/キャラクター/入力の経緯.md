# 入力の経緯

設計: [入力の設計](入力の設計.md)、[NPCのAIの設計](NPCのAIの設計.md)

何をして、なぜ今の形になったかの記録です。日付ごとに書き足します。

---

## 2026-11-05 入力元を分けた

| 以前 | 今 |
|---|---|
| Player が `g_pad` や `GetAsyncKeyState` を、移動・アニメーション・魔法の中で直接読んでいた | 入力元が `CharacterInput` を作り、キャラクターは受け取るだけ |
| Enemy の中で、追うかの判断と移動処理が混ざっていた | 判断は `NpcInputSource`、移動は `CharacterMover` |

## 2026-11-06 ダッシュと走るを1つのボタンにした

左Shift の押した瞬間を `dash`、押している間を `isRun` に入れるようにした（[プレイヤーのステートの経緯](../プレイヤー/プレイヤーのステートの経緯.md)）。

## 2026-11-06 敵を止めた

ダッシュの見た目を確かめやすくするため、`searchRange = 0` にした。相手が見つからないので、動かず、向きも変えず、撃たない。動かすときは 900 に戻す。

## 2026-11-13 近接攻撃のボタン attack を足し、AI がボタン3つを使い分けるようにした

| 以前 | 今 |
|---|---|
| 黒騎士の剣も魔法も `fire` だった。AI が押せるのも `fire` だけ（`canFire`・`fireRange` など） | 剣は `attack`、魔法は `fire`・`subFire`。AI はボタンごとの `ActionSettings` を持ち、届く距離がいちばん短いものから押す |

敵に魔法を持たせると、剣と魔法が同じボタンで同時に出てしまうため分けた（[魔法と弾の経緯](../魔法/魔法と弾の経緯.md) の同じ日）。黒騎士の値（220・2.5秒・0.6秒）は `attack` に移しただけで変えていない。

**確かめたこと:** 作業用フォルダ（git worktree）で main から [NPCの攻撃と魔法の使い分けの手順](NPCの攻撃と魔法の使い分けの手順.md) を上から順に組み込み、手順1〜3のそれぞれでビルド（Debug / x64）が通ることと、出来上がったコードがブランチのものと同じになることを見た。黒騎士が前と同じく剣を振るかは、画面ではまだ確かめていない。
