キャラクターのモデルとアニメーションを受け持つ部品 `CharacterModel` を作り、キャラクターに持たせるまでの手順です。

**出来上がるもの:** Player（SK_Player）と Enemy（ユニティちゃん）のモデルが表示され、入力で動きます。アニメーションのクリップは、ステートの手順（[敵のステートの手順](../敵/敵のステートの手順.md)・[プレイヤーのステートの手順](../プレイヤー/プレイヤーのステートの手順.md)）で足します。

**前提:**

- Visual Studio 2022 で `Action/Game/Game.sln` を開き、構成は **Debug / x64** でビルドする。
- 先に [移動の手順](移動の手順.md) を済ませておく（順番は [README の「ゲームを作る順番」](../../README.md#ゲームを作る順番)）。
- モデル（`Assets/modelData/player/Model/SK_Player.FBX`・`Assets/modelData/unityChan.tkm`）は、リポジトリにもとからある（変えない）。FBX をそのまま読む仕組みは、エンジンにもとからある（[モデル読み込みの設計](../../エンジン/モデル読み込みの設計.md)）。
- この手順書では、パスを `const char*` で持つ形で書く。[プレイヤーの調整値の手順](../プレイヤー/プレイヤーの調整値の手順.md)（ゲームの手順書の最後）の手順1で `std::string` に変える。
- 作業を始める前に、main からブランチを切る。

```cpp
#pragma once

// アニメーションクリップ1つ分の指定。
struct AnimClipDesc
{
	// .tka か .fbx。.fbx ならモデルのスケルトンにボーン名でリターゲットして .tka に変換してから読む。
	const char* path = nullptr;
	bool isLoop = true;
};

// キャラクターの見た目の指定。キャラクターごとの違いはここに書くデータだけにする。
struct CharacterModelDesc
{
	const char* modelPath = nullptr;            // .tkm か .fbx。
	EnModelUpAxis upAxis = enModelUpAxisY;      // 3ds Max で作ったモデルは Z。
	float scale = 1.0f;
	bool isShadowCaster = true;
	// 添字がアニメーションクリップの番号になる（PlayAnimation に渡す番号）。
	std::vector<AnimClipDesc> clips;
};

// キャラクターのモデルとアニメーション。Player・Enemy で共通に使う。
// モデルやアニメーションの読み込みの決まり（FBX の変換・リターゲット・クリップを先に読むこと）はここに閉じ込める。
// 持ち主は Start() で Init() を呼び、毎フレーム SetTransform() → Update() を呼ぶ。
class CharacterModel
{
public:
	void Init(const CharacterModelDesc& desc);

	// 位置と回転を反映する。大きさは Init で指定したもの。
	void SetTransform(const Vector3& position, const Quaternion& rotation)
	{
		m_modelRender.SetTRS(position, rotation, m_scale);
	}
	void Update()
	{
		m_modelRender.Update();
	}
	void Draw(RenderContext& rc)
	{
		m_modelRender.Draw(rc);
	}
	void PlayAnimation(int animClip, float interpolateTime = 0.0f)
	{
		m_modelRender.PlayAnimation(animClip, interpolateTime);
	}

	// アニメーション速度・ボーン・状態異常の色など、ModelRender を直接触る部品向け。
	ModelRender& GetModelRender()
	{
		return m_modelRender;
	}

private:
	std::unique_ptr<AnimationClip[]> m_animClips;  // ModelRender が指し続けるので、Init 後は動かさない。
	ModelRender m_modelRender;
	Vector3 m_scale = Vector3::One;
};
```

```cpp
#include "stdafx.h"
#include "CharacterModel.h"
#include "tkFile/FbxRuntimeImporter.h"

namespace
{
	bool EndsWithFbx(const std::string& path)
	{
		if (path.size() < 4) {
			return false;
		}
		std::string ext = path.substr(path.size() - 4);
		for (char& c : ext) {
			c = static_cast<char>(tolower(static_cast<unsigned char>(c)));
		}
		return ext == ".fbx";
	}

	// tkm と同じフォルダ・同じ名前の .tks。FBX→tkm 変換で一緒に作られる（ModelRender も同じ規則で読む）。
	std::string ToTksPath(const std::string& tkmPath)
	{
		const size_t dot = tkmPath.find_last_of('.');
		return tkmPath.substr(0, dot) + ".tks";
	}
}

void CharacterModel::Init(const CharacterModelDesc& desc)
{
	m_scale = Vector3(desc.scale, desc.scale, desc.scale);

	const int numClips = static_cast<int>(desc.clips.size());
	m_animClips = std::make_unique<AnimationClip[]>(numClips);

	// FBX のアニメーションをリターゲットするにはモデルのスケルトン(.tks)が要る。
	// .tks は FBX→tkm 変換で作られるので、ModelRender::Init より前に変換だけ済ませておく。
	std::string tksPath;

	for (int i = 0; i < numClips; i++) {
		const AnimClipDesc& clip = desc.clips[i];
		std::string tkaPath = clip.path;
		if (EndsWithFbx(tkaPath)) {
			if (tksPath.empty()) {
				tksPath = ToTksPath(nsK2EngineLow::FbxRuntimeImporter::ResolveToTkmFilePath(desc.modelPath));
			}
			// 変換結果はファイルの更新日時でキャッシュされるので、同じ FBX を何度渡しても変換は1回。
			tkaPath = nsK2EngineLow::FbxRuntimeImporter::ResolveAnimationFbxToTka(clip.path, tksPath.c_str());
		}
		if (tkaPath.empty()) {
			continue;  // 変換に失敗した。エラーは変換側で表示される。
		}
		m_animClips[i].Load(tkaPath.c_str());
		m_animClips[i].SetLoopFlag(clip.isLoop);
	}

	// ModelRender::Init は中で 0 番のクリップを再生するので、クリップは必ずこれより前に読み込む。
	m_modelRender.Init(desc.modelPath, numClips > 0 ? m_animClips.get() : nullptr, numClips, desc.upAxis);
	m_modelRender.SetShadowCasterFlag(desc.isShadowCaster);
}
```

- **クリップは `ModelRender::Init()` より前に読む。** `Init()` は中で 0 番のクリップを再生するためです。
- **FBX のクリップは、モデルのスケルトン（.tks）にボーン名でリターゲットして .tka に変換してから読む。** .tks は FBX→tkm 変換で作られるので、先にモデルの変換だけを済ませます（`FbxRuntimeImporter`、エンジンにもとからある）。
- **クリップの配列は `Init()` のあと動かさない。** `ModelRender` が指し続けるためです。

**確かめ方:** ソリューションのビルドが通る。
