## 2026-11-07 ステートマシンをテンプレートにし、Enemy にも持たせた

前は `PlayerStateMachine` が Player 専用の型（`PlayerStateId`・`PlayerStateContext`・`PlayerState`）で書かれていた。Enemy は `UpdateAction` の中の if 文で動いていた（動いていれば Run、止まっていれば Idle、凍っていたら重力だけ）。攻撃やひるみを足すと if 文が増えるので、その前に Enemy にもステートマシンを持たせることにした。

切り替えの手順（遷移を決める → Exit → Enter → Update）と、凍ったら Frozen へ移す処理は Player と Enemy で同じなので、`StateMachine<Id, Context>` と `State<Id, Context>` のテンプレートにした。Enemy 用にコピーすると、直すときに2か所を直すことになるため。

| 変えたところ | 中身 |
|---|---|
| `Character/StateMachine/` | `State.h`・`StateMachine.h` を新しく作った（ヘッダーだけ） |
| `PlayerState` | `using PlayerState = State<PlayerStateId, PlayerStateContext>;` にした。各ステートのコードは変えていない |
| `PlayerStateMachine` | テンプレートを継承し、7つのステートの登録と、「ダッシュのあと走り続ける」を下ろす前処理（`OnBeforeUpdate`）だけにした |
| `Enemy` | Idle・Move・Frozen の3つのステートにした。アニメーションのクリップの enum は `EnemyState.h` へ移した |

Enemy の動きは前と同じにした。ただ、Idle と Move の切り替えは、前は動いた結果（`CharacterMover::IsMoving()`）で、今は移動の入力の大きさ（`moveThreshold` = 0.1）で決めている。ステートは動く前に行き先を決めるため。今は敵の索敵範囲が 0 で動かないので、見た目は変わらない。

決めるときに比べたこと:

- **Id を文字列のハッシュにするか。** エンジンに `Util::MakeHash` があり使える。ただ、書き間違いや登録し忘れに気づけなくなる。ステートをデータから決める予定もないので、enum のままにした。
- **テンプレートではない共通の基底（`IStateMachine`）を作るか。** 今のステート名を全キャラクター分表示するときなどに要る。使う場所がまだないので作らなかった。
- **登録をどこに書くか。** Player / Enemy の `OnStart` に書くと、継承したステートマシンが要らない。そのかわり Player.cpp が長くなるので、各ステートマシンのコンストラクタに書いた。

確かめたこと: ビルドが通り、ゲームを起動して落ちないこと、プレイヤーが Idle で立ち、敵が表示されることを画面で見た。敵が動く・凍るところは操作していないので見ていない。
