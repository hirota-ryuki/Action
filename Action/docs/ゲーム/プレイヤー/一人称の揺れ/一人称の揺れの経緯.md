## 2026-11-16 歩き・走りの揺れと着地の沈みを足した

### やりたかったこと

一人称のカメラで歩くと、視点が上下・左右に揺れ、一人称の腕（`FirstPersonArms`）も歩きに合わせて揺れるようにする。左Shift を押したまま走ると、揺れが大きく、振りが速くなるようにする。

### 調べたこと

1. 腕は `FirstPersonArms::UpdateTransform` で、毎フレームカメラにぴったり付けて置いている。カメラを揺らすだけでは、腕は画面の同じ所に貼り付いたままになるので、腕の振りはカメラの揺れとは別に足す必要がある。
2. 魔法を撃つ位置は、カメラの位置と向きからのずれ（`PlayerInputSource` の `FIRST_PERSON_HAND_OFFSET`・`FIRST_PERSON_CHARGE_OFFSET`）で決まる。カメラを揺らしても撃つ位置は一緒に動くが、腕だけを振ると手と撃つ位置がずれる。
3. 速さは `player.json` で歩き 170、走り **960**（設計案の相談のときに 480 と書いたのは、`PlayerConfig.cpp` の既定値を見たため。実際は `player.json` で2倍にしてある）。そのため、1歩の長さは、走りで 1秒に約3歩になるよう 320 にした。
4. `CharacterMover` は `Character` の中に隠してあり、地面に着いているかを外から見られなかったので、`Character::IsOnGround()` を足した。

### 決めたこと（ユーザーと相談して）

| 項目 | 決めたこと |
|---|---|
| 走りの首振り | 入れる（足が着いた瞬間に 0.6° 下を向く） |
| 傾き | 保留。定数で入れておき（歩き 0.4°・走り 1.0°）、ゲームで見て残すか 0 にするか決める |
| 炎を溜めている間の腕 | 振りを止める |
| 着地の沈み | 入れる |
| 調整値 | `.cpp` の定数 |
| 揺れを切る設定 | 付けない |

### 作り方

- 揺れは、時間ではなく進んだ距離で進める（歩き出し・止まるときの滑り・ダッシュでも足の運びとずれないように）。速さはキャラコンの速度ではなく、前のフレームの位置との差で測る。
- 上下の揺れは、歩きと走りでいちばん低くなる所を変えた。歩きは脚を棒にした振り子なので足が着いた瞬間がいちばん低く、走りはばねのように脚が縮むので踏ん張る真ん中（1歩の 0.2）がいちばん低い。
- 着地の沈みは、`UpdateOffsets` の最後に別の行で足す形にした。手順書で「着地の沈み」を最後の手順に分けて足せるようにするため（前の手順で書いた行を書き換えずに済む）。

### どう確かめたか

1. 実装の作業用フォルダ（`feature/view-bob`）で、`Game.sln` を Debug / x64 でビルドし、通ることを確かめた（足したファイルに警告なし）。
2. 手順書は、main（#163）から切った別の作業用フォルダで、手順1〜6を順に組み込み、手順ごとにビルドが通ることを確かめた。全部を組み込んだあとの7つのファイルが、実装と1行も違わないことも確かめた。
3. 画面での確認はしていない。歩く・走るにはゲームの窓を前に出してキーを押す必要があり、ユーザーの画面の邪魔になるため、ユーザーに確かめてもらう。

## 2026-11-16 腕を歩きのように交互に振り、視点の揺れを Apex Legends くらいに小さくした

### 1. 現状の問題

ゲームで見てもらったところ、次の2つを直すことになった。

1. 腕は8の字に揺れて前後に少し動くだけで、歩いているときのように左右交互に振っているようには見えなかった。ユーザーからは「歩くときのように腕を交互に軽く振ってほしい。ただし両手はずっと画面に映るように」と頼まれた。
2. 視点の揺れは、Apex Legends くらい（歩きではほとんど揺れず、走りでも小さく揺れる）がよい、と頼まれた。前の値（走りで上下 4cm・傾き 1°・首振り 0.6°）はそれより大きいと判断した（Apex の正確な数値はなく、記憶からの判断）。

画像は撮っていない。揺れは歩く・走るときにしか出ず、そのためにはゲームの窓を前に出してキーを押す必要があり、ユーザーの画面の邪魔になるため。

### 2. ソースコードの問題箇所

腕の前後は、`FirstPersonBob::UpdateOffsets` で腕全体のずれの z（前）に入れていただけだった。腕ごと前後へ平行に数cm動くだけで、肩から振る動きにならない。

```cpp
// FirstPersonBob::UpdateOffsets（直す前）
m_armsOffset[0] = Vector3(armsX, armsY, -swing);
m_armsOffset[1] = Vector3(armsX, armsY, swing);
```

### 3. 直し方

1. 腕の振りは、`FirstPersonBob` からは「前後に振る量」（`GetArmSwing`。+ で前）だけを渡し、腕の側（`FirstPersonArms::SpreadArms`）で、肩を中心に回す置き方（`ArmPose` の上げる角度と前へ押す量）に足す。
2. 前に振る形（`SWING_FORWARD_POSE`）と後ろに振る形（`SWING_BACK_POSE`）を分け、後ろを小さくする。構えの手は画面の下 1/3 にあるので、後ろへ大きく振ると画面の外へ出るため。
3. 視点の揺れを小さくする（上下 0.6・1.5cm、左右 0.4・0.8cm、傾きは歩きなし・走り 0.4°、首振り 0.3°）。

振りの大きさは、ゲームで3回見てもらって決めた。

| 回 | 前に振り切ったとき | 後ろに振り切ったとき | ユーザーの判断 |
|---|---|---|---|
| 1 | 上げる 10°・前へ 8 | 下げる 4°・手前へ 4 | 振りすぎ。半分くらいの距離に |
| 2 | 上げる 5°・前へ 4 | 下げる 2°・手前へ 2 | 今の3分の2くらいに |
| 3 | 上げる 3.3°・前へ 2.7 | 下げる 1.3°・手前へ 1.3 | OK |

視点の揺れは、1回目の値でそのまま OK になった。

### 4. ソースコードの直し

```diff
 // FirstPersonBob::UpdateOffsets
-m_armsOffset[0] = Vector3(armsX, armsY, -swing);
-m_armsOffset[1] = Vector3(armsX, armsY, swing);
+m_armsOffset[0] = Vector3(armsX, armsY, 0.0f);
+m_armsOffset[1] = Vector3(armsX, armsY, 0.0f);
+m_armSwing[0] = -swing;
+m_armSwing[1] = swing;
```

```diff
 // FirstPersonArms::SpreadArms
 pose = BlendPose(pose, RELEASE_POSE, m_releaseWeight[side]);
+const float swing = m_bobSwing[side];
+const ArmPose& swingPose = swing >= 0.0f ? SWING_FORWARD_POSE : SWING_BACK_POSE;
+pose.raiseDeg += swingPose.raiseDeg * fabsf(swing);
+pose.push += swingPose.push * fabsf(swing);
```

`WALK_ARMS_SWING`・`RUN_ARMS_SWING` は、cm（0.5・2.5）から「振り切った形の割合」（0.5・1.0）に意味を変えた。`FirstPersonArms::Update` で、`m_bobSwing` にも撃つ形の混ぜ具合で弱めた値を入れる。

### 5. どう確かめたか

1. ゲームでユーザーに見てもらい、両手がずっと画面に映り、振りの大きさと視点の揺れがよいことを確かめてもらった。
2. この日に、main（#168）を取り込んだ（ドキュメントが「1つの項目に1つのフォルダ」になったので、このページも `一人称の揺れ/` へ移した）。
3. 手順書は、新しい決まり（小手順ごとの「なぜ」「効果」「初めて出てくる名前」）に合わせて書き直した。main（#168）から切った別の作業用フォルダで手順1〜6を順に組み込み、手順ごとにビルドが通ること、全部を組み込んだあとの7つのファイルが実装と1行も違わないことを確かめた。
