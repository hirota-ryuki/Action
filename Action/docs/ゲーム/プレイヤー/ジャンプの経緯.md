## 2026-11-13 ジャンプのモーションを入れ、跳ぶ・空中・着地に分ける

### 何をしたか

- それまでの Jump の枠には Run が入っていて、空中でも走るモーションが流れていた。
- ユーザーがジャンプのモーション3本（`Jump - take-off`・`Jump - in the air`・`Jump - landing`、30fps の FBX）をダウンロードした。ボーンの名前は UE のマネキン式（`pelvis`・`thigh_l` など）で、中に `KinemIQ_UAL_Mannequin` というノードがあり、Universal Animation Library のマネキンのモーションと思われる。マネキンのメッシュとスキンも入っている。
- 3本を UE で SK_Player にリターゲットし（`tools/UnrealScripts/ual_jump.json`）、JumpStart・JumpLoop・JumpLand にした。
- Air を「跳んだら JumpStart → JumpLoop、落ちたら JumpLoop」にし、着地の Land ステートを足した。

### モーションを調べた結果

元の FBX のボーンの位置を、コマごとに計算して調べた（腰・足の高さ。元の単位はメートル）。

| クリップ | わかったこと |
|---|---|
| take-off | 0コマ目だけ腰が 0.72 と低く、1コマ目で 0.90 に戻る。足は 3〜4コマ目で地面から離れ、8コマ目で引きつけ終わる。最後の腰の高さ（0.91）とポーズは in the air の最初と同じ |
| in the air | 最初と最後のポーズの差は 0.1° ほどで、そのままループできる |
| landing | 0コマ目で足が着いている。6コマ目で腰が 0.43 までしゃがみ、25コマ目でほぼ立つ |
| 3本とも | 腰が横に動くのは 0.03 以下で、その場で動くもの（In Place） |

### 1. 現状の問題（リターゲットで膝が伸びた）

最初に、Mixamo と同じ設定でリターゲットした。書き出した JumpLand で足の高さを計算すると、しゃがむところで足が地面より下に入っていた。

| JumpLand のコマ | 腰の高さ | 左足首の高さ |
|---|---|---|
| 0コマ目（足が着く） | 93.1 | 15.2 |
| 6コマ目（いちばん深くしゃがむ） | 41.7 | **-21.5** |
| 39コマ目（立つ） | 88.2 | 9.1 |

ゲームを動かす前に数値で見つけたので、ゲームの画像はない。

### 2. どこでずれているか

膝の曲がり（太ももとすねの向きの差）を、段階ごとに比べた。

| 段階 | 6コマ目の膝の曲がり |
|---|---|
| 元の FBX | 119.3° |
| UE に読み込んだ元のアニメーション（リターゲット前） | 119.3° |
| リターゲット後 | **18.3°** |
| リターゲット後（`align_source_to_target` なし） | 18.3° |
| リターゲット後（IK の処理 `Run IK Rig` を止める） | 114.5° |

読み込みまでは正しく、リターゲットの中の IK の処理で膝が伸びていた。ポーズ合わせ（align）は関係なかった。チェーンの対応（`LeftLeg` は太もも〜足首）は Mixamo のときと同じだった。

### 3. 直し方

`retarget_to_player.py` に `use_ik` の設定を足し、false なら `Run IK Rig` を止めるようにした。ジャンプは足を地面に固定する場面がほとんどなく、腰の上下と関節の角度を写すだけで足りる。Mixamo（Idle・Walk）の設定は変えない（`use_ik` を書かなければ今までどおり IK を使う）。

### 4. 直した結果

| JumpLand のコマ | 腰の高さ | 左足首の高さ（直す前 → 後） | 膝の曲がり |
|---|---|---|---|
| 0コマ目 | 93.1 | 15.2 → 17.1 | 24.5° |
| 6コマ目 | 41.7 | -21.5 → 4.8 | 114.5° |
| 39コマ目 | 88.2 | 9.1 → 11.3 | 25.7° |

立ったときの足首の高さ（11.3）は Idle（10.7）とほぼ同じ。JumpStart の最後と JumpLoop の最初のポーズも一致した。

### 5. どう確かめたか

- 書き出した FBX のボーンの名前が Idle と同じ（247本、SK_Player の骨格）であることを見た。
- 作業用フォルダ（git worktree）で Debug / x64 をビルドし、通ることを確かめた。
- ゲームを最小化・非アクティブのまま起動し、`JumpStart.tka`・`JumpLoop.tka`・`JumpLand.tka` ができたところ（起動から約16秒）で終了させた。その間に落ちなかった。
- 跳んだときの見た目は、キー入力が要るので、まだ確かめていない。

### 値の決め方

どのコマから流すかなどは、見てから決めることにした。最初の値は上の調べた結果から次のようにした。

- JumpStart は 1コマ目から流す（0コマ目の低い腰を飛ばす）。跳ぶのはボタンを押したフレーム。
- JumpLoop へは JumpStart の 30コマ目で移る（そこからはほぼ同じポーズ）。
- JumpLand は 0〜18コマ目を流す（腰が 77 まで戻ったところ）。残りは Idle への 0.3秒の補間で立つ。
- 移動しながら着地したら、しゃがまずに歩き・走りへ移る。

## 2026-11-14 ジャンプ中に膝をそろえる

### 何をしたか

- 実機で見て、ジャンプ中の股の開き（膝が外へ開いている）を直したいとなった。
- はじめは、F1 の開発用の画面に「股を開く角度」「太ももを前後に回す」「太ももを上げる量」「膝を曲げる量」のスライダーと、膝の位置の数字を出して調整できるようにした。
- 試したあと、スライダーをやめて「膝をそろえるか（true / false）」だけにすることにした。あわせて、開発用の画面の「プレイヤーの体」の窓（走りの腕の調整）も消した。腕の値は player.json だけで変える。

### 試したことと、わかったこと

- 最初の「股を開く」は、キャラクターの前後の軸で太ももを回していた。跳んで太ももが前へ上がっていると、この軸は太ももとほぼ同じ向きになり、太ももがねじれるだけで膝は閉じなかった。
- 軸を「太ももの向き」と「体の横の向き」の両方に直角にすると、太ももの向きによらず、膝は横へだけ動く。
- 「膝を前に出す」（体の左右の軸で回す）は、太ももが前へ上がっているときは膝が上下に動いた。ほしかったのは左右の動きだった。

### 脚の位置を調べた結果

書き出した FBX で、腰の真ん中から股関節・膝までの横の距離を計算した。

| クリップ | 股関節 | 膝 | 足首 |
|---|---|---|---|
| Idle の 0コマ目 | 約 8 | 約 10〜11 | 約 11〜13 |
| JumpLoop の 0コマ目 | 約 8 | 左 約 31・右 約 20 | 左 約 15・右 約 7 |

ジャンプは膝だけが大きく開き、足首は膝より内にある。太ももごと内へ回すと、足首が真ん中を越えて交差する。そのため、膝から下は回し返して足首の横の位置を残すことにした。

### どう確かめたか

- 作業用フォルダで Debug / x64 をビルドし、通ることを確かめた。
- 見た目は、ユーザーに実機で見てもらう。

## 2026-11-14 腕・足首・スカートを直して、ジャンプを仕上げる

ユーザーが実機で見て、次の順に直した。最後に「ジャンプに関しては完成」となった。

### 腕

- 「跳んだときに片方の脇を締めすぎている」となった。クリップでは左右の腕の開きはほぼ同じ（腰の真ん中からひじまで 約 33 と 約 30）だったので、BodyLink の走り用の腕の調整が原因と考えた。振りを抑える処理（`LimitArmSwing`）は走っていなくてもいつも効き、腕を横へ上げたジャンプの姿勢を「後ろへ振りすぎ」とみなして真下へ引き寄せる。ジャンプ中は、走り用の腕の調整を全部外した。
- そのあと「跳んだときに上がる腕の、上がる上限を決めたい」となった。クリップでは骨が `J_Bip_R` の腕だけ真下から約 105° まで上がる（反対は約 77°）。上腕の上限を付け、F1 のスライダーで見て 68° に決めた。途中で「脇を締める角度」を作ったが、求めていたのは上限だったので置き換えた。

### 足首

- 「右足首をまっすぐ前に」となった。空中では骨が `J_Bip_R` の足のつま先が上から見て内へ約 24°、`J_Bip_L` は外へ約 10° 向いている。`J_Bip_R` をまっすぐ前へ向ける直しを入れたが、「一旦戻して」となって取り消した。
- 左右の足首の向きを F1 のスライダーにして、ユーザーが `J_Bip_L` を 24° に決めた。

### スカート

- 「跳んだときにスカートがめくれすぎて中が見える」となった。
- まず、落ちるときの揺れの遅れでめくれると考え、ジャンプ中は揺れでモーションの形より上へ上がらないようにした。まだ見えた。
- 推測で直すのをやめ、ジャンプ中のスカートの骨ごとに「真下からの角度」を、モーションの形・揺れのあと・脚に押したあとの3段階でファイルに書き出して調べた。

| 段階 | 上がった量（最大） |
|---|---|
| モーションの形 | 前のスカートの付け根が 真下から 110° |
| 揺れで足される分 | 数°〜30° 前後（上へ上がらない処理のあと） |
| 脚に押される分 | ほぼ 0° |

- 書き出した FBX で確かめると、スカートの骨はクリップの中で太もも＋約 13° の向きに動いていた（Idle は太もも 12°・スカート 25°、JumpLand の 6コマ目は太もも 97°・スカート 110°）。
- ジャンプ中は、スカート・コートのすそを真下から 50° より上へ上げないようにした（脚に押す処理のあと）。

### どう確かめたか

- 作業用フォルダで Debug / x64 をビルドし、通ることを確かめた。
- 見た目は、どれもユーザーが実機で見て決めた。調べる用の記録とスライダーは、スカートの上限のスライダーだけ残した。
