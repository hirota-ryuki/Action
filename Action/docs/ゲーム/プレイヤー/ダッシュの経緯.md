# ダッシュの経緯

設計: [ダッシュの設計](ダッシュの設計.md)

何をして、なぜ今の形になったかの記録です。日付ごとに書き足します。コマは 30fps で、クリップの先頭を 0コマ目と数えます。

---

## 2026-11-06 止めたポーズから、一蹴りのアニメーションに変えた

以前は Run の疾走ポーズ（0.23秒の位置）で止めたまま、一定の速さで滑っていた（仮の状態）。
Run の体全体を前へ倒し、1歩分（着地して蹴り、宙へ飛び出す）にした `DashL` / `DashR` を1回流し、飛び出したポーズで止めるようにした。移動も、蹴った瞬間に平均の2倍で飛び出してだんだん止まる（ease-out）ようにした。

| 候補 | 選ばなかった理由 |
|---|---|
| 前へ倒した走りをループで流す（いったんこうした） | ダッシュの 0.2秒の間に足が回るだけで、蹴って飛び出した感じが出ない |
| 一定の速さで進む | 滑っているように見え、蹴った勢いが伝わらない |

「バタバタして見える」「走りへ移るのが早い」とのことで、0.2秒・1.5倍から 0.3秒・等速に変え、出るときの補間（はじめ 0.4秒、のちに 0.5秒）を足した。

## 2026-11-06 ダッシュの長さを何度か調整した

1. 平均の速さ 1000（0.3秒）・着地 0.2秒。
2. 「ダッシュ時間を2分の1にして速く」→ 平均 2000（0.15秒）、アニメーション2倍、着地 0.1秒。
3. 「元の4分の3の時間でいい」→ 平均 約1333（0.225秒）、アニメーション約1.33倍、着地 0.15秒。
4. 録画を原神の動画と並べると、しゃがみが1コマで終わって見え、着地で一気に起き上がっていた → しゃがみ 約0.15秒、着地 0.25秒にのばした。

## 2026-11-06 原神の動画から作り直し、通しの1本にした

しゃがみ・一蹴り・着地の3本（`DashCrouchL/R`・`DashLandL/R`）をやめ、原神の動画（33.41〜33.94秒）から作った通しの1本にした。長さは動画と同じ（しゃがむ 0.13秒・飛ぶ 0.23秒・着地 0.17秒）。作り方は [動画からアニメーションを作る設計](../アニメーション制作/動画からアニメーションを作る設計.md)。

走り・歩きを始めるコマを、最後に蹴った足に合わせた。最初のコマから始めると前後の足が逆になり、補間の間に前の足だけ先に下りて、つまずいたように見えた。着地を足す前は、飛んだポーズに合わせて、走りは Run の 4コマ目 / 13コマ目、歩きは Walk の 22コマ目 / 4コマ目（左で蹴ったとき / 右で蹴ったとき）にしていた。

## 2026-11-07 着地の間に走りへ補間するようにした（`dashLandIntoRun`）

前は着地を流し切ってから補間していた。ダッシュのクリップは1回きりなので、終わると最後のポーズで止まり、止まったポーズから 0.15秒かけて走りへ補間していた。「ダッシュから走りに行こうとするときにピタッと止まる」とのことで変えた。

## 2026-11-07 ダッシュのあとは移動の入力を離すまで走るようにした（`dashKeepRun`）

前は、ボタンをちょんと押してダッシュすると、着地のあと歩き（170）に戻っていた。480 から急に遅くなり、歩きのアニメーションも約1.3倍で回るので、ちょこちょこ歩いて見えた。「ダッシュ後にちょこちょこ歩くのを消して」とのことで、原神に近い「離すまで走る」にした。Dash の間は `context.keepRunAfterDash` を立て、`SelectByInput()` は `isRun` と同じに扱う。移動の入力がないフレームで `PlayerStateMachine::Update` が下ろす。

あわせて、入力がなければ Idle ではなく Stop へ移るようにした（`dashEndWithStop`）。着地の終わりの速さ（480）は Stop の滑り始めの速さにそのままつながる。

## 2026-11-07 連打で続けて出すのをやめた（`dashCanChain = false`）

「完全にダッシュが終わるまで入力不可」とのことでやめた。コードは残してあり、`dashCanChain` を true にすると戻る。そのときの仕組み:

| 書き方 | 理由 |
|---|---|
| 次のダッシュはステートを出ずに、同じステートの中で始め直す（`Begin()`） | ステートマシンは同じステートへの遷移をしない（`Enter` が呼ばれない）ため |
| `CheckTransition` で `input.dash.isTrigger` も見る | 進み切ったちょうどのフレームに押されたとき、予約される前にステートを出ないように |
| 入ったフレームの押下を数えない（`m_isFirstFrame`） | `Enter` と同じフレームの `Update` にも同じ押下が来るので、数えると1回で2回出てしまう |

## 2026-11-07 空中ではダッシュできないようにした

前は Air から Dash へ移れた（空中ではしゃがみを飛ばして蹴るところから流していた）。回数の制限がなく、空中で Dash → 足場がないので Air → また Dash… と、着地しないまま飛び続けられた。原神に近づけるため、空中ではダッシュできないことにした。

| 変えたところ | 中身 |
|---|---|
| `PlayerAirState::CheckTransition` | Dash へ移る行を消した |
| 地面のステート・`PlayerStopState` | ダッシュボタンで Dash へ移るのは、足場があるときだけ（足場から歩いて出たフレームに押しても出ない） |
| `PlayerDashState`（連打） | 続けて出すのも足場があるときだけ（`dashCanChain` を true にしたとき） |

しゃがまずに入る補間（`dashAnimBlendSeconds`、0.05秒）は、連打で続けて出すときのために残した。

## 2026-11-07 蹴る足を左だけにした（DashL / DashR → Dash）

前は左足で蹴る `DashL` と右足で蹴る `DashR` を作り、ダッシュのたびに交互に流していた。交互にしたのは連打で続けて出すためで、別のクリップへの切り替えにすると、指定したところから流し直せた（同じクリップを流し直すと、エンジンが補間せずにそのポーズへ飛ぶ）。連打をやめた（`dashCanChain = false`）ので、交互にする理由がなくなっていた。

「原神では片方の足からしかできない」とのことで、原神と同じく左足で蹴る1本だけにし、名前を `Dash` にした。毎回同じ形で出るので「ダッシュした」とすぐわかり、走り・歩きへのつなぎ（始めるコマ）も1通りで済む。メモリ（`.tka` 1本 約230KB）や処理の重さ（流しているクリップの分しか計算しない）は、ほとんど変わらない。

| 変えたところ | 中身 |
|---|---|
| アニメーション | `DashL.fbx` / `.tka` を `Dash` に名前を変え、`DashR` を消した。`dash_roto.json` も `Dash.fbx` の1本だけ作る |
| `PlayerDashState` | `m_isLeftKick` を消した |
| 調整値 | `dashLToRunStartTime` などの左右の4つを、`dashToRunStartTime`（Run の 5コマ目）・`dashToWalkStartTime`（Walk の先頭）の2つにした |
