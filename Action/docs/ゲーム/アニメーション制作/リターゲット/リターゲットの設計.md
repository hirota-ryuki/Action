# リターゲットの設計

作成日: 2026-11-07（[プレイヤーのアニメーションの設計](../プレイヤーのアニメーション/プレイヤーのアニメーションの設計.md) から分けた）
対象: [retarget_to_player.py](../../../../tools/UnrealScripts/retarget_to_player.py)、[mixamo_idle_walk.json](../../../../tools/UnrealScripts/mixamo_idle_walk.json)、[ual_jump.json](../../../../tools/UnrealScripts/ual_jump.json)
経緯: リターゲット専用の項はない。[プレイヤーのアニメーションの経緯](../プレイヤーのアニメーション/プレイヤーのアニメーションの経緯.md)の「2026-11-06 Walk の上半身を前へ 20° 起こした」に、リターゲットで背骨の形が残る話がある。`use_ik` を足した理由は [ジャンプの経緯](../../プレイヤー/ジャンプ/ジャンプの経緯.md)の「2026-11-13 ジャンプのモーションを入れ、跳ぶ・空中・着地に分ける」

Mixamo などのモーションを、UE で SK_Player の骨格に移して FBX で書き出すスクリプトです。

- **エディターを開かず、[UE をコマンドラインで動かして](../../../用語集.md#アニメーション制作)流す。**
- **元の骨格（Mixamo の Y Bot、T ポーズ）の IK Rig を自動で作り、SK_Player（VRM、T ポーズ）の IK Rig と、腕・脚などのチェーンごとに対応づけて移す。** IK Rig とリターゲッターは2回目から使い回す。

| 用語 | 何のことか |
|---|---|
| `SK_Player` | UE の中にある、プレイヤーの骨格つきのモデル（スケルタルメッシュ）。リターゲット先 |
| Y Bot | Mixamo の標準のキャラクター。T ポーズで、Mixamo のモーションの元の骨格になっている |
| T ポーズ・A ポーズ | 腕を真横に伸ばして立つ姿勢が T ポーズ、腕を斜め下に下ろした姿勢が A ポーズ。リターゲットでは、元と先のポーズをそろえる必要がある |
| IK Rig | UE の資産の1つ。骨格の骨を、腕・脚・背骨などの「チェーン」にまとめ、IK の設定を持つ |
| チェーン | IK Rig の中で、つながった骨のまとまり（左腕・右脚など）。元と先で、同じ名前のチェーンどうしが対応する |
| リターゲッター | UE の資産の1つ。元の IK Rig と先の IK Rig のチェーンを対応づけて、モーションを移す設定を持つ |
| 資産 | UE の中で扱うデータの1つ1つ（モデル・アニメーション・IK Rig など）。`/Game/…` というパスで指す |
| VRM・VRM4U | VRM は、人型のキャラクターのモデルの規格。VRM4U は、VRM を UE に読み込むための外部のプラグイン |
| マネキン | UE が標準で付けている人型のキャラクター。骨の名前や並びが決まっている |
| Universal Animation Library | 配布されているモーション集。ここでは、マネキンの骨格のジャンプのモーションを使っている |
| 非推奨 | まだ動くが、将来なくなるので、使わない方がよいとされている関数 |
| Without Skin・Keyframe Reduction | Mixamo の書き出しの設定。Without Skin はメッシュを入れず骨とモーションだけにする。Keyframe Reduction はコマを間引く設定で、`none` なら間引かない |
| In Place | Mixamo の書き出しの設定。歩く・走るモーションで、その場で足踏みする形にする（体が前へ進まない） |

## 1. 流れ

```mermaid
flowchart LR
    A[FBX を読む] --> B[元の IK Rig を作る]
    B --> C[SK_Player へリターゲット]
    C --> D[FBX で書き出す]
```

| 手順 | 使う API | 理由 |
|---|---|---|
| 元のモデル（Y Bot）を読む | `AssetImportTask` + `FbxImportUI` | アニメーションだけの FBX は、骨の長さや基準のポーズを持たない |
| 元の IK Rig を作る | `apply_auto_generated_retarget_definition()`・`apply_auto_fbik()` | Mixamo やマネキンは UE が骨格を見分けてチェーンを作れる |
| リターゲッターを作る | `auto_map_chains(FUZZY)` | 元と先でチェーン名がほぼ同じ |
| ポーズを合わせる（A ポーズのときだけ。設定 `align_source_to_target` が true） | `auto_align_all_bones(SOURCE)` | Mixamo と VRM はどちらも T ポーズなので不要 |
| IK を止める（`use_ik` が false のとき） | `set_retarget_op_enabled()` で `Run IK Rig` を止める | 深くしゃがむモーションで、IK が膝を伸ばして足が地面に入るため（[ジャンプの経緯](../../プレイヤー/ジャンプ/ジャンプの経緯.md)） |
| リターゲットする | `IKRetargetBatchOperation.run_batch_retarget()` | 5.8 では `duplicate_and_retarget` が非推奨 |
| 書き出す | `AnimSequenceExporterFBX`（`export_preview_mesh = False`） | 骨格とアニメーションだけにする |

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 型 | `AssetImportTask` | ファイルを UE の資産として読み込む作業を、1つにまとめて渡すため | 読み込むファイル・置き場・設定を持つ | 外部ライブラリ（Unreal Engine の Python の `unreal`） |
| 型 | `FbxImportUI` | FBX の読み込みの設定を決めるため | メッシュを読むか、アニメーションだけ読むか、材質を読むかなどを持つ | 外部ライブラリ（Unreal Engine の Python の `unreal`） |
| 関数 | `apply_auto_generated_retarget_definition()` | 元の IK Rig のチェーンを、手で作らずに済ませるため | UE が骨格を見分けて、腕・脚などのチェーンを自動で作る | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`IKRigController`） |
| 関数 | `apply_auto_fbik()` | IK Rig に、全身の IK の設定を足すため | 全身の IK（FBIK）の設定を自動で足す | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`IKRigController`） |
| 関数 | `auto_map_chains()` | 元と先のチェーンを、手でつながずに済ませるため | 元と先のチェーンを自動で対応づける。`FUZZY` は、名前が近いもの同士をつなぐ | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`IKRetargeterController`） |
| 関数 | `auto_align_all_bones()` | 元の姿勢を、先の姿勢に合わせるため | `SOURCE`（元）の骨を、先の T ポーズに合わせて回す | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`IKRetargeterController`） |
| 関数 | `set_retarget_op_enabled()` | リターゲッターの中の処理を、入れたり切ったりするため | 番号で指した処理を、使う・使わないに切り替える | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`IKRetargeterController`） |
| 値 | `Run IK Rig` | リターゲッターの中の、IK で足の位置を直す処理を指すため | この処理の名前。`use_ik` が false のとき、`set_retarget_op_enabled()` で止める | UE のリターゲッターが最初から持つ処理の名前 |
| 値 | `use_ik` | IK を使うかどうかを、モーションごとに決めるため | false のとき、`Run IK Rig` を止める | [retarget_to_player.py](../../../../tools/UnrealScripts/retarget_to_player.py) の設定（JSON のキー） |
| 関数 | `IKRetargetBatchOperation.run_batch_retarget()` | いくつものモーションを、まとめてリターゲットするため | 元のモーションを、リターゲッターの設定で先の骨格に移した資産を作る | 外部ライブラリ（Unreal Engine の Python の `unreal`） |
| 関数 | `duplicate_and_retarget` | リターゲットを1つずつ行う、UE の古い関数 | UE 5.8 では非推奨なので、このスクリプトでは使っていない | 外部ライブラリ（Unreal Engine の Python の `unreal`）（非推奨） |
| 型 | `AnimSequenceExporterFBX` | アニメーションを FBX にして書き出すため | アニメーションの資産を FBX にするエクスポーター | 外部ライブラリ（Unreal Engine の Python の `unreal`） |
| メンバー変数 | `export_preview_mesh` | 書き出す FBX に、メッシュを入れるかを決めるため | false にすると、メッシュを入れず、骨格とアニメーションだけを書き出す | 外部ライブラリ（Unreal Engine の Python の `unreal`）（`FbxExportOption`） |


IK Rig とリターゲッターを使い回すのは、UE では読み込み済みの資産を消してから同じ名前で作ろうとすると失敗するため（あればそれを読み込む）。


| UE の資産 | 内容 |
|---|---|
| `/Game/01_PlayerVRM/SK_Player` | VRM4U で読み込んだモデル。ゲームの `SK_Player.FBX` はここから書き出した |
| `/Game/01_PlayerVRM/IK_Player_Mannequin` | リターゲット先の IK Rig（チェーン名は UE のマネキン式） |
| `/Game/04_Retarget/<作業名>/` | スクリプトが作る資産 |

## 2. 使い方（Mixamo のモーションを足す）

1. Mixamo からダウンロードし、`D:\04_dawnload\mixamo\` に置く。
   - キャラクター「Y Bot」: FBX Binary・T-pose
   - モーション: FBX Binary・Without Skin・30fps・Keyframe Reduction は none。移動するものは **In Place**


2. `mixamo_idle_walk.json` の `clips` に `{"name": "書き出す名前", "fbx": "元のFBX"}` を足す。
3. UE のエディターを閉じてから実行する（UE をコマンドラインで動かす書き方は、**このコマンドが全ページで唯一の置き場所**。[姿勢補正スクリプト](../姿勢補正スクリプト/姿勢補正スクリプトの設計.md)・[止まるモーション](../止まるモーション/止まるモーションの設計.md)はここを見る）（Git Bash では `MSYS_NO_PATHCONV=1` を付ける）。

   ```bash
   T=D:/02_git/01_my/01_Action/Action/tools/UnrealScripts
   MSYS_NO_PATHCONV=1 "D:/01_software/13_UnrealEngine/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" \
     "D:/03_data/AssetMigrate_Combat 5.8 - 2/AssetMigrate_Combat.uproject" -run=pythonscript \
     "-script=$T/retarget_to_player.py $T/mixamo_idle_walk.json" -unattended -nop4 -nosplash -NullRHI
   ```

   **名前:**

   | ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
   |---|---|---|---|---|
   | 変数 | `T` | スクリプトと設定の置き場を、何度も書かずに済ませるため | `retarget_to_player.py` と JSON が入っているフォルダのパス | シェルの変数（このコマンドの1行目で決める） |
   | 環境変数 | `MSYS_NO_PATHCONV` | Git Bash がコマンドの引数を Windows のパスに勝手に書き換えるのを止めるため | `1` にすると、`-script=...` などの引数がそのまま UE に渡る | 外部ライブラリ（Git Bash の MSYS2） |
   | コマンド | `UnrealEditor-Cmd.exe` | 画面を出さずに UE を動かすため | UE のコマンドライン版の実行ファイル | 外部ライブラリ（Unreal Engine） |
   | 引数 | `-run=pythonscript` | UE に Python のスクリプトを実行させるため | 続く `-script=` のスクリプトを Python として実行する | 外部ライブラリ（Unreal Engine のコマンドライン） |
   | 引数 | `-script=` | 実行するスクリプトと、その引数を渡すため | `retarget_to_player.py` のあとに、設定の JSON のパスを続ける | 外部ライブラリ（Unreal Engine のコマンドライン） |
   | 引数 | `-unattended` | 途中で確認の窓が出て止まらないようにするため | ダイアログを出さずに最後まで動かす | 外部ライブラリ（Unreal Engine のコマンドライン） |
   | 引数 | `-nop4` | ソース管理（Perforce）につなごうとして止まらないようにするため | Perforce を使わない | 外部ライブラリ（Unreal Engine のコマンドライン） |
   | 引数 | `-nosplash` | 起動の画面を出さないため | スプラッシュ画面を出さない | 外部ライブラリ（Unreal Engine のコマンドライン） |
   | 引数 | `-NullRHI` | 画面に描かずに動かすため | 描画をしない（GPU を使わない）モードで起動する | 外部ライブラリ（Unreal Engine のコマンドライン） |

4. `log` のファイルの最後が `DONE` か確かめる。
5. 新しいクリップなら `EnPlayerAnimClip` に値を足し、`PlayerConfig.cpp` の `CLIP_TABLE` に JSON でのクリップ名（例 `"Walk"`）と `EnPlayerAnimClip` の値を足して、`Assets/data/player.json` の `animation.clips` にパスを書く（[プレイヤーの調整値の設計](../../プレイヤー/プレイヤーの調整値/プレイヤーの調整値の設計.md)）。

   **名前:**

   | ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
   |---|---|---|---|---|
   | 型 | `EnPlayerAnimClip` | プレイヤーのアニメーションを、番号で区別するため | クリップごとの番号の列挙型（`enPlayerAnimClip_Idle` など） | ゲームの [PlayerAnimator.h](../../../../Game/Source/Player/PlayerAnimator.h) |
   | 変数 | `CLIP_TABLE` | JSON のクリップの名前と、クリップの番号を結びつけるため | 名前・番号・既定の FBX のパスの表。番号の順に並べる | ゲームの [PlayerConfig.cpp](../../../../Game/Source/Player/PlayerConfig.cpp) |
   | 値 | `animation.clips` | クリップごとの FBX のパスを、JSON で変えられるようにするため | `player.json` の `animation` の中にある、クリップの設定 | ゲームの [player.json](../../../../Game/Assets/data/player.json) |

6. ゲームを1回起動して `.tka` を作り、`.fbx` と `.tka` をコミットする。

Mixamo 以外（UE のマネキン式のボーン名のもの）も同じスクリプトで移せる。設定ファイルを別に作り、`source_mesh_fbx` にはメッシュ入りの FBX を指定する。

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `source_mesh_fbx` | 元の骨格を持つ、メッシュ入りの FBX を指すため | このパスの FBX を、元のスケルタルメッシュとして読み込む | スクリプトの設定の JSON のキー（[retarget_to_player.py](../../../../tools/UnrealScripts/retarget_to_player.py) の冒頭に一覧がある） |
| 値 | `align_source_to_target` | 元が A ポーズのとき、先の T ポーズに合わせるため | true なら、元のポーズを先に合わせる（`auto_align_all_bones()`）。省略すると false | スクリプトの設定の JSON のキー（[retarget_to_player.py](../../../../tools/UnrealScripts/retarget_to_player.py) の冒頭に一覧がある） |


| 設定ファイル | 元 | 設定の違い |
|---|---|---|
| `mixamo_idle_walk.json` | Mixamo の Y Bot（Idle・Walk） | 既定どおり |
| `ual_jump.json` | Universal Animation Library のマネキン（JumpStart・JumpLoop・JumpLand）。元のファイルは `D:\04_dawnload\ual_jump\` | `align_source_to_target: true`、`use_ik: false` |

## 3. 既知の課題

- **UE のプロジェクトと元のファイルはリポジトリにない。** `D:\03_data\AssetMigrate_Combat 5.8 - 2` と `D:\04_dawnload\mixamo\`・`D:\04_dawnload\ual_jump\` は、このPCにしかない。
- **Walk をリターゲットし直すと補正が消える。** そのあと [姿勢補正スクリプト](../姿勢補正スクリプト/姿勢補正スクリプトの設計.md) を1回流し直す。
