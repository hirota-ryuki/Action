# 止まるモーションの設計

作成日: 2026-11-07（[走りから止まる設計](../../プレイヤー/走りから止まる/走りから止まる設計.md) から分けた）
対象: `Game/Assets/modelData/player/Animation/StopL.fbx`・`StopR.fbx`
経緯: [走りから止まる経緯](../../プレイヤー/走りから止まる/走りから止まる経緯.md)

走りから止まるモーション StopL / StopR の作り方です。手順の全体は [動画からアニメーションを作る設計](../動画からアニメーションを作る/動画からアニメーションを作る設計.md) にあります。

コマは 30fps で、クリップの先頭を 0コマ目と数える。元の動画のコマは「動画の 6コマ目」、クリップのコマは「StopL の 3コマ目」と書き分ける（[用語集](../../../用語集.md#アニメーション制作)）。

- **原神の動画から作った通しの1本。** 前の足を突っ張って滑る → 起き上がって立つ。
- **StopL / StopR は脚・腕の左右を入れ替えただけ。**

| 用語 | 何のことか |
|---|---|
| 子 | 親のボーンが動くと、それにつられて動くボーン（太ももの子は、太ももについて動く） |
| ガウス | 前後のコマの値を、近いものほど重くして平均する方法（ガウス関数の形の重み）。急な跳ねがなだらかになる |

smoothstep・ロトスコープは[用語集](../../../用語集.md#動きを近づける)にある。

---

## 1. 元にしたもの

| 項目 | 内容 |
|---|---|
| 動画 | 個人用 OneDrive の `02_Action参考資料/原神/`、29.78〜30.89秒（34コマ） |
| 向き | キャラクターが画面の左へ走っているので、`pose_to_angles.py` に `flip` を付けて左右を反転して読む |
| 角度 | [genshin_stop_pose.json](../../../../tools/UnrealScripts/genshin_stop_pose.json)。[clean_angles.py](../../../../tools/Rotoscope/clean_angles.py) で、前・今・次の 3コマの中央値を取ってから 1:2:1 の平均でならし、乱れたコマを手で直したもの。使うのは動画の 6コマ目から 34コマ分 |
| 設定 | [stop_roto.json](../../../../tools/UnrealScripts/stop_roto.json)（`start: 6, count: 34`） |

角度は横から見た向きで、前 0°・真上 90°・真下 -90°（[動画からアニメーションを作る設計](../動画からアニメーションを作る/動画からアニメーションを作る設計.md)の「2. 角度の測り方」）。

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| コマンド | [pose_to_angles.py](../../../../tools/Rotoscope/pose_to_angles.py) | 動画から読み取った結果を、モーションに使える角度にするため | 横から見た角度（前 0°・真上 90°・真下 -90°）に直す | このゲームの `Action/tools/Rotoscope/` のスクリプト（Python） |
| 引数 | `flip` | キャラクターが画面の左へ走る動画を、右へ走る向きで読むため | 付けると、左右を反転して読む | `pose_to_angles.py` の3つ目の引数 |
| 値 | `start`・`count` | 動画から読み取った結果の、使う範囲を決めるため | `start` は動画の最初のコマ、`count` は使うコマの数 | `stop_roto.json` の `rotoscope` の設定（JSON のキー） |

UE での設定は、胴体と首をデータのまま前へ倒し足さない・顔を 30° 起こす・一番低いつま先を 0.5cm に合わせる、の3つで、[走りとダッシュのモーションの設計](../走りとダッシュのモーション/走りとダッシュのモーションの設計.md)の「2. 調整用の数値」と同じ。走りの最初のコマとつながるようにするため。

頭・首・スカート・腕・脚は、止まる専用に次のように決めている（数値は「3. 調整用の数値」）。

### 頭と首

Idle へなめらかにつながるように決める。

- **顔の向き**は、頭に角度を足すのでなく、顔の向きそのもの（水平から、+ が上）を決める。走りから入ったところの向きから Idle と同じ向きへ smoothstep で変え、そのあとは変えない。上へ戻る向きには動かない。
- **首**（首 → 頭の線）は、起き上がるところでデータより起こす。最後が約84°になり、Idle（約84°）とそろう。
- 顔の向きと首は、角度を計算して UE で測り直し、残りの差を足すのを4回くり返して合わせる（`rotoscope pass`。最後の差は 0.5° 以下）。

### スカート

SK_Player のスカートは、前と後ろのボーン（`J_Sec_L/R_SkirtFront0`・`SkirtBack0`）が太ももの子、横のボーン（`SkirtSide0`）が腰の子で、モーションでは動かない。踏ん張るところ（StopL の 3〜13コマ目）では原神のデータどおり両方の太ももがほぼ水平（-2〜-15°）まで上がるので、そのままだと前の布が水平に突き出て正面から中が見え、後ろの布も前へ持ち上がってめくれる。そこで `skirt_follow` で、太ももや腰の回りに一部だけついていくようにする。

式: 親（太もも・腰）が基準のポーズから左右の軸まわりに回った角度を d とすると、スカートの根元を **(1 − k) × d だけ戻す**（k がついていく割合）。布は3枚（`_01`〜`_03`）とも同じにする。

| 布の種類 | 親 | ついていく割合 k | 踏ん張るところの向き（前 0°・真下 -90°）。直す前 → 直したあと |
|---|---|---|---|
| 前（`Front`） | 太もも | 0.5 | -4〜+5° → -39〜-41°。太ももが布を少し突き抜けるが、布が下に垂れて正面からの視線をさえぎる |
| 後ろ（`Back`） | 太もも | 0.25 | -28〜-32° → -93〜-94°（ほぼ真下） |
| 横（`Side`） | 腰 | 0.5 | -102〜-108° → -101〜-104° |

脚は原神のデータの角度のまま（太ももの上限 `thigh_max_deg` は使っていない）。走り（Run）から入るところで前の布が約 20° 下がるが、0.2秒の補間でつながる。

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `skirt_follow` | スカートを、太ももや腰の動きに一部だけついていかせるため | 布の種類ごとの、ついていく割合 k を `follow` に書く（`Front`・`Back`・`Side`） | `adjust_bone_rotation.py` の設定（JSON のキー） |
| 値 | `J_Sec_L/R_SkirtFront0`・`SkirtBack0`・`SkirtSide0` | スカートの前・後ろ・横の布の根元を指すため | `SK_Player` のスカートのボーンの名前。左右（L・R）がある | ゲームの `SK_Player`（[`J_Sec_*`](../../../用語集.md#左右と向き)） |
| 値 | `thigh_max_deg` | 太ももが上がりすぎないようにするため | 太ももを、この角度より上へ上げない（前 0°・真下 -90°）。ここでは設定していない | `adjust_bone_rotation.py` の `rotoscope` の設定（JSON のキー） |

### 後ろへ来る腕の肘

読み取りでは、肘が動画の 8コマ目で 109° 曲がってから 11コマ目で 10° まで伸び、前腕が3コマで約100°後ろへ振られていた。そのあと 16〜18コマ目は肘が逆へ反っていた。そこで肘の曲がりだけを前後のコマとガウスでならす（`arm_smooth`）。前腕は 5〜15コマ目（約0.33秒）かけて、1コマ最大約9°で後ろへ振るようになった。上腕はならさない（始めと終わりの角度を変えず、走り・Idle とのつながりを保つ）。

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 値 | `arm_smooth` | 読み取りで肘が急に曲げ伸ばしされるのを抑えるため | 腕ごとに、肘の曲がりをならす幅（コマ数）を書く。`"a"` は腕（読み取りの結果の `a`・`b` が腕） | `adjust_bone_rotation.py` の `rotoscope` の設定（JSON のキー） |

### 起き上がるところの脚

StopL / StopR の 14〜30コマ目の脚は、読み取りの揺れを消すため、14コマ目の角度から 30コマ目の角度へ smoothstep でまっすぐ移している。

## 2. 作り直す

作る前に、角度の JSON と設定（上の「元にしたもの」）がそろっていること。実行は次のとおり。UE をコマンドラインで動かす書き方（`MSYS_NO_PATHCONV`・`UnrealEditor-Cmd.exe`・`-run=pythonscript`・`-script=`・`-unattended`・`-nop4`・`-nosplash`・`-NullRHI`）の名前の表は、[リターゲットの設計](../リターゲット/リターゲットの設計.md)の「2. 使い方」3 にある。

```bash
T=$(cd Action/tools/UnrealScripts && pwd -W)
MSYS_NO_PATHCONV=1 "<UE_5.8>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "<空の>.uproject" -run=pythonscript \
  "-script=$T/adjust_bone_rotation.py $T/stop_roto.json" -unattended -nop4 -nosplash -NullRHI
```

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 変数 | `T` | スクリプトと設定の置き場を、何度も書かずに済ませるため | `adjust_bone_rotation.py` と JSON が入っているフォルダ（`Action/tools/UnrealScripts`）の、Windows 形式のパス | シェルの変数（このコマンドの1行目で決める） |
| シェルの書き方 | `$(cd ... && pwd -W)` | フォルダへ移ったうえで、その場所のパスを `T` に入れるため | `pwd -W` は、現在のフォルダを `C:/...` の形（Windows のパス）で出す。`$(...)` は、中のコマンドの出力をその場に入れる | 外部ライブラリ（Git Bash のシェルの書き方） |

そのあとゲームを1回起動して `.tka` を作り直し、`.fbx` と `.tka` をコミットする。

## 3. 調整用の数値（`stop_roto.json`）

| 内容 | 値 |
|---|---|
| 顔の向き（水平から、+ が上） | StopL の 3コマ目まで -16°（走りから入ったところと同じ）、4〜26コマ目で Idle と同じ -4° へ smoothstep、そのあとは -4°（`face_deg: [-16, -4]`、`face_frames: [4, 26]`） |
| 首をデータより起こす角度 | 14〜30コマ目で最大 25°。最後が約84°（`neck_add_deg: 25`、`neck_add_frames: [14, 30]`） |
| 動画から使う範囲 | 動画の 6コマ目から 34コマ分（`start: 6`・`count: 34`） |
| スカートがついていく割合 k | 前 0.5・後ろ 0.25・横 0.5（`skirt_follow.follow`） |
| 後ろへ来る腕の肘をならす幅 | 4コマのガウス、肘は 5° より伸ばさない（`arm_smooth: {"a": 4}`、`elbow_min_deg` の省略時の値） |
| 起き上がる脚を直線で移す区間 | StopL の 14コマ目 → 30コマ目 |

## 4. 決めたこと

| 決めたこと | 理由 |
|---|---|
| 頭に角度を足さず、顔の向きそのものを決める | 首の角度が大きく変わっても、顔は一方向へだけ動き、起き上がるとき首が起きて上を向かない |
| 首を最後に Idle と同じ角度にそろえる | Idle へ移るとき、頭が後ろへ引かれないようにする |
| スカートの根元を (1 − k) × d だけ戻す | 太ももがほぼ水平に上がる間、前の布が突き出て中が見える、後ろの布がめくれるのを防ぐ |
| 脚は原神のデータの角度のまま、上限を付けない | 踏ん張る形を原神に合わせる。スカートの方を直して見え方を抑える |
| 腕の肘だけをならし、上腕はならさない | 肘の急な曲げ伸ばしを抑えながら、始めと終わりの角度を走り・Idle に合わせたままにする |
| 起き上がる脚は 14コマ目から 30コマ目へ直線で移す | 読み取りの揺れを消す |
