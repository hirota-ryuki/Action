## 2026-11-14 スキルの基底クラスを置くことにした（設計）

[魔法の作り直し](../魔法/魔法の経緯.md)のあと、魔法を撃つ入力について次の3つが残っていた。

| # | 残っていたこと | どうするか |
|---|---|---|
| 1 | キャラクターが「`fire` は枠0、`subFire` は枠1」と、どのボタンで撃つかを知っていた | 入力元が `SkillCommand`（どのスキルを・押した／押している／離した）を作り、キャラクターはそれを渡すだけにする |
| 2 | 魔法を番号（枠）で登録していて、何を撃つのか読み取れなかった | `SkillId` で登録し、指示も ID で出す |
| 3 | 黒騎士の剣の攻撃も `fire` を使っていて、魔法の指示と混ざっていた | 剣の入力は `attack` に分ける |

あわせて、魔法と剣の攻撃の上に基底クラス `SkillBase` を置き、派生を `MagicBase`・`AttackBase` にすることにした。指示の受け取り・溜め・クールダウン・同時に使えるのは1つ、を1か所にまとめるため。

決めたこと:

- 溜めている間（剣なら振っている間）は、ほかのスキルの指示を受け付けない。
- 入力を受け取ったあとの判断（押している間・離した・中断）は `SkillBase` に書く。
- クールダウンはスキルごとに持ち、既定は 0。剣の攻撃は振っている間ほかを受け付けないので、0 のままでよい。
- 黒騎士の剣を `AttackBase` にするのは、あとの作業にする。

この日は設計書を書いたところまで。

## 2026-11-14 実装した（入力をボタンにまとめ、SkillController にした）

設計を書いたあと、入力の扱いを次のように決め直してから実装した。

| 設計を書いたとき | 実装した形 | 理由 |
|---|---|---|
| 入力元が「どのスキルを」使うかの指示（`SkillCommand`・`SkillId`）を作る | 入力元は「どのボタンが押されたか」（`ActionButton::Action1`・`Action2`）だけを入れる | 入力元にスキル（魔法）のことを書かないため。どのボタンで何を使うかは `SkillController` の登録で決める |
| 登録して使う部品は `SkillSet` | `SkillController` | 入力を見てスキルを使わせる係なので、データの集まりに見える名前を避けた |
| 黒騎士の剣の入力は `attack` に分ける | 黒騎士も `Action1` を押し、`attackIndex` で種類を伝える | あとで剣の攻撃も `AttackBase`（スキル）にして、同じボタンで使うため |

`SkillController` が `PlayerInputSource` を直接読む形も比べた。直接読むと、AI がスキルを使う道がなくなり、キーの割り当て・押した瞬間の判定・窓や ImGui の判断が入力元と2か所になるので、`CharacterInput` を間に置く形にした。

3段攻撃（#133）で足された「攻撃のコマに合わせて撃つ入力の書き換え」（`FilterCastInput`）は、`FilterSkillInput` に名前を変え、`Action1` を書き換える形にした。

どう確かめたか:

- `Game.sln`（Debug / x64）をビルドし、ゲームのソースから警告・エラーが出ないことを確かめた。
- 画面での確かめ（左クリックで氷、右クリックで溜め撃ち、溜めている間は左クリックが効かない、凍ったら溜めが消える、3段攻撃で撃つ、黒騎士が剣で攻撃する）は、ゲームの窓を前に出してクリックする必要があるため、ユーザーに頼んだ。
- 手順書（[魔法の手順](../魔法/魔法の手順.md) など）は、まだこの形に直していない（[README の注意事項](../../README.md#注意事項)）。
