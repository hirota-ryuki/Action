## 2026-11-08: 素材と作り方を決めた

### 何をしたか

「ポリゴン数少なめで、原神のような岩と草原のステージを作りたい。アニメ調がよいがシェーダーでなんとかなるならよい。重くならないことだけ気にする」という要望から始めた。

素材は次の候補を比べた。

| 候補 | 結果 |
|---|---|
| Quaternius「Stylized Nature MegaKit」（無料・CC0） | **これにした**。手描き風のテクスチャで、候補の中でいちばん原神に近い |
| Quaternius「Ultimate Nature Pack」（無料・CC0） | 単色でのっぺりしている。数を足したいときの予備 |
| Kenney「Nature Kit」（無料・CC0） | 積み木のような形で、原神から遠い |
| Synty「POLYGON」シリーズ | 有料なので使わない |
| Fab（Epic）の Stylized 系 | 重いものが多く、UE のマテリアルに頼っていて持ち込みにくい |

Sketchfab などにある「原神の〇〇」はゲームから抜き出したモデルなので、使わないことにした。

そのほかに決めたこと。

- 光の当て方（アニメ調の影など）は別の作業でやる。このページの範囲はステージだけ。
- 広さは原神に合わせ、見渡せる草原にする。
- 地形と配置は Blender で作る。Blender は手で操作せず、スクリプトでウィンドウなしに動かして作る。

### 入れたもの

| もの | 場所 | 確かめたこと |
|---|---|---|
| Blender 5.2.3 LTS（ポータブル版の zip） | `D:\01_software\17_Blender\blender-5.2.3-windows-x64\` | 公式のチェックサムが一致した。`--background --version` で起動した |
| Stylized Nature MegaKit 無料版（itch.io） | `D:\03_data\StylizedNatureMegaKit\` | 中に実行ファイルがないこと。ライセンス（`License_Standard.txt`）が CC0 であること |

- 無料版は全 116 個のうち 68 個。岩は `Rock_Medium` 3種と小石・石畳だけで、崖ほど大きな岩はない。そのため、崖は地形の岩肌と岩を組み合わせて作ることにした。
- プレビュー画像の、風に揺れる草や葉の見た目は、有料版に付くシェーダーによるもの。モデルとテクスチャは同じ。

### エンジンについて調べたこと

- ゲームの1単位は 1cm（プレイヤーの走る速さが 480/秒）。カメラの見える距離は 40000（400m）。
- 普通の `ModelRender` は、画面の外にあると描かない。インスタンス描画のときはこれをしない（`ModelRender::Draw` のコメント）。
- G バッファに書くシェーダーは、アルファ 0.2 未満のピクセルを捨てる。草や葉の切り抜きに使える。
- G バッファの材質の絵（`metaricShadowSmooth`）は b を使っていない。ライティングの作業で使えるかもしれない。

## 2026-11-08: 2×2 区画の草原を作った

### 何をしたか

- Blender のスクリプト `generate_stage.py` と設定 `field_settings.json` を作り、2×2 区画（128m 四方）の地形・地面の色・部品の配置を書き出した。
- ゲーム側は `Stage` を書き直し、`StageChunk`（1区画の地形）と `StageProps`（部品のインスタンス描画）を足した。今までの仮の足場（`kariAsiba.tkm`）は使わなくなった。
- エンジンのインスタンス描画を直した（下の「つまずいたこと」の 3）。別のブランチ（`Instancing`）で直し、ステージのブランチに取り込んだ。

### つまずいたこと

1. **茂みが赤かった。** 茂みの葉は、ねじれた木の紅葉の画像（`Leaves_TwistedTree_C.png`）を使っていた。隣の白い画像（`Leaves_TwistedTree.png`）は有料版のシェーダーで色を付ける前提のものなので、スクリプトで緑を掛けた画像を作って貼った。
2. **崖の前の大きな岩が浮いていた。** 岩の真ん中の地面の高さに置いていたので、崖の斜面では手前が浮いた。足もとの範囲（9か所）でいちばん低い地面に置くようにした。
3. **エンジンのインスタンス描画は、数が多いと使えない作りだった。** 全インスタンス分の頂点を事前計算して大きな頂点バッファを作り、毎フレーム全部計算し直していた（描く数はいつも 1）。草 6,000 本だと数百 MB になる。アニメーションのないモデルは、シェーダーにもとからあった `VSMainInstancing` で描き、渡した数だけ `DrawIndexedInstance` するようにした。
4. **ゲームの中で地形が 1/100 の大きさだった。** エンジンの FBX インポーターは単位の設定を見ない。書き出しの設定を `apply_unit_scale=False`・`FBX_SCALE_NONE` に変え、tkm の頂点の範囲が 1区画 6400（64m）になったことを確かめた。途中、メッシュを自分で 100 倍したら 100 倍大きくなったので、それはやめた。

### どう確かめたか

- Blender の描き出し画像（地面から・斜め上から・真上から）で、崖・岩・木・道・草の並び方を見た。
- Debug・Release の x64 でビルドが通った。
- ゲームを、前に出さず・フォーカスを奪わず・画面の外に置いて起動し、そのウィンドウだけを撮って、すぐ終了した。
  - 地形・草・岩・木・石畳が出て、プレイヤーが地面に立っている（当たり判定が効いている）。
  - Release で、ステージありが 351fps、配置 JSON を外してステージなしにしたときが 366fps（GPU は専用のもの、1920×1080）。
- 草が暗く、岩が白く光って見えるのは光の当て方の問題なので、この作業では直していない。
