## 2026-11-14 魔法と弾を1つにまとめ、魔法を撃つたびに1つ作る形にした

### 何が分かりにくかったか

| # | 以前の形 | 分かりにくかったところ |
|---|---|---|
| 1 | `MagicCaster` が魔法の一覧・切り替え（Q・E）・サブの魔法を持っていた | 一覧に入っているのは氷魔法だけで、切り替えが空回りしていた |
| 2 | `IceMagic` はクールダウンを見て `IceBullet` を出すだけ（18行） | 1つの魔法に、クラスが2つ要った |
| 3 | `FireMagic`（溜め）と `FireBullet`（飛ぶ）に分かれていた | 溜め中の見た目を `FireBullet` の関数で決めていて、分けた意味が薄かった |
| 4 | `BulletBase` が `Magic/` にあるのに、黒騎士の斬撃（`SlashBullet`）は魔法を通らずに使っていた | 「魔法」と「弾」の関係が読み取れなかった |
| 5 | `MagicCaster` が入力（`CharacterInput`）を丸ごと受け取り、撃つ位置も作っていた | 入力・キャラクター・魔法の受け持ちが混ざっていた |

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 型 | `MagicCaster` | 魔法の一覧・切り替え・撃つ位置・クールダウンを持つため | 魔法を撃つ部品だった | ゲームの `Magic/MagicCaster.h`（今はない。[スキルの経緯](../スキル/スキルの経緯.md) の 2026-11-14「実装した」で `SkillController` にして消した） |
| 型 | `IceBullet` | 氷の弾（飛ぶ物）を表すため | 氷魔法が出す、飛んでいく氷 | ゲームの `Magic/IceBullet.h`（今はない。下の 2026-11-14「魔法と弾を1つにまとめ」で `IceMagic` に入れて消した） |

| 型 | `BulletBase` | 弾の共通処理（飛ぶ・当たる・消える）を持つため | 弾の基底クラス | ゲームの `Magic/BulletBase.h`（今はない。同じ日に `MagicBase` に中身を移して消した） |
| 型 | `SlashBullet` | 黒騎士の斬撃を表すため | 黒騎士が剣を振って飛ばす弾 | ゲームの `Enemy/SlashBullet.h`（今はない。同じ日に `SlashMagic` にして消した） |
| 型 | `CharacterInput` | キャラクターが1フレームに受け取る入力をまとめるため | ボタンの状態や移動の向きなどを持つ、値だけの構造体 | ゲームの [CharacterInput.h](../../../Game/Source/Character/Input/CharacterInput.h) |

### どう変えたか

| 以前 | 今 |
|---|---|
| 魔法（撃ち方）と弾（飛ぶ物）を別のクラスにした | 魔法 = 飛んでいく1発。`MagicBase` に「待つ → 飛ぶ → 当たる → 消える」の流れを持たせ、`BulletBase` の中身を移した |
| 溜めは `FireMagic` が持ち、離したら `FireBullet` を作った | 押した瞬間に `FireMagic` を作り、離すまで撃つ位置で待たせる（`IsChargeType()`）。溜めた火の玉がそのまま飛ぶ |
| `MagicCaster` は一覧・切り替え・サブ・撃つ位置・クールダウンの減算を持っていた | `Register<T>(枠)`・`Fire(枠, ボタン, 位置, 向き)`・`CancelAll()` だけにした |
| クールダウンは毎フレーム残り秒数を減らした | 「撃った時刻」と `GameClock::Now()` の差で測る。溜めの長さも同じ |
| 撃つ位置と向きは `MagicCaster` が作った | `Character::MakeCastPose()` が作る。設定は `CharacterCastSettings` |
| 黒騎士の斬撃は `Enemy/SlashBullet` | `Magic/SlashMagic`（`MagicBase` を継承）。攻撃のステートが直接作る |
| エフェクトの名前は `ice_bullet`・`fire_bullet`（`EffectId::IceBullet`・`FireBullet`） | `ice_fly`・`fire_fly`（`EffectId::IceFly`・`FireFly`） |

**名前:**

| ジャンル | 名前 | 何のためのもの | 何をするためのもの | どこから来たもの |
|---|---|---|---|---|
| 型 | `MagicBase` | 飛んでいく魔法の共通の仕組み（飛ぶ・当たる・消える）を持つため | 魔法の基底クラス。同じ日の遅くに、スキルの基底クラス `SkillBase` の派生にした | ゲームの [MagicBase.h](../../../Game/Source/Magic/MagicBase.h) |

| 関数 | `GameClock::Now()` | 「撃った時刻」との差で、クールダウンと溜めの長さを測るため | ゲームが始まってからの秒数を返す | ゲームの [GameClock.h](../../../Game/Source/Core/GameClock.h) |
| 関数 | `Character::MakeCastPose()` | 撃つ位置と向きを作るため | 照準があればそちらへ、なければ足元から `castHeight` の高さで正面へ撃つ位置と向きを作る | ゲームの [Character.h](../../../Game/Source/Character/Character.h) |

| 型 | `SlashMagic` | 黒騎士の斬撃を、魔法として扱うため | `MagicBase` を継承した、まっすぐ飛ぶ斬撃 | ゲームの [SlashMagic.h](../../../Game/Source/Magic/SlashMagic.h) |

`GameClock` は、エンジンの `GameTime` に足す案もあったが、エンジンに手を入れずに済むよう Game の側（`Source/Core`）に置いた。
コードのコメントや設計書の「弾」も、飛んでいく魔法を指すところは「魔法」に直した。

### 動きを変えないように合わせたところ

- 炎魔法のクールダウンは、以前と同じく「離して飛ばしたとき」から数える（押した瞬間から数えると、長く溜めたあとすぐに次を溜められてしまう）。
- 凍って溜めを捨てたときは、以前と同じくクールダウンを始めない。
- クールダウン中に押した分は、以前と同じく溜めない（火の玉を作らない）。
- 読み込みに失敗した溜め撃ちの魔法は、`MagicCaster` が指している間は消さず、離されるか中断されてから消す（消えた魔法に `Hold()` を呼ばないため）。

### どう確かめたか

1. 作り直したコードを `Game.sln`（Debug / x64）でビルドし、ゲームのソースから警告・エラーが出ないことを確かめた。
2. 手順書は、行番号を数えて表を作る作業用のツールで書いた。手順書の印（`<!-- add: … -->` など）を読み直して当てた結果が、ツールで作った形と同じことを確かめた。
3. #84 のコードから、作り直す前の手順書 22 → 14（番号は作り直す前のもの）を逆に当てて「走りから止まる手順まで済ませた形」を作り、そこから新しい [魔法の手順](魔法の手順.md)・[氷魔法の手順](氷魔法/氷魔法の手順.md)・[炎魔法の手順](炎魔法/炎魔法の手順.md)・[炎魔法発射後の燃える床の手順](炎魔法発射後の燃える床/炎魔法発射後の燃える床の手順.md) を当てた。`GameClock`・`MagicBase`・`MagicCaster`・`IceMagic`・`FireMagic`・`BurningGround`・`FireEffect` は、今のコードと一字一句同じになった。
4. 4本の手順書のそれぞれが済んだところで、#84 の作業用フォルダに置いてビルドした。4回ともエラーなく通った。
5. 魔法の手順で `Game.cpp`・`PlayerInputSource` の行が増減したので、後ろの [UIの構成の手順](../UI/UIの構成/UIの構成の手順.md)・[HUDの手順](../UI/HUD/HUDの手順.md)・[プレイヤーの調整値の手順](../プレイヤー/プレイヤーの調整値/プレイヤーの調整値の手順.md)・[デバッグUIの手順](../../エンジン/デバッグUI/デバッグUIの手順.md) の行番号を、ツールで新しい形に合わせて直した（調整値の手順は `MagicCaster::Settings` を `CharacterCastSettings` に読み替えた）。0〜21 を当てた結果を #84 で、デバッグUIまで当てた結果を #85 でビルドし、どちらも通った。
6. 画面での確かめ（左クリックで氷、右クリックで溜め撃ち、凍ったら溜めが消える）は、ゲームの窓を前に出してクリックする必要があるため、ユーザーに頼んだ。

`Character`・`Enemy`・`Player`・`PlayerConfig`・`Game` は、手順書の流れの敵がまだユニティちゃんで剣も持っている形（[README の注意事項](../../README.md#注意事項)）なので、今のコードとは魔法と関係のないところが違う。黒騎士の斬撃（`SlashMagic`）は、黒騎士の手順書がないので、手順書には入っていない。
