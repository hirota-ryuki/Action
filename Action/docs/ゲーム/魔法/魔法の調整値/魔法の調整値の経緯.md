## 2026-11-17 魔法の強さを magic.json に出した

### きっかけ

魔法を撃つ敵（`NpcInputSource` を使うキャラクター。[NPCのAIの経緯](../../キャラクター/NPCのAI/NPCのAIの経緯.md)）を作るとき、氷魔法・炎魔法の強さをキャラクターごとに調整できるようにしたかった。強さは `IceMagic.h` の `COOLDOWN`、`IceMagic.cpp`・`FireMagic.cpp`・`SlashMagic.cpp` の定数と `MakeSettings` に散らばっていて、値を変えるたびにビルドが要った。

### 以前の試み（`magic-shared` ブランチ）

2026-11-13 に、ブランチ `magic-shared` で同じことを作っていた。このときの設計は次のとおり。

| `magic-shared` の設計 | 今 |
|---|---|
| 値を持つのは `MagicSettings.h/.cpp`（`GetIce()`・`GetFire()`） | `MagicConfig.h/.cpp`。名前を `MagicSettings`（`MagicBase` が受け取る速さ・射程・半径の型）と取り違えないように変えた |
| 氷・炎の弾（`IceBullet`・`FireBullet`）に `Setup` で値を渡す | 弾のクラスは 2026-11-14 になくなったので、魔法（`IceMagic`・`FireMagic`）が `MagicConfig` から直接取り出す |
| 魔法の作り手（`MagicCaster`）が、`std::make_unique<IceMagic>(MagicSettings::GetIce())` のように、値を渡して魔法を作る | 魔法は `NewGO` で引数なしに作るので、値を渡せない。魔法が `MagicConfig::GetIce()` を呼ぶ |
| 連射間隔は、魔法のコンストラクターの値 | スキルの `Register<T>(button, cooldown)` に渡す |
| 黒騎士の斬撃は対象外（なかった） | `slash` の段を足した |

`magic-shared` は main から 226コミット遅れていた。魔法と弾を1つにまとめた変更（2026-11-14）、スキルの仕組み（`SkillBase`・`SkillController`）、黒騎士の AI など、土台が大きく変わっていたので、マージはせず、今の main の形で作り直すと2026-11-17 に決めた。古い設計は、`git show magic-shared:"Action/docs/ゲーム/魔法/魔法の調整値の設計.md"` で読める。残っていた `magic-shared` の行は [やりたいこと](../../../やりたいこと.md) の「作業中」から消した。

### 何をしたか

| 以前 | 今 |
|---|---|
| 氷魔法の連射間隔は `IceMagic::COOLDOWN`（`static constexpr`） | `magic.json` の `ice.cooldown`。`Player.cpp` が `Register<IceMagic>(ActionButton::Action1, MagicConfig::GetIce().cooldown)` で渡す |
| 氷魔法の速さ・射程・半径は `IceMagic.cpp` の `MakeSettings` | `ice.speed`・`range`・`radius`。`IceMagic` が `MagicBase(MagicConfig::GetIce().settings)` で渡す |
| 凍らせる秒数は `IceMagic.cpp` の `FREEZE_SECONDS` | `ice.freezeSeconds` |
| 炎魔法の連射間隔は `FireMagic::COOLDOWN` | `fire.cooldown` |
| 炎魔法の溜め時間・速さ・射程・半径・燃える床の半径と秒数は `FireMagic.cpp` の定数 | `fire.maxChargeSeconds`・`speed`・`range`・`minRadius`・`maxRadius`・`minGroundRadius`・`maxGroundRadius`・`groundBurnSeconds` |
| 黒騎士の斬撃の速さ・射程・半径は `SlashMagic.cpp` の `MakeSettings` | `slash.speed`・`range`・`radius` |
| `SkillController::Register<T>(button)` だけ（間隔は `T::COOLDOWN`） | 引数2つの `Register<T>(button, cooldown)` を足した。引数1つの版は残した（剣の攻撃は今までどおり） |

値は、変える前の定数と同じにした。キーがないときの既定値も同じなので、動きは変わらない。

### 決めたこと

- **Player と敵で同じ値にした。** 魔法を `NewGO` で引数なしに作るので、作るときに値を渡せない。`magic-shared` の設計では、敵だけ値をコピーして書き換えて渡せたが、今の形ではできない。氷・炎を撃つ敵はまだいないので、必要になったときに考える。
- **JSON を知っているのは `MagicConfig.cpp` だけ。** 魔法は構造体を受け取るだけにした（`magic-shared` と同じ決め）。
- **読み方は `PlayerConfig.cpp` と同じ。** 最初の1回だけ読む、キーがない・数でないときは既定値を使い、出力ウィンドウに出す。
- **見た目と作りの値は `magic.json` に出さない。** エフェクトの拡大率、脈打ち、床を探すレイの長さは、コードに残した。
- **`BurningGround.cpp` の値（燃える秒数 1.5、燃え広がる秒数 0.4 など）は移していない。** 床の作りに近い値なので、`magic-shared` のときと同じく、今回も移していない。

### 手順書をどう確かめたか

[魔法の調整値の手順](魔法の調整値の手順.md) のコードは、実装したコミット（`67a143f6`）の差分を、小手順ごとの追加・書き換え・削除に分けて書いた。確かめたのは次のとおり。

- 小手順の追加・書き換え・削除を、上から順に全部当てると、`magic.json`・`MagicConfig.h`・`MagicConfig.cpp`・`SkillController.h`・`IceMagic.*`・`FireMagic.*`・`SlashMagic.cpp`・`Player.cpp` の全部が、`67a143f6` のファイルと1文字も違わなくなる（行番号と一緒に、スクリプトで確かめた）。
- 手順ごとのビルドも確かめた（2026-11-17）。実装の前の状態（`17b53c20`、#187 の main）から別の作業用フォルダ（git worktree）を作り、手順書の追加・書き換え・削除を、手順1から順にスクリプトで当てた（書き換え・削除は、「前」の枠が今のファイルと一致することも見た）。新しいファイルは `Game.vcxproj` と `Game.vcxproj.filters` に登録した（手順書には書かない、Visual Studio がやること）。
  - Debug / x64 で MSBuild を回し、手順3・4・5・6・7・8 の終わりで、エラーも `Source` の警告も出ずにビルドが通った。手順1（`magic.json`）・手順2（`MagicConfig.h` だけでまだどこからも読まれない）はビルドの対象にならないので、手順3 のビルドで一緒に確かめた。
  - 手順8 まで当てたあと、`magic.json`・`MagicConfig.*`・`SkillController.h`・`IceMagic.*`・`FireMagic.*`・`SlashMagic.cpp`・`Player.cpp` は、`67a143f6` と差がなかった。
  - 手順書は直していない（行番号のずれ・ビルドが通らない所はなかった）。
  - 動かして確かめること（`magic.json` の数値を変えて起動し直す）は、していない。
